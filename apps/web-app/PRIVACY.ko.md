# XIV Dye Tools — 개인정보 안내 (웹 앱)

> 이 문서는 편의를 위해 제공되는 번역본입니다. 영어 버전이 원본이며, 두 버전이 다를 경우 영어 버전이 우선합니다. [English](PRIVACY.md)

**최종 업데이트:** 2026-09-16 · **xivdyetools.app**과 **beta.xivdyetools.app**에 적용됩니다. Discord 봇은 별도의 정책을 따릅니다: [`apps/discord-worker/PRIVACY_POLICY.md`](../discord-worker/PRIVACY_POLICY.md).

XIV Dye Tools는 브라우저에서 실행됩니다. 색상 도구 — 팔레트 추출, 색상 조화 탐색기, 염료 비교, 그라데이션, 믹서, 접근성 검사기, 예산 제안, 캐릭터 매처 — 는 모두 사용자의 기기에서 작동합니다. 아래 항목에서 별도로 명시하지 않는 한 업로드하거나 선택하거나 입력한 어떤 것도 어디로도 전송되지 않으며, 아래 항목이 그 전체 목록입니다.

## 이미지 및 카메라 촬영

- 업로드, 붙여넣기, 드래그 앤 드롭 또는 카메라로 촬영한 이미지는 사용자의 기기를 벗어나지 않으며, 브라우저 저장소에 기록되지도 않습니다. 이미지는 브라우저의 Canvas API로 읽어들여 해당 세션 동안만 페이지 메모리에 보관되며, 이미지를 지우거나 탭을 닫거나 새로고침하면 삭제됩니다.
- 팔레트 추출 도구도 파일을 선택하는 위치에 자물쇠 아이콘과 함께 같은 안내를 표시합니다 — "이미지는 브라우저 안에서만 읽히며 업로드되지 않습니다.". 이 안내는 링크가 아닌 일반 텍스트이며, 이 문서는 **XIV 염색 도구 정보 → 개인정보처리방침**에서 접근할 수 있습니다.

## 캐릭터 파일 (`.chara`)

- `.chara` 파일(Anamnesis, Ktisis, Brio)은 사용자의 기기에서 해석됩니다. 그 안에 담긴 캐릭터 이름은 어디로도 전송되지 않으며, 프리셋 이름이나 작성자 이름 등 다른 사람이 볼 수 있는 곳에는 절대 사용되지 않습니다. 커뮤니티 프리셋에 글래머를 제출하려면 이름을 직접 입력해야 합니다 — 이 입력란은 일부러 빈 상태로 시작하는데, 캐릭터 이름과 파일 이름 모두 플레이어가 실명을 적어 넣는 위치이기 때문입니다.
- **한 가지 예외가 있으며, 이 예외는 사용자의 기기 안에만 머무릅니다.** 이름을 입력하지 않고 글래머나 그 팔레트를 이 브라우저에 저장하면, 저장된 기록은 캐릭터의 닉네임을, 그것도 없으면 `.chara` 파일 이름을 대신 사용합니다. 이 이름은 사용자의 다른 저장된 컬렉션과 함께 브라우저 저장소에 보관됩니다. 이는 절대 업로드되지 않으며, 위에서 설명한 커뮤니티 경로에서도 읽히지 않습니다. 기록의 이름을 바꾸거나 삭제하거나 사이트 데이터를 지우면 사라집니다.
- 글래머 블록의 장비 이름을 표시하기 위해, 앱은 각 슬롯 뒤에 있는 아이템을 저희 API에 문의합니다. 이 요청에는 파일에서 가져온 장비 **모델 번호**만 포함되며(파일당 십여 개의 작은 정수) 파일 자체나 이름, 색상은 포함되지 않으며, 아이템 아이콘은 같은 호스트(`data.xivdyetools.app`)에서 전달됩니다.

## 사용자의 기기에 저장되는 정보

`localStorage`에는 가벼운 설정과 사용자가 직접 저장한 작업물이 담깁니다: 테마, 언어, 도구별 설정(아래의 분석 스위치 포함), 즐겨찾는 염료, 저장된 팔레트와 컬렉션, 그리고 로그인한 경우 커뮤니티 프리셋 세션 토큰입니다. 이 중 어떤 것도 추적 식별자가 아닙니다. **고급 설정**의 "설정 초기화"와 브라우저의 사이트 데이터 관리 기능으로 이를 지울 수 있습니다.

`IndexedDB`에는 한 가지만 저장됩니다: 이미 조회한 장터 가격의 캐시로, 같은 조회를 반복하지 않기 위한 것입니다. 이미지는 전혀 저장하지 않습니다 — 이전 버전의 앱은 마지막으로 추출한 이미지를 여기에 보관했지만, 이번 업데이트 이후 앱을 처음 열 때 그 사본은 삭제됩니다. 브라우저의 사이트 데이터 관리 기능으로 이를 지울 수 있습니다.

## 네트워크 접근

앱은 다음의 자체 호스트에만 통신하며(사이트의 Content-Security-Policy는 그 외에는 아무것도 허용하지 않습니다), 아래에 명시된 제3자 서비스도 함께 이용합니다:

1. **장터 가격** (선택 사항 — "가격 표시" 스위치): 아이템 id와 사용자가 선택한 서버 또는 데이터 센터 정보가 저희 프록시인 `data.xivdyetools.app`로 전송되며, 이곳에서 [Universalis](https://universalis.app)로부터 데이터를 가져옵니다.
2. **`.chara` 가져오기용 장비 이름과 아이콘** — `data.xivdyetools.app` (위 참고).
3. **커뮤니티 프리셋** (`api.xivdyetools.app`): 둘러보기만으로는 사용자에 대한 어떤 정보도 전송되지 않습니다. Discord 또는 XIVAuth로 `auth.xivdyetools.app`를 통해 로그인하면 프리셋을 제출하거나 투표하지 않더라도 즉시 계정 기록 — 제공자 id와 사용자 이름 — 이 생성됩니다. 사용자가 제출한 프리셋과 투표는 해당 계정 아래에 저장되며, 게시된 프리셋에는 작성자 이름이 표시됩니다. 프리셋을 제출하거나 수정할 때 그 이름과 설명이 조정 점수를 위해 Google의 [Perspective API](https://perspectiveapi.com/)로 전송될 수 있습니다(선택 사항 — 콘텐츠 조정 용도로만 사용); 이 요청은 Google에 해당 데이터를 저장하지 말라고 지시하며(`doNotStore`), 계정 신원을 포함한 그 외의 어떤 것도 전송되지 않습니다. 계정 기록과 제출물의 삭제를 원하시면 아래의 문의하기 섹션을 참고하세요. 프리셋 미리보기 이미지는 `shots.xivdyetools.app`에서 제공되며, 아바타는 Discord의 CDN에서 불러옵니다.
4. **공유 링크**: 공유 링크는 사용자가 선택한 염료나 색상을 URL 안에 인코딩합니다. 링크를 열면 다른 페이지와 마찬가지로 그 URL이 로드되며, Discord 등에서 표시되는 링크 미리보기는 URL만 확인하는 저희 자체 `og-worker`가 생성합니다.
5. **사용 분석** (옵트인 — 다음 섹션 참고): `data.xivdyetools.app`.

글꼴은 자체 호스팅됩니다. 제3자 분석 스크립트, 광고 또는 소셜 트래커는 전혀 없으며, 쿠키도 사용하지 않습니다.

### 다른 사이트로 이동하는 링크

위 목록과는 별개로, 일부 버튼은 백그라운드에서 무언가를 가져오는 대신 사용자를 커뮤니티 데이터베이스로 **이동**시킵니다. 캐릭터 매처에서 글래머 부위의 "다음에서 열기…" 메뉴는 [Mirapri](https://mirapri.com/), [Garland Tools](https://www.garlandtools.org/), [Teamcraft](https://ffxivteamcraft.com/), [Gamer Escape](https://ffxiv.gamerescape.com/) 또는 Lodestone을 엽니다. 염료 결과 카드는 Universalis, Garland Tools, Teamcraft 또는 [Saddlebag Exchange](https://saddlebagexchange.com/)를 열 수 있습니다.

이러한 링크에 담기는 것은 게임 자체의 아이템 정보 — 그 숫자 아이템 id이거나, 해당 사이트가 사용하는 언어로 된 아이템 이름입니다. 사용자에 대한 정보, 팔레트, 캐릭터, 세션에 관한 어떤 것도 URL에 포함되지 않습니다. 이 링크들은 리퍼러가 차단된 새 탭에서 열리므로, 도착한 사이트는 사용자가 어느 페이지에서 왔는지 알 수 없습니다. 일단 그곳에 도착하면 사용자는 다른 누군가의 사이트에, 그들의 개인정보처리방침 아래에 있게 됩니다.

## 사용 분석 (옵트인)

분석은 **기본적으로 꺼져 있습니다**. **고급 설정 → 분석 활성화**가 켜져 있을 때만 작동하며, 스위치가 켜져 있어도 브라우저가 [Global Privacy Control](https://globalprivacycontrol.org/) 신호를 보내면 절대 작동하지 않습니다. 서버 역시 이를 강제합니다: 앱 자체 출처에서 온 원격 측정만 수신하며, 브라우저의 `Sec-GPC` 신호가 포함된 배치는 기록하기 전에 폐기합니다. 스위치를 끄면 열려 있는 모든 탭에서 즉시 전송이 중단되고, 아직 전송되지 않은 데이터는 폐기됩니다.

활성화하면 앱은 이러한 이벤트를 작은 배치 단위로 저희 API(`data.xivdyetools.app`)에 전송하며, 이는 Cloudflare Analytics Engine에 저장됩니다:

- **도구 조회** — 어떤 도구가 열렸는지, 그것이 페이지가 처음 로드된 도구인지, 공유 링크를 통한 것인지, 아니면 사용자가 의도적으로 전환한 것인지, 그리고 그 탭이 몇 초간 화면에 표시되었는지.
- **염료 선택** — 팔레트 서랍이나 염료 그리드에서 사용자가 명시적으로 선택한 염료의 숫자 id와, 어느 도구에 있었는지. 무작위 염료 버튼이나 도구가 받아들이지 않은 선택은 집계되지 않으며, 팔레트 전체가 전송되는 일은 없습니다.
- **캐릭터 파일 가져오기** — `.chara` 파일이 해석되었는지 여부와, 어떤 프로그램 계열에서 만들어졌는지(Anamnesis, Ktisis, Brio, 기타). 파일이나 캐릭터 자체는 절대 전송되지 않습니다.
- **테마 전환** — 사용자가 의도적으로 전환한 테마.

각 배치에는 다음의 다섯 가지 대략적인 차원도 함께 담깁니다: 앱 버전, 환경(production 또는 beta), UI 언어, 현재 테마, 뷰포트 구간(phone / tablet / desktop).

**사용자의 이벤트와 함께 절대 저장되지 않는 것**: IP 주소, 사용자 에이전트나 기기 정보, 계정·세션·클라이언트 식별자, 쿠키, 페이지 URL, 작업 중인 색상이나 이미지, 검색어, 프리셋 텍스트, 캐릭터 이름이나 서버 이름, 또는 두 번의 방문을 서로 연결할 수 있게 하는 그 어떤 것도 포함됩니다. 서버는 검증된 이벤트를 제외한 요청에 관한 모든 정보를 폐기하며, 이벤트 목록은 허용 목록 방식이라 그 외의 것은 모두 버려집니다. (사용자의 IP는 방문하는 모든 웹사이트에 도달하는 것과 같은 방식으로 저희 서버에도 도달합니다. 그 이후 무엇을 하는지는 다음 섹션에서 다룹니다.)

Analytics Engine은 데이터를 약 석 달간 보관합니다. 코드는 오픈 소스로 공개되어 있습니다: [`apps/web-app/src/services/telemetry-service.ts`](src/services/telemetry-service.ts) (브라우저가 보내는 내용)와 [`apps/api-worker/src/telemetry/schema.ts`](../api-worker/src/telemetry/schema.ts) (서버가 받아들이는 내용).

## 사용자의 IP 주소와 서버 로그

사용자가 방문하는 모든 웹사이트는 사용자의 IP 주소를 받습니다 — 응답이 사용자를 찾아가는 방식이 그렇기 때문입니다. 저희 쪽에서는 이를 Cloudflare가 처리하며, 저희가 이를 가지고 하는 일의 전부는 다음과 같습니다.

- **남용 방지.** 저희 API는 하나의 출처가 서비스를 넘치게 하지 못하도록 IP당 요청 수를 **60초** 단위로 집계합니다. 이 집계는 Cloudflare 자체의 속도 제한 서비스가 수행하며, 저희는 주소를 그쪽에 넘길 뿐 직접 저장하지 않습니다. 그 서비스가 연결되지 않은 배포 환경에서만 사용되는 대체 경로도 있는데, 이 경우 주소가 포함된 키 아래 Cloudflare KV에 카운터를 두며 유효 기간은 **120초**입니다. 두 경로 모두 사용자의 주소를 데이터베이스에 기록하지 않으며, 어느 쪽도 분석 이벤트와 연결되지 않습니다.
- **사용자의 IP는 사용자가 한 어떤 행동과도 함께 저장되지 않습니다** — 이벤트도, 프리셋도, 투표도 마찬가지입니다. 방문 기록을 연결하거나 프로필을 구축하거나 사용자를 식별하는 데 사용되지 않습니다.
- **운영 로그.** 저희 워커는 요청을 처리하는 동안 짧은 진단 로그를 출력할 수 있습니다. 지속적인 로그 수집(Cloudflare Workers Logs)은 모든 워커에서 **꺼져** 있으므로, 이 로그는 디버깅 중 실시간 스트림을 지켜보는 관리자에게만 보이며 이후에는 남지 않습니다. 만약 저희가 지속적인 로그 수집을 켠다면, 그 사실을 이곳에 먼저 밝히겠습니다. Discord 봇의 로그는 [별도의 정책](../discord-worker/PRIVACY_POLICY.md)에서 다룹니다.

## 확인하는 방법

1. 개발자 도구(DevTools) → Network(네트워크) 탭을 열고 "로그 유지(Preserve log)"를 켭니다.
2. 이미지나 `.chara` 파일을 사용하는 아무 도구나 사용해 보세요.
3. 이미지 업로드는 전혀 보이지 않고, 위에 나열된 요청들만 보일 것이며, 분석을 켠 경우에만 `/v1/telemetry` 비콘이 나타납니다.
