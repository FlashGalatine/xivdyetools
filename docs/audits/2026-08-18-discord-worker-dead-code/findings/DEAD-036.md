# [DEAD-036]: core locale files — `metallicDyeIds`, `jobNames`, `grandCompanyNames` sections ×6 languages feed accessors nobody calls

## Category
i18n (test-only payload) / Unused Export

## Location
- `packages/core/src/data/locales/{en,ja,de,fr,ko,zh}.json` — sections `metallicDyeIds` (16 legacy itemIDs — superseded by `METALLIC_STAIN_IDS`, which `DyeDatabase` now uses), `jobNames` (22 keys), `grandCompanyNames` (3 keys)
- `packages/core/src/services/LocalizationService.ts` — `getMetallicDyeIds`, `getJobName`, `getGrandCompanyName` (0 external consumers: 0 src, 0 test outside core)
- `packages/core/scripts/build-locales.ts` — `buildJobNames`, `buildGrandCompanyNames`, `identifyMetallicDyes` builders
- `packages/types` — `JobKey`, `GrandCompanyKey`
- ≈150 lines across core + types + 6 JSON, ≈60 test lines

Kept: `visionTypes` + `visions` (both read: `getVisionType`/`getVisionShort`); `categories.Facewear` / `acquisitions.Facewear Collection` (DyeSearch still filters `category === 'Facewear'` defensively — keep for now).

## Evidence
`git grep -nw getMetallicDyeIds|getJobName|getGrandCompanyName` outside `packages/core` → 0. Locale-section → accessor → external-consumer chain in `evidence/track-B-core.md` §0.8, §5.

## Why It Exists
Locale sections built for features (job/GC display, metallic detection by itemID) that either never shipped or were superseded by stainID-first data.

## Removal Risk Assessment
| Factor | Assessment |
|--------|------------|
| **Confidence** | HIGH |
| **Blast Radius** | LOW — the JSONs are generated by `build-locales.ts`, so removing the builders regenerates without the sections; `JobKey`/`GrandCompanyKey` are type-only |
| **Reversibility** | EASY |
| **Hidden Consumers** | Locale JSON is bundled into every core consumer — this is a small bundle win too |

## Recommendation
**REMOVE WITH CAUTION** (documented in CLAUDE.md as accessors) — remove builders + accessors + types, regenerate the six locale files, CHANGELOG note.
