## Positive controls — already right, do not re-file

- **The new colour-wheel vocabulary is correct end to end**: 5 wheels × 6 locales in core (distinct, non-English, house-style parentheses; fr correctly localizes RYB → `RJB`); web-app, bot, og-worker and api-worker all read it through core's getter and none re-types it; og-worker's font gate picked the new strings up automatically and its subsets were re-cut for them.
- **`/manual` 5.0 rewrite**: harmony, wheel and category names equal core's value in every non-en locale (checked programmatically); placeholder parity perfect across all 513 keys × 6; ja/zh prose uses full-width punctuation; longest de/fr bodies well inside Discord's 1024/4096/6000 limits.
- **Locale threading in the bot**: buttons and autocomplete re-resolve the acting user's locale on every interaction (KV preference → Discord locale → en); localized dye-name *input* is threaded from every handler via `t.getLocale()`.
- **web-app formatting**: `shared/format.ts` number / date / list / gil formatters all default to the app locale, never `en-US`; `<html lang>` and `document.title` follow locale and route changes; Extractor share-link stripping preserves `?lang=`.
- **`dyenames.csv`**: 0 empty cells, 0 non-en cells identical to en, 0 within-locale duplicate names across 125 × 5; trailing spaces never reach output (`csv-parse trim`).
- **api-worker**: the four new endpoints take `?locale=` through the same middleware as `/v1/dyes*` — same `INVALID_LOCALE` 400, same `SUPPORTED_LOCALES` import, same omit-when-en `meta.locale`; VitePress docs match the code everywhere checked. `.chara` ko/zh fallback is documented precisely.
- **presets-api**: every error a client shows carries an `ErrorCode` (content_revision 409s, dye-signature conflicts, preview-image errors); oauth and image-worker still emit no user-visible text.
- **2026-09-03 fixes all hold**: static CJK instances, no `★` drawn (test-pinned), `Perlmutt-` gone, bot harmony/vision names from core, `/budget` quick picks localized, Facewear names wired to the render site, `?lang=` on og share URLs with no new bypass site.
- **Glamour list export's English slot labels are deliberate** — a fixed GPOSERS submission format, documented in `shared/glamour-markdown.ts`'s header; item and dye names inside it *are* localized.

## Rejected suspicions — checked and dropped

- **"Two gates are red" (`webapp-i18n-tests`, `discord-i18n` exit 1).** Every test passed (90/90, 85/85); both `vitest.config.ts` files set `coverage.enabled: true`, so a *subset* run trips the global thresholds. Runner artefact — next time pass `--coverage.enabled=false` to subset runs.
- **`★` and 8 emoji reported as tofu by `svg-literal-glyphs.py`.** The `★` hits are comments in `emitted-glyphs.ts` and a JSDoc diagram; `preset-swatch.test.ts:135-148` pins that no star is drawn. The emoji are Discord message text, never drawn by resvg (rejected 2026-09-03 too). The script scans raw text including comments.
- **14 / 9 "missing" codepoints in the KR subsets (`font-coverage.py --scripts hangul`).** All CJK punctuation (`、。「」（）：…`) carried by the SC face, which every stack lists. Union tofu is 0. Same verdict as 2026-09-03 — the per-font script is stricter than the runtime.
- **discord-worker fonts are older than the last bot-logic string change** (2026-09-18 vs 2026-09-19). Coverage is complete; the change added no glyph.
- **presets-api vote failures return an English sentence in `error`** (`votes.ts:99,153`). Never user-visible: web-app maps `errorCode` → key with a localized fallback (`preset-detail.ts:48-65`), the bot replies `preset.voteFailed` (`preset.ts:678`). A contract wart, not an i18n defect.
- **`/v1/wheels` and `/v1/harmony/types` overwrite `name` with the localized string** rather than the dyes' `name` + `localizedName` pair — documented and intentional (`docs/…/harmony.md`); `id` is the stable handle.
- **presets-api `/categories` returns an English `name`.** Clients key off `id`; web-app localizes via `shared/preset-i18n.ts:66-71`.
- **og-worker's crawler description never names the colour wheel.** True, and identical in English — a product-copy gap, not a localization one.
- **de `about.poweredBy` = "Powered by Cloudflare Workers"** while ja/fr/ko/zh translate it. "Powered by" is an accepted anglicism in German tech copy; not wrong. It is, however, exactly what an identical-value allow-list with reasons would record (recommendation 3).
- **zh `manual5.topics.spectrumPrices.name`** translates the concept where other locales transliterate "Spectrum" — a translator's choice, pre-existing, not an error.
- **`/harmony wheel` choice names English in the picker** — deliberate per in-code comment (identifier-style tags, like the matching-method tags); the card's wheel name is localized separately.
- **Moderator-facing paths pin `createTranslator('en')`** (`preview-image.ts`, `preset-notifications.ts`, `preset.ts:1078`) — explicit comments; consistent with the 2026-09-03 English-only moderation decision.
- **`?locale=JA` / `?locale=zh-CN` → 400 on api-worker** — one middleware, consistent across old and new routes, documented.
- **zh web-app mixes `——` (25×) and ` — ` (8×).** Pre-existing split, cosmetic; not filed.
- **The coordinator's own belief that ko Market Board is `장터 게시판`** — the researcher reported it refuted (`장터`), and `장터` is what shipped. *Corrected 2026-09-20 from the maintainer's raw page captures:* `장터 게시판` is the client's own map label for the board object, `장터` the feature the official guide is titled after — both official, and the apps mean the feature. The lesson cuts both ways: a fluent guess needs a source, and a summarized fetch needs the raw page.

## Recommendations — guardrails

1. **Add Market Board, World and Data Center rows to `docs/reference/ffxiv-terminology.md`** with the sources in `evidence/official-terms-research.md`; `term-check.py` then guards them. The dictionary's silence is why three forms per locale accumulated.
2. **Same-English-value consistency check in `validate:i18n`** (`tool-name-consistency.py --all` with an allow-list for context-dependent pairs such as `Dark`/`Light`): would have caught TERM-001, TERM-002 and TERM-004 at PR time.
3. **Give bot-logic an identical-to-en allow-list with reasons**, as web-app has — carried from 2026-09-03 recommendation 5, still not done; 27–38 values per locale are currently unreviewed by any gate.
4. **`localize.test.ts` should assert coverage, not the current count**: every description and every choice either localized in all five mapped locales or listed in a deliberate-English set (closes I18N-001/002 permanently).
5. **`translator.test.ts`: plural cases per locale** (fr 0/1/2, de 0/1) — the suite tests English only, which is how I18N-003 passed.
6. **Make `build-locales.ts` fail on an empty cell** (I18N-007) — ko/zh names are hand-pasted for every new dye.
7. **Subset gate runs need `--coverage.enabled=false`** in `run-gates.sh` so a green suite does not read as red.
8. **og-worker: one render test with the longest de/fr wheel name in the harmony deck row** — the `fit()` guard exists but no test exercises the long combination.

### What remediation found that the audit had not

- **A second `안팡`** in `accessibility.unitDeDesc` — the audit filed one occurrence (I18N-004).
- **Discord's 8,000-character cap counts a field once, at its longest localization.** The planning
  verifier said localizations add up; the first implementation summed them, put `/preferences` at
  9,909 and reported a blocker. Discord's own docs settle it; counted that way the largest command
  is 2,736 (34 %). Nothing was cut. *Check the primary source before trading away translations.*
- **The orphan gate did not know the new key family** — 137 picker keys looked unreferenced until
  `locale-orphans.test.ts` enumerated them per registered command.
- **German `resultCard.sentToSwatch` named the wrong tool**; two more French `RVB`; ja `Web アプリ`
  / fr `Application Web` / fr `(facultative)` inconsistencies; zh `{n} 个` vs `{n} 个配色`.
- **The policy translations passed the mechanical gate and were still wrong in four places that
  change a commitment** (ja 当社 ×45 — "this company" for one individual; zh presets "published
  after you leave"; fr consumer-rights clause; ja 利用 for "exploit"), plus 8 stale or mismatched UI
  labels and 8 German comprehension defects — 32 corrections from two `opus` reviewers
  (`evidence/scripts/apply-policy-corrections.py`, idempotent). Parity is necessary, not sufficient.
- **The parity gate itself pushed a translator into unnatural Korean** (`제삼자` for `제3자`) to satisfy
  its digit count; it now has a lexical-digit allow-list, and the spelling was restored.
- The dead-code reachability gate rightly refused the hand-run key generator until it carried an
  `@entrypoint` reason; the link gate covers the policy documents and caught their links while
  the translations were still untracked.
