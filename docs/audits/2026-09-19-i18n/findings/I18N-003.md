# I18N-003: `Translator.tc()` applies the English plural rule to every locale — French renders "0 votes" on every unvoted preset card
**Tier:** P2 · **Locale(s):** fr · **Deploy unit:** bot-logic (published) → discord-worker · **Semver:** MINOR (observable output change in a published package — house rule)

## Location
- `packages/bot-logic/src/i18n/translator.ts:104` — `` `${key}_${count === 1 ? 'one' : 'other'}` `` for all six locales.
- `apps/discord-worker/src/handlers/commands/preset.ts:1007-1010` — `t.tc('preset.cardVotes', preset.vote_count)`; only `undefined` skips it, so `0` is a live input (every new preset).
- Other `.tc()` sites that can receive 0: `dye.ts:139` (`dye.search.foundCount`), `bot-logic/src/commands/gradient.ts:324,328`, `swatch.ts:382`.

## Evidence
- CLDR: French `one` = `i = 0,1` (0 and 1 are singular); en/de `one` = `i = 1`; ja/ko/zh have `other` only. fr values: `preset.cardVotes_one` = `{count} vote`, `_other` = `{count} votes` → the card draws "0 votes"; correct French is "0 vote".
- `translator.test.ts` asserts English behaviour only.

## Fix
- Select the category with `new Intl.PluralRules(locale).select(count)` (available in Workers and Node; returns `one`/`other` for all six shipped locales), falling back to `other` when the suffixed key is missing. Add fr `0`/`1`/`2` and de `0` cases to `translator.test.ts` — the repo has no prior `Intl.PluralRules` use, so these tests are also what makes a stripped-ICU runtime fail loudly instead of silently returning `other`.
