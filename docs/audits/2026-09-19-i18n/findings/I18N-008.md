# I18N-008: two web-app sorts bypass the locale-aware comparator
**Tier:** P3 · **Locale(s):** ja de fr ko zh · **Deploy unit:** web-app · **Generated?** no

## Location
- `apps/web-app/src/components/budget-tool.ts:658` — `this.dyeName(a.dye).localeCompare(this.dyeName(b.dye))`: localized names, but collated by the *browser's* default locale, not the app's.
- `apps/web-app/src/components/dye-selector.ts:441` — `a.category.localeCompare(b.category)` (the "sort by category" option): orders dyes by the English category id, so under a localized UI the category sequence follows English alphabetical order (Blues, Browns, Greens…) rather than the displayed labels'.

## Evidence
- `apps/web-app/src/shared/dye-name.ts:26` already has the right comparator — `localeCompare(…, LanguageService.getCurrentLocale())` — with a test pinning that the locale is passed. These two sites predate or missed it. Visible when app locale ≠ browser locale (e.g. German UI in an English browser: `ä`/`ö` placement).

## Fix
- `budget-tool.ts`: use `compareDyeNames`. `dye-selector.ts`: compare the localized category labels with the current locale (or keep a deliberate fixed game order and say so in a comment).
