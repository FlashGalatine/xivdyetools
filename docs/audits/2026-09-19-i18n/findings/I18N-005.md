# I18N-005: localized dye-name search folds ASCII case only — `schneeweiss`, `creme`, half-width kana find nothing
**Tier:** P1 (raised by the planning verifier: search returns *nothing* for ~1/3 of dyes typed in the user's own locale — a broken feature, not wrong-but-readable text) · **Locale(s):** de fr ja · **Deploy unit:** core (published) → api-worker; bot-logic (published) → discord-worker · **Semver:** MINOR for both — `foldForSearch` is a new public core export and search results change observably (house rule: observable package change = MINOR)

## Location
- `packages/core/src/services/DyeService.ts:344,355` — `searchByLocalizedName`: `query.toLowerCase()` vs `localizedName.toLowerCase().includes(…)`. Only caller: `apps/api-worker/src/routes/dyes.ts:69` (`GET /v1/dyes?q=…&locale=`).
- `packages/bot-logic/src/input-resolution.ts:60-65` — `searchDyesByName`, same fold; feeds every Discord dye option and autocomplete via `resolveColorInput`.

## Evidence
- 31 of 125 de names and 34 of 125 fr names contain a non-ASCII letter (`Schneeweißer`, `Rußschwarzer`, `jaune crème`, `brun châtaigne`). `'schneeweiss'.includes` never matches `'schneeweißer'`; `creme` never matches `crème`. No `normalize(` call exists anywhere in core, bot-logic, discord-worker or web-app `src/`.
- A German player without ß on their layout, or anyone on a phone keyboard, cannot find a third of the dyes by their localized name. ja: half-width kana and full-width Latin are the same class (NFKC).

## Fix
- One shared `foldForSearch(s)` in core, applied to both sides in both sites (bot-logic imports it): `NFKC` first (folds half-width kana / full-width Latin), lower-case, `ß → ss`, then strip combining marks **from Latin letters only** — a blanket NFD + `\p{M}` strip would also erase Japanese dakuten (が → か) and over-match. `GET /v1/dyes?q=` now matches more rows — note it in the VitePress `q=` docs. Tests: `schneeweiss`, `russschwarz`, `creme`, half-width `ｽﾉｳ`, and a negative ja case (`か` must not match `が`).

## Status
FIXED 2026-09-20 `f7c6e1fc` + `b76623dd` (docs `7ae472e7`) — `foldForSearch()` in core, used by `DyeService` and bot-logic; Latin-only mark strip, `が`≠`か` tested
