# I18N-001: discord-worker `localize.ts` never localizes subcommand/option descriptions — 134 of 151 picker tooltips are English in every locale
**Tier:** P1 (raised by the planning verifier: 134 untranslated strings on every command's picker is "untranslated strings shipping in UI", and an already-skipped carry-forward) · **Locale(s):** ja de fr ko zh · **Deploy unit:** discord-worker (+ bot-logic locale keys) · **Generated?** no
Supersedes `2026-08-20-discord-worker-i18n/F-03` (its phase 2, "option descriptions", was never executed; phases 1 and 3 shipped).

## Location
- `apps/discord-worker/src/commands/localize.ts:183-195` — `localizeOption()` attaches `name_localizations` to choices only; it never sets `description_localizations` on an option or subcommand.
- `apps/discord-worker/src/commands/localize.ts:201-208` — `localizeCommands()` localizes the 17 top-level descriptions and nothing below them.
- `apps/discord-worker/src/commands/schemas.ts` — 151 `description:` fields; 17 are top-level.

## Evidence
- The module header (`localize.ts:10-15`) states the scope: top-level descriptions + selected choice lists.
- `localize.test.ts` asserts `descriptions === commands.length` (17) — the gate pins the gap rather than closing it.
- A user with Discord set to Japanese sees a Japanese `/harmony` description, then English tooltips for `type`, `dye`, `wheel`, … (`evidence/review-discord-worker.md` D-01).

## Fix
- Add `commands.<cmd>.options.<path>.description` keys (×6) to bot-logic locales; walk options in `localizeOption()` with the same `keyed()` guard (raw-key miss + 100-char cap). Flip the test to assert every description is localized in every mapped Discord locale.
- **Two constraints found at planning:** (1) `apps/discord-worker/scripts/subset-cjk-fonts.py:132-140` ingests the *whole* bot-logic locale JSON, so 134 × 5 picker strings would add CJK glyphs resvg never draws to a worker already at ~2,632 of 3,072 KiB gzip — exclude `commands.*.options.*` from the scan (and from `font-coverage.test.ts`'s source set) or measure with `check-bundle-size.mjs`. (2) Discord caps a command at 8,000 characters *including* localizations; `/preferences` is ~2k today → ×6 ≈ 6.6k plus choice localizations — assert per-command payload size in `localize.test.ts`, since `register-commands.ts` has no dry-run.
- Needs a `register-commands` run (CI does it on merge). Descriptions only — localized option **names** are a separate, riskier decision (lowercase/no-space constraints) and are not proposed.
