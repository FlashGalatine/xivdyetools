# BUG-004: Preset detail view fetches Universalis prices into `priceData` on every preset and never reads it — 'Show prices' is a silent no-op there
**Severity:** MEDIUM · **Type:** Logic · **Deploy unit:** web-app · **Covered by test?** no

## Location
- `apps/web-app/src/components/v4/preset-detail.ts:127-141,594-641,678-710` — `marketConfig`, `priceData`, the `prices-updated` subscription and `fetchPricesIfNeeded()` all write `this.priceData`
- `apps/web-app/src/components/v4/preset-detail.ts:958` — the dye row emits `.dye-price` from the static vendor `formatGil(dye.cost)`; no line after 703 reads `priceData`

## Evidence
- Reproduction: enable Show prices, open any preset → rows show vendor cost only, while the network tab shows the Universalis fan-out for the preset's dyes
- Reviewer row `webapp-v4-19` (graded HIGH); Opus pass corrected to MEDIUM because the row is not wrong, only the toggle is inert

## Fix
- Render `priceData.get(getMarketItemID(dye))` in the dye row when `marketConfig.showPrices` (the same presentation `market-board.ts` uses), or drop the fetch and the subscription if the view is meant to stay vendor-only
- Add a test that seeds `priceData` and asserts the rendered gil differs from `dye.cost`
