# BUG-018: og-worker keys `wheel` into the cache for `/og/harmony/default.png`, a route that never reads it
**Severity:** LOW · **Type:** Edge case · **Deploy unit:** og-worker · **Covered by test?** no

## Location
- `apps/og-worker/src/index.ts:357` — `c.req.path.startsWith('/og/harmony/')` also matches the default card, so up to five validated wheel ids each force a fresh resvg render of a byte-identical PNG

## Evidence
- Reviewer row `og-worker-01`; bounded to 5 extra rasters of one card — hence LOW

## Fix
- Exclude the `default` path (or key on the route that actually reads `wheel`); extend `og-guards.test.ts` with the default card

## Status
FIXED (Sprint 10, `9963891f`) — `wheel` is keyed only for the parameterised harmony dye card (`readsWheel(path)`), never `/og/harmony/default`; og-guards test proves both directions.
