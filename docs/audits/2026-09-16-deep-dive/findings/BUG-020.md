# BUG-020: logger's browser error-tracker wrapper uses raw `JSON.stringify(error)`, so a circular or BigInt-bearing non-Error value throws inside `logger.error()`
**Severity:** LOW · **Type:** Error handling · **Deploy unit:** logger · **Covered by test?** no

## Location
- `packages/logger/src/presets/browser.ts:120-125` — `JSON.stringify(error)` instead of the package's own `safeStringify` (the BUG-104 fix applied to the adapters, not here)

## Evidence
- `git grep errorTracker apps/*/src` is empty — no app configures a tracker today, so latent
- Reviewer row `pkg-foundation-01`

## Fix
- Use `safeStringify`; add the circular-value case to `browser.test.ts`. Publish `@xivdyetools/logger`, no consumer deploy needed until a tracker is configured
