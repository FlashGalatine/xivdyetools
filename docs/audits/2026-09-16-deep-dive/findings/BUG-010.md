# BUG-010: `DyeDatabase.getAllDyes` is documented as a defensive copy but is shallow, and `LocaleLoader`/`LocaleRegistry` hand out the static locale module objects — a caller mutation would corrupt shared indices
**Severity:** LOW · **Type:** State · **Deploy unit:** core · **Covered by test?** no — the 'defensive copy' test checks array identity only

## Location
- `packages/core/src/services/dye/DyeDatabase.ts:392-395` — `return [...this.dyes]` (elements are the shared `DyeInternal` records also held by `dyesByIdMap`, the hue buckets and the k-d tree)
- `packages/core/src/services/localization/LocaleLoader.ts:49-70`, `LocaleRegistry.ts:64-66` — returns `localeMap[locale]` itself
- `packages/core/src/services/dye/__tests__/DyeDatabase.test.ts:195-201` — `expect(dyes1).not.toBe(dyes2)` only

## Evidence
- `git grep` over `apps/*/src packages/*/src` finds no consumer assigning to a dye or locale field outside `initialize()` — latent today
- Reviewer rows `core-data-01/02/03`

## Fix
- Either freeze the records at `initialize()` (`Object.freeze` per dye; cheap, 125 objects) and say so in the JSDoc, or deep-clone on the way out and accept the cost — freezing is the recommendation; add an element-mutation test
