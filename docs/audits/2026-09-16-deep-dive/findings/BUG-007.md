# BUG-007: `createMockDye()` draws stainIDs from `Math.random()` over 254 values with no uniqueness, so every workspace test run has a ~0.4 % chance of a red that is nobody's fault
**Severity:** MEDIUM · **Type:** Race · **Deploy unit:** test-utils · **Covered by test?** the existing test is the flake

## Location
- `packages/test-utils/src/factories/dye.ts:35-37` — `randomStainId()` returns `floor(random()*254)+1`
- `packages/test-utils/src/factories/dye.ts:181-183` — `stainID`, `itemID` and `id` are all derived from that draw
- `packages/test-utils/tests/factories/dye.test.ts:90-95` — 'generates unique IDs' asserts `dye1.id !== dye2.id`

## Evidence
- This audit's baseline `turbo run test:coverage --force` failed exactly here: `expected 5794 not to be 5794` (`evidence/coverage-baseline.txt:506-535`); the plain `test` run 20 minutes earlier passed
- P(collision per pair) = 1/254 ≈ 0.39 %; any consumer building N mock dyes collides with P ≈ N²/508

## Fix
- Make the default deterministic and unique: a module-level counter over 1..254 (wrap → throw or reset per test via `vi` hooks), keep `randomStainId` only behind an explicit `{ random: true }`
- Workspace-private package: merge only, every consumer re-resolves it from `dist` on the next run
