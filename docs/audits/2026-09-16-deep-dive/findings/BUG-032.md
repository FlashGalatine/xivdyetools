# BUG-032: `ColorAccessibility.test.ts` guards its only assertion behind a branch that never runs for its fixed fixture
**Severity:** LOW · **Type:** Untested behaviour · **Deploy unit:** core · **Covered by test?** the test cannot fail

## Location
- `packages/core/src/services/color/__tests__/ColorAccessibility.test.ts:108-121` — `if (!smallText) { expect(largeText).toBe(true) }`; `#767676`/white is ~4.55:1 so `smallText` is always true

## Evidence
- Reviewer row `core-color-02`. Behaviour it was meant to catch: the large-text AA threshold (3:1) being applied to small text

## Fix
- Use a pair between 3:1 and 4.5:1 (e.g. `#949494`/white) and assert both flags explicitly

## Status
FIXED (Sprint 8, `197226e3` + `4c232c36`) — the `if` is gone; the fixture's ratio is asserted in-test to lie in (3, 4.5) and both flags asserted unconditionally. The review found the plan's suggested `#949494` sits at 3.03:1 (not "~3.5"), so the fixture was moved nearer the window's centre.
