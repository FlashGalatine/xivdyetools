# BUG-002: Extractor share links were dropped by the 4A rebuild while `ShareService.ExtractorShareParams` and og-worker's `/og/extractor/:colors.png` card remain with no producer
**Severity:** MEDIUM · **Type:** State · **Deploy unit:** web-app · **Covered by test?** no

## Location
- `apps/web-app/src/components/extractor-tool.ts` — no `ShareService`, `v4-share-button` or `URLSearchParams` reference anywhere in the 2,156-line file (every other tool wires its own share button)
- `apps/web-app/src/services/share-service.ts:114,136,285,313` — `ExtractorShareParams` encoder/decoder still present, referenced only by its own union
- `apps/og-worker/src/index.ts:1047` — `/og/extractor/:colors.png` still served and tested (`index.test.ts:554-629`)

## Evidence
- Reproduction: open Extractor, extract a palette → no Share control; paste a pre-4A `/extractor?…` share URL → the tool ignores its params (it never consumes them)
- Reviewer row `webapp-tools-b-01`; Opus pass confirmed no v4-shell path supplies extractor sharing

## Fix
- Either restore the share button on the 4A extractor (produce + consume `ExtractorShareParams`, so the OG card is reachable again) or retire the feature deliberately: remove the encoder branch, the og-worker route and its tests in one change
- Product decision first; the retire path touches og-worker (its bare deploy is the live beta)

## Status
FIXED — **restored** (Sprint 7, `161d0326` + `3eaca5a7` + `cb3f44f0` + `24ba3888`; web-app 5.11.0). Decision taken by the coordinator on 2026-09-17: og-worker's card was built net-new for 5.0 for this, seven of nine tools share, and the 4A spec never retired sharing — the rebuild simply did not re-wire it. The link carries `colors` (bar order, `#`-less uppercase, capped at og-worker's five — its crawler route accepts bare hexes only, `og-data-generator.ts:901-910`) and `algo`; picks excluded. Opening a link renders equal-share bands with the matched dyes and no image; the loupe and `+` tile stay inert until an image is loaded. `ShareService.validateShareParams` gained an `extractor` arm. Verified in a browser on the dev server. Not carried: the picture, the picks, Max Colors (a no-op on a shared palette). Follow-up filed: `BaseLitComponent.firstUpdated()` sets a reactive flag, so every v4 Lit component logs Lit's dev-only `change-in-update` warning on first render — pre-existing, not this feature's.
