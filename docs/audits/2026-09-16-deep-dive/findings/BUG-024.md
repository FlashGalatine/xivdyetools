# BUG-024: `CollectionService.importData` lets a truthy non-string `name` past its guard, then `name.trim()` throws and aborts the loop after earlier collections were persisted
**Severity:** LOW · **Type:** Error handling · **Deploy unit:** web-app · **Covered by test?** no

## Location
- `apps/web-app/src/services/collection-service.ts:931` — `if (!collection.name || !Array.isArray(collection.dyes))`
- `apps/web-app/src/services/collection-service.ts:626` — `createCollection` calls `name.trim()`

## Evidence
- Reviewer row `webapp-services-01`; needs a hand-edited import file, and the result then reports `success:false` for data that was written

## Fix
- `typeof collection.name !== 'string'` in the guard; wrap each iteration so one bad record is skipped, not fatal
