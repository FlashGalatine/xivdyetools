# BUG-007: New-preset response reports vote_count 0 after the author's auto-vote is committed
**Severity:** LOW · **Type:** State · **Deploy unit:** apps/presets-api · **Covered by test?:** No regression assertion; see evidence.

## Location
- `apps/presets-api/src/services/preset-service.ts:430`
- `apps/presets-api/src/handlers/presets.ts:1081`
- `apps/presets-api/src/handlers/presets.ts:1163`

## Evidence
- createPreset returns vote_count:0. The handler awaits addVote, which recomputes stored vote_count, then returns the original preset object rather than submittedRow or refreshed count.
- Reproduce: Submit a new approved preset; POST response preset.vote_count=0 while immediately reading that preset yields 1.
- Test gap: tests/handlers/presets.test.ts:552 success case checks status, success, name and moderation_status at :606-610; no returned vote_count or DB-state comparison. See [review and verification evidence](../evidence/).

## Fix
- Build the response from the post-vote row already read for notification or copy the successful vote result's count.
