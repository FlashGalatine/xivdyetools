# BUG-001: Harmony hue-only selection prints angular degrees as the chosen matching metric
**Severity:** MEDIUM · **Type:** Logic · **Deploy unit:** packages/bot-logic · **Covered by test?:** No regression assertion; see evidence.

## Location
- `packages/core/src/services/dye/HarmonySelector.ts:136`
- `packages/bot-logic/src/commands/harmony.ts:275`
- `packages/svg/src/harmony-card.ts:291`

## Evidence
- When strictMatching=false on an HSV-carrying wheel, selector devianceFor returns angular hue distance (:139-141). executeHarmony assigns that value directly to the main row deltaE (:275), but companions get getDistanceForMethod (:278-280), and the card grades/formats every row under matchingMethod. Thus degrees are labelled and thresholded as DeltaE/OKLAB/RGB, mixing units within one result.
- Reproduce: Run /harmony with strict_matching=false, companions=2 and matching=oklab on the RGB wheel. Inspect the main and companion row measurements: main is a hue-angle difference, companion is OKLAB distance. The former is graded against 0.041/0.101/0.174 harmony bands despite being degrees.
- Test gap: harmony.test.ts:365-389 tests only strictMatching:true and asserts result.ok, never the measures passed to generateHarmonyCard. No strictMatching:false case found in command tests. Static trace only; no suite/repro was executed by reviewer. See [review and verification evidence](../evidence/).

## Fix
- Keep hue deviance for selection, then recompute the selected dye row's displayed distance in matchingMethod just as for companions. Add a false-strictness card-argument regression; publish bot-logic then deploy consumers.
