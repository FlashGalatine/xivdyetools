**Impact:** LOW · **Category:** I/O · **Deploy unit:** apps/discord-worker · **Expected gain:** up to 49 fewer service calls per 50-item list · **Benchmark:** count binding calls and row queries for 1/10/50 favorites.

## Evidence
- Promise.all calls getPreset once per favorite, each a separate signed service-binding request and row query. Oct4 OPT-003 remains OPEN and current implementation is unchanged.
- Reproduce: 50 favorites produce 50 getPreset/PRESETS_API.fetch calls; capped batch can reduce to one request/set query.
- Test gap: Add 50-entry call-count benchmark after batch endpoint exists. No runtime benchmark performed. See [review and verification evidence](../evidence/).

- Supersedes 2026-10-04-deep-dive/OPT-003.
## Fix
- Deploy a capped approved-only batch-by-id API first, then switch the caller while preserving order, missing IDs and failures. Up to 49 fewer service-binding requests/query round trips per 50 favorites; not 49 fewer rows read. Coordinate the same implementation with security FINDING-024.
