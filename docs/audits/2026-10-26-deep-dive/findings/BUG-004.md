# BUG-004: Glamour embed truncation leaves oversized notes unbounded
**Severity:** LOW · **Type:** Edge case · **Deploy unit:** packages/bot-logic · **Covered by test?:** No regression assertion; see evidence.

## Location
- `packages/bot-logic/src/commands/glamour.ts:193`
- `packages/bot-logic/src/commands/glamour.ts:581`
- `packages/bot-logic/src/commands/glamour.ts:604`

## Evidence
- The 4000-character budget truncates only body. Names in fixed/blocked/company notes can make tail itself exceed that budget. The computed lastIndexOf position then becomes negative; with no newline at index zero, lastIndexOf returns -1 and body.slice(0,-1) retains almost the whole body. Description at :613 still includes the entire tail and can exceed Discord 4096 characters. The injectable resolver accepts long names and the live upstream cleanName has no cap, though abnormal game data is needed for the production scenario.
- Reproduce: Use a resolver answer with a fixed/blocked/company name long enough that notes.join(newline) exceeds 4000 characters. executeGlamour returns ok:true with embed.description longer than 4096; ordinary body truncation cannot make an already oversized tail fit. Static derivation; reviewer did not execute this repro.
- Test gap: glamour.test.ts:624-660 covers long acquisition/body lines (BUG-127), keeping all closing notes short. It asserts the aggregate length only for that case; no oversized-note or negative remaining-budget case exists in the reviewed tests. See [review and verification evidence](../evidence/).

## Fix
- Allocate a nonnegative tail budget first and bound/compact note names or lines, then truncate body within remaining space and assert the final description cap. Add oversized-tail and no-complete-body-line cases. Keep the worker failed-edit handling as its separate finding.
