# BUG-016: A completed preset edit can dismiss a different modal
**Severity:** LOW · **Type:** Race · **Deploy unit:** apps/web-app · **Covered by test?:** No regression assertion; see evidence.

## Location
- `apps/web-app/src/components/preset-edit-form.ts:142`
- `apps/web-app/src/components/preset-edit-form.ts:651`
- `apps/web-app/src/components/preset-edit-form.ts:806`

## Evidence
- showPresetEditForm discards the ID returned by ModalService.show. The form remains closable and Cancel remains enabled while editPreset/upload/remove awaits. Success then calls dismissTop(), so cancellation followed by another modal causes the old completion to dismiss that unrelated top modal.
- Reproduce: Start a valid edit against a delayed response. Cancel the edit, open another modal, then resolve editPreset successfully. The newly opened modal is dismissed by the original edit completion.
- Test gap: preset-edit-form.test.ts:268-289 uses a deferred edit but checks only busy/restored button labels; it never closes the form and opens another modal before resolving. No suite was run. See [review and verification evidence](../evidence/).

## Fix
- Keep the edit form modal ID and dismiss only that ID, mirroring the submission form. Keep the callback semantics explicit when the initiating modal has already closed.

OPEN — audit only; no implementation change.
