# BUG-012: SWAP does not cancel an export sheet still waiting for its chunk
**Severity:** LOW · **Type:** State · **Deploy unit:** apps/web-app · **Covered by test?:** No regression assertion; see evidence.

## Location
- `apps/web-app/src/components/glamour-block.ts:337`
- `apps/web-app/src/components/glamour-block.ts:803`
- `apps/web-app/src/components/chara-file-card.ts:358`

## Evidence
- openSheet captures listSource and sheetOpenToken before import(). show(null), reached by SWAP, clears the visible file and actions but neither increments the sheet token nor checks the captured session in the import callback. The old character's export sheet opens after the chunk arrives. Dedicated source-level Vitest probe passes while asserting this observed defect; see repro-web.txt and scripts/repro-web.test.ts.
- Reproduce: Load a glamour, click Copy list while its chunk is cold, then SWAP before the chunk arrives. The file is cleared but the old file's sheet still opens.
- Test gap: Existing lifecycle guards cover destroy/repeated opens; the audit's separate deferred import probe demonstrates the missing session-clear guard. See [review and verification evidence](../evidence/).

## Fix
- Invalidate sheetOpenToken and close any open export sheet on session replacement/clear, or bind the pending open to the captured session identity. Test SWAP and a replacement file during the import.
