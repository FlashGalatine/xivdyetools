# BUG-017: Accessibility ignores saved canonical display options until a setting changes
**Severity:** LOW · **Type:** State · **Deploy unit:** apps/web-app · **Covered by test?:** No regression assertion; see evidence.

## Location
- `apps/web-app/src/components/accessibility-tool.ts:234`
- `apps/web-app/src/components/accessibility-tool.ts:295`
- `apps/web-app/src/services/config-controller.ts:357`

## Evidence
- Accessibility initializes cardDisplayOptions from DEFAULT_DISPLAY_OPTIONS and never reads getConfig(accessibility). Its subscription only handles future broadcasts; ConfigController.subscribe merely registers a listener and does not replay current state. The sidebar loads current canonical options, so persisted showHex=false/showRgb=false/showCmyk=true disagree with cards after entering/reloading the tool. Legacy vision-type restoration does not restore these card options.
- Reproduce: Change global color-format options on another tool (for example hide HEX, enable CMYK), then enter Accessibility or reload on it and select a dye. Sidebar switches show saved settings, but cards use default HEX/CMYK visibility until another display toggle broadcasts.
- Test gap: accessibility-tool.test.ts:772-787 validates merging an explicit post-mount setConfig call. It does not preseed ConfigController, mount, and inspect first-render card properties. See [review and verification evidence](../evidence/).

- Scope is supported display fields only; intentional Accessibility price/acquisition restrictions remain valid.
## Fix
- Seed Accessibility display options from ConfigController before the first results render, then subscribe to changes. Retain intentional tool-specific metadata restrictions.

OPEN — audit only; no implementation change.
