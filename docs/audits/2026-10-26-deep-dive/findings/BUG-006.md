# BUG-006: Changing only the primary category can retain that category in secondary_categories
**Severity:** LOW · **Type:** Logic · **Deploy unit:** apps/presets-api · **Covered by test?:** No regression assertion; see evidence.

## Location
- `apps/presets-api/src/handlers/presets.ts:611`
- `apps/presets-api/src/handlers/presets.ts:1519`
- `apps/presets-api/src/services/validation-service.ts:331`

## Evidence
- validateEditRequest receives only current primary; if PATCH has category_id but omits secondary_categories, undefined is passed to validator and accepted. updatePreset retains old secondary_categories.
- Reproduce: Existing primary=jobs, secondary=[zones]. PATCH only category_id=zones. Stored primary and secondary both contain zones.
- Test gap: tests/handlers/presets.test.ts:2975 sends both lists; :3001 tests an explicitly repeated primary; :3059 tests supplied secondary against unchanged primary. No promotion with omitted secondary list. See [review and verification evidence](../evidence/).

- Category SQL uses OR/EXISTS and does not double counts; this is a stored/UI invariant defect.
## Fix
- Validate effective primary plus effective secondary list after merging edits with the stored preset; optionally normalize away the promoted secondary.

## Status
OPEN — audit only; no implementation change.
