# BUG-003: Character label cap can split a surrogate pair
**Severity:** LOW · **Type:** Edge case · **Deploy unit:** packages/core · **Covered by test?:** No regression assertion; see evidence.

## Location
- `packages/core/src/services/chara/chara-library.ts:146`
- `packages/core/src/services/chara/chara-library.ts:265`
- `packages/core/src/services/chara/chara-library.ts:269`

## Evidence
- boundedLabel truncates raw UTF-16 at 256 code units. A 255-unit prefix followed by an astral character leaves a high surrogate without its low surrogate. producer and nickname projections both call this function; serialized/UTF-8 rendered nickname can show U+FFFD. SVG escapeXml drops illegal surrogates, so that sink does not break XML.
- Reproduce: Import a .chara with Nickname = 'a'.repeat(255) + a supplementary-plane character. The capped nickname ends with only the first UTF-16 code unit of that character.
- Test gap: chara-library.test.ts:196-205 bounds only ASCII n.repeat(400) and asserts length 256, so a split supplementary-plane character is untested. Static derivation only; no suite/repro was executed by reviewer. See [review and verification evidence](../evidence/).

- Cosmetic malformed boundary: the web card displays labels; SVG strips lone surrogates. Web file-name slice at apps/web-app/src/services/chara-file-loader.ts:81 (at main `13c386e5`) needs the same boundary rule in its separate consumer sprint.
## Fix
- Truncate on code-point boundaries while preserving a documented code-unit cap; coordinate with web file-name truncation. Publish core before consumers.
