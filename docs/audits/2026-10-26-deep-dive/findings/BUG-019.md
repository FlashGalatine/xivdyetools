# BUG-019: Comparison ignores the global Stain and Spectrum display switches
**Severity:** LOW · **Type:** Logic · **Deploy unit:** apps/web-app · **Covered by test?:** No regression assertion; see evidence.

## Location
- `apps/web-app/src/components/comparison-tool.ts:398`
- `apps/web-app/src/components/comparison-tool.ts:1552`
- `apps/web-app/src/components/comparison-tool.ts:2054`

## Evidence
- Comparison setConfig applies the five color formats, delta and price only. It never assigns showStain or showSpectrum. Both card render paths read optional fields with ?? true, so those rows remain enabled despite the visible global switches and canonical config becoming false. An exact-source method extraction confirmed setConfig({displayOptions:{showHue:false,showStain:false,showSpectrum:false}}) leaves all three current properties true.
- Reproduce: On Comparison select one or two dyes. Turn off Stain and Spectrum in Options. Both switches remain off, but cards still show the stain readout and spectrum row. Navigate away/back: those fields are still default-on in the tool.
- Test gap: comparison-tool.test.ts:425-443 merely calls setConfig and asserts leftPanel has children. It does not inspect rendered card properties or rows, and its fixture omits the new options. See [review and verification evidence](../evidence/).

- Only Stain/Spectrum are claimed. Comparison's deliberate acquisition and pair DeltaE rows remain unchanged.
## Fix
- Apply the complete supported DisplayOptionsConfig key set, preferably through the shared helper. Seed it from canonical settings and test the single-card and duel-card rows.

OPEN — audit only; no implementation change.
