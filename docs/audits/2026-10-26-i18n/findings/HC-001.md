# HC-001: The localized fatal startup screen always renders an English detail sentence
**Tier:** P1 · **Locale(s):** ja, de, fr, ko, zh · **Deploy unit:** apps/web-app · **Generated?:** No

## Location
- `apps/web-app/src/main.ts:187`
- `apps/web-app/src/shared/error-handler.ts:71`
- `apps/web-app/src/shared/error-handler.ts:86`

## Evidence
- main.ts supplies translated FATAL_STRINGS for the heading/body/button, but supplies ErrorHandler.createUserMessage(appError) separately as the detail. That method always returns one of the English ERROR_MESSAGES constants. renderFatalError paints that value with textContent. The startup table exception is justified because LanguageService may itself have failed, but the detail was omitted from that standalone localization design.
- Reproduce: Use a supported non-English navigator.language and make an awaited startup dependency reject (for example block the dynamically imported v4-layout module), then reload. The localized heading and reload button surround 'An unexpected error occurred. Please try again.' Source tracing establishes the outcome; no browser fault injection was performed.
- Test gap: Fatal rendering tests supply arbitrary details, not all localized startup sentences. See [review and verification evidence](../evidence/).

## Fix
- Extend the existing dependency-free six-language fatal copy table with a localized detail (or localized safe error-code details), and use it without calling LanguageService on this failure path. Keep the default English fallback. Assert all displayed fatal-screen sentences in each locale.

OPEN — audit only; no implementation change.
