## Evidence
- The autocomplete handler resolves locale but calls getClanAutocompleteChoices(query) without it. The helper filters and prints SUBRACE_DISPLAY_NAMES-derived English clan/race names. Invalid-clan validation inserts the same English table into an otherwise translated sentence. Core already carries the official six-language clan/race names and bot-logic exports their getters. Canonical English option values can remain identifiers; their displayed names need not be English. The clan preference is currently stored but unused by commands, which lowers this candidate's practical priority.
- Reproduce: In a Japanese Discord client open /preferences set clan and type a localized clan name, e.g. サンシーカー: the helper matches only its English table and returns no corresponding choice. With an empty query it displays Seeker of the Sun (Miqo'te). Enter an invalid clan to see the English-only valid-name list in a localized error.
- Test gap: Existing helper tests pin English canonical table labels, not localized display/search. See [review and verification evidence](../evidence/).

- P1 follows the skill rule for live hardcoded UI. The optional preference has no command consumer today; that limits practical urgency but not reachability.
## Fix
- Carry locale into autocomplete, match/display official localized race/clan names while preserving existing canonical stored values, and render localized names alongside canonical tokens in validation. Keep this optional preference's dormant consumer status explicit.
