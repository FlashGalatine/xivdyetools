# I18N-005: the web-app collapses presets-api's specific error codes into a generic `submitFailed`, so the real reason reaches the user only as an English detail line
**Tier:** P2 · **Locale(s):** ja de fr ko zh · **Deploy unit:** web-app (mapping) + presets-api (codes) · **Generated?** no

## Location
- `apps/presets-api/src/middleware/ban-check.ts:38-45` — returns `{ error: ErrorCode.USER_BANNED, message: 'You have been banned from using Preset Palettes.' }`.
- `apps/web-app/src/services/preset-submission-service.ts:325-326` — on any non-OK submit: `errorCode: 'submitFailed', error: result.message`. The API's own code is discarded; the English sentence is kept.
- `apps/web-app/src/components/preset-submission-form.ts:766-772` — `ToastService.error(presetErrorMessage(result.errorCode, 'errors.submitPresetFailed'), result.error)` — arg 1 localized headline, arg 2 raw detail.
- `apps/presets-api/src/services/validation-service.ts:377` — tag-pattern / unsupported-character / secondary-category failures carry a free-text English `message` and no per-rule code.

## Evidence
- `git ls-files 'apps/web-app/src/**' | xargs grep -n USER_BANNED` → **no hits**; the code has no locale mapping anywhere in the client.
- A banned German user therefore sees the localized headline *"Absenden des Farbsets fehlgeschlagen"* over the English detail *"You have been banned from using Preset Palettes."*
- The headline is not merely untranslated — it is **wrong**: it reports a submit failure when the actual state is an account ban, and the only text that says so is in English.
- This is *not* the "raw presets-api `response.error`" case the earlier audits ruled deliberately English: that ruling was about the **bot** echoing server text. The web-app's own design comment says the server message is "shown as toast details **under the translated headline**", which presumes the headline names the cause.

## Fix
- Carry the API's `error` code through `preset-submission-service.ts` instead of flattening to `submitFailed`, and add locale keys for the terminal ones — `USER_BANNED` first, since it is actionable and permanent.
- Give the three server-only validation rules per-rule codes so `presetValidationMessage()` can translate them, matching the coded rules that already work.
