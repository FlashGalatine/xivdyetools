# I18N-006: `/budget quick preset`'s 22 choices are English dye names in every locale, though core already has all 125 dye names localized
**Tier:** P2 · **Locale(s):** ja de fr ko zh · **Deploy unit:** discord-worker (needs `register-commands`, which runs in CI on merge) · **Generated?** no
Same class as `2026-08-20-discord-worker-i18n`'s deliberately-deferred *F-03 phase 2*, but the surface grew 4.4× (5 → 22 choices) after it was deferred.

## Location
- `apps/discord-worker/src/commands/schemas.ts:1276-1279` — `choices: QUICK_PICKS.map((pick) => ({ name: \`${pick.emoji} ${pick.name}\`, value: pick.id }))`. `pick.name` is the English dye name.
- `apps/discord-worker/src/services/budget/quick-picks.ts` — 22 entries (`grep -c "id: '"` = 22).
- `apps/discord-worker/src/commands/localize.ts:116-144` — `choiceLocalizations()` has cases for `preferences`/key, `preferences`/gender, `preferences`/theme, `harmony`/type, `accessibility`/vision and `dye`/category. **No `budget` case**, so these choices ship unlocalized.

## Evidence
- A Japanese user opening `/budget quick preset` sees 22 English names in the picker while the rest of the command — description, and `/dye category`'s choices — is Japanese.
- The dye names are not untranslatable: `packages/core/src/data/locales/*.json` carries `dyeNames.*` for all 125 dyes in six locales, and the surrounding card already renders those localized names.
- The pattern to copy is in the same function: the `dye`/`category` case resolves through core via `getLocalizedCategory(value, locale)` and falls back cleanly when a locale has no value.

## Fix
- Add a `budget`/`preset` case to `choiceLocalizations()` that resolves each `pick.id` to its core `dyeNames` entry per locale, keeping the emoji prefix and the same `v === value → undefined` fallback the category case uses.
- Discord caps choices at 25 and the localized name has its own length limit — check the longest ja/de name fits before shipping.
- Takes effect only after `register-commands` runs, i.e. on merge.
