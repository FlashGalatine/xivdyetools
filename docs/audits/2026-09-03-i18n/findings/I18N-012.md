# I18N-012: punctuation and capitalization drift inside single bot-logic locale files, and stoat-worker pins `locale='en'`
**Tier:** P3 · **Locale(s):** ja zh fr (drift); all six (stoat) · **Deploy unit:** bot-logic, stoat-worker (**parked**) · **Generated?** no

## Location
- `packages/bot-logic/src/i18n/locales/ja.json:340-341` and `zh.json:340-341,354-358` — the same "label: value" shape uses full-width `：` under `errors.*` and half-width `:` under `validation.*`.
- `packages/bot-logic/src/i18n/locales/ja.json:473` — ranges mix ASCII (`1-3秒`) and wave dash (`3〜6色`, `2〜10`).
- `packages/bot-logic/src/i18n/locales/fr.json:393-406` — `preferences.methods` and `preferences.blendingModes` are two parallel option lists using three different capitalization rules; en and de capitalize both lists consistently.
- `apps/stoat-worker/src/commands/info.ts:38` — calls bot-logic's fully six-locale `executeDyeInfo` with `locale='en'` hardcoded.

## Evidence
- These are consistency defects inside one file, so no gate can see them: parity, orphan and reverse-key checks all compare *key sets*, never punctuation style. All three locale sets pass every gate.
- CJK convention is full-width punctuation in running text; the split means two adjacent bot messages punctuate differently in the same language.
- stoat-worker is **parked** (no active investment) and its own `CLAUDE.md` documents the gap, so it is recorded for completeness, not scheduled. It consumes a translator that already supports six locales, so the fix is one argument whenever the app is revived.

## Fix
- Normalize `：` vs `:` and the range dash per locale in the bot-logic files, and settle fr capitalization across the two option lists — a single pass by someone who reads each language, not a find/replace.
- Leave stoat-worker alone until the app is unparked; note it in that app's changelog if it ever ships again.
- Optional guardrail: a lint that flags half-width `:` at the end of a label value in ja/zh files would catch the recurring half of this.
