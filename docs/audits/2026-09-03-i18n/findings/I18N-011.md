# I18N-011: two latent English/CJK hazards in `packages/svg` — English default labels and an unguarded text row
**Tier:** P3 (both latent — the only production caller avoids them) · **Locale(s):** all six / ja ko zh · **Deploy unit:** svg · **Generated?** no

## Location
- `packages/svg/src/preset-swatch.ts:175` — `emptyLabel = 'No valid dyes in this preset'` as a default parameter; `authorLine` similarly falls back to `'Official'` / `` `by ${authorName}` `` at `:224`.
- `packages/svg/src/frame.ts:574-587` — `measuredRow()` draws its lead and sub text without the `fitText()` guard the package's own convention requires.

## Evidence
- **Latent, not live.** The only production caller passes localized overrides: `apps/discord-worker/src/handlers/commands/preset.ts:995-1007` supplies `authorLine`, `emptyLabel: t.t('preset.noValidDyes')` and a localized `dyeName` resolver. So no user sees the English defaults today.
- The hazard is a second caller. `packages/svg` is published and og-worker already draws preset cards from its own path; a caller that omits the options gets English baked onto a localized card with no gate to catch it — exactly the shape of 2026-08-20's F-11, which added the override parameters but left the English defaults in place.
- `measuredRow` without `fitText()`: with `WIDTHS.lead = 56` (`swatch-card.ts:89`) the current strings clear the budget by roughly 1–15 px, so nothing overflows now. CJK glyphs are full-width, so a slightly longer ja/ko/zh label is what would spill first — and a sibling CJK-overflow bug in the same area was fixed in an earlier sprint.

## Fix
- Make `emptyLabel` and `authorLine` **required** parameters (a compile error at every call site beats a silent English default), or default them to a visibly non-shipping placeholder.
- Wrap `measuredRow`'s lead/sub in `fitText()` like the surrounding rows, and add a ja/zh case to the widest existing card test so the budget is actually exercised with full-width glyphs.
