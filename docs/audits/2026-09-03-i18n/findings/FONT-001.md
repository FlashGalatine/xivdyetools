# FONT-001: all six bundled CJK subsets are still VARIABLE fonts defaulting to Thin 100, so every bold/semibold CJK glyph on every card renders thin — the 2026-08-29 fix covered only the Latin faces
**Tier:** P1 (wrong rendering, visible to a user, in exactly the three non-Latin locales) · **Locale(s):** ja ko zh · **Deploy unit:** discord-worker **and** og-worker (+ svg for the stacks) · **Generated?** the subsets are generated by each worker's `scripts/subset-cjk-fonts.py`

## Location
- `apps/discord-worker/src/fonts/NotoSans{JP,SC,KR}-Subset.ttf` and `apps/og-worker/src/fonts/NotoSans{JP,SC,KR}-Subset.ttf` — all six carry an `fvar` `wght` axis `(min 100, **default 100**, max 900)` and `OS/2.usWeightClass = 100`.
- `packages/svg/src/frame.ts:168` — `if (o.weight) attrs.push(\`font-weight="${o.weight}"\`)`, on stacks from `FONT_STACKS` that list the CJK subsets. 25 call sites pass `weight: 600`, 8 pass `weight: 700`.
- The gate that should catch this: `apps/discord-worker/src/services/font-faces.test.ts:61` and the identical `apps/og-worker/src/services/font-faces.test.ts`.

## Evidence
- `evidence/variable-font-check.txt` (fontTools): every Latin face is static and reports its real weight (`Onest-Bold` 700, `SpaceGrotesk-SemiBold` 600, …); every CJK subset is `VARIABLE … wght=(100.0, 100.0, 900.0)`.
- **resvg ignores variable axes and renders the default instance** — the repo already established this: PR #148 (2026-08-29) replaced the Latin faces with static Regular/SemiBold/Bold instances precisely because "Space Grotesk's default instance is Light (300)" made every `font-weight` a no-op (`font-faces.test.ts:7`). The CJK subsets were not part of that change.
- Why it survived: the gate's variable-font assertion is a **filename** test — `bundled.filter((f) => /VariableFont/i.test(f))` — and the subsets are named `NotoSansJP-Subset.ttf`, which does not match. Its weight-differentiation loop then iterates only `['Space Grotesk', 'Onest']` (line 64), so no CJK face is ever weight-checked.
- Net effect on a ja/ko/zh card: Latin runs draw at 600/700 while the CJK runs beside them draw at 100, so headings and labels look thin and mismatched in exactly the locales the subsets exist to serve.

## Fix
- Instance the three Noto subsets to static Regular/SemiBold/Bold the way PR #148 did for Latin (`instance-latin-fonts.py` is the precedent), or at minimum pin each subset's default instance to 400 during subsetting, and update the `FONT_STACKS` weight mapping to match.
- Change the gate from a filename match to an actual `fvar`-table check over **every** bundled face, and extend the weight loop past the two Latin families — same edit in both workers' `font-faces.test.ts`.
- Prove the fix by **rendering**, never from the SVG string: the string already says `font-weight="700"` today and is drawn thin regardless.
