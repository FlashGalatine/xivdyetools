# I18N-007: the German name for Pearl White ships as the truncated fragment `Perlmutt-`
**Tier:** P1 (broken text in a shipped locale, on the most-read data in the product) · **Locale(s):** de · **Deploy unit:** core (published — web-app, both bots, og-worker and the public API all inherit it) · **Generated?** **yes — fix `dyenames.csv`, never the JSON**

## Location
- `packages/core/dyenames.csv:114` — `30123,Pearl White ,パールホワイト,Perlmutt-,blanc perlé,진주색,珍珠白`
- Surfaces as `packages/core/src/data/locales/de.json` → `dyeNames["30123"] = "Perlmutt-"`.

## Evidence
- All five other locales are complete for this dye: `Pearl White` / `パールホワイト` / `blanc perlé` / `진주색` / `珍珠白`. Only German is a fragment ending in a dangling hyphen.
- `grep -o "Perlmutt[^,]*" packages/core/dyenames.csv` returns exactly one row — there is no sibling compound it was split from, so this is a truncation in the source row, not a naming convention.
- German dye names in this file are otherwise complete compounds (`Schneeweißer`, `Blutroter`, `Rubinroter`, …), which is what makes `Perlmutt-` visibly wrong rather than merely terse.
- A German user sees `Perlmutt-` everywhere a dye name is rendered: the web app, `/dye` cards, OG cards and `GET /v1/dyes`.

## Fix
- Restore the full German name in `dyenames.csv:114` (the FFXIV German client's name for Pearl White — `Perlmuttweißer` is the expected form, but take it from the game/XIVAPI rather than from this file), then re-run `pnpm --filter @xivdyetools/core run build:locales` and commit the regenerated JSON.
- Worth a quick scan for the same shape while you are there: any locale cell ending in `-` or `‑` is almost certainly a truncated compound.
- core is published, so this ships as a core release and both resvg workers should be re-subset afterwards if the new name adds glyphs (it does not — Latin only).
