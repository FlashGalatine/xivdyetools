# I18N-009: moderation-worker carries a full six-locale i18n apparatus that can only ever return English — decide, then either localize it or delete the machinery
**Tier:** P3 (staff-facing surface; graded down deliberately — see below) · **Locale(s):** ja de fr ko zh · **Deploy unit:** moderation-worker · **Generated?** no

## Location
- `apps/moderation-worker/src/services/bot-i18n.ts:112-119` — `const locales: Record<LocaleCode, LocaleData> = { en: enLocale, ja: enLocale, de: enLocale, fr: enLocale, ko: enLocale, zh: enLocale }`, commented *"only English for moderation bot"*.
- `apps/moderation-worker/src/services/i18n.ts:23-26` — imports the real `SUPPORTED_LOCALES` / `isValidLocale` / `discordLocaleToLocaleCode` / `resolveUserLocale` ladder from `@xivdyetools/bot-logic/i18n` and resolves a locale correctly, which is then discarded by the table above.
- Unreached content: `bot-i18n.ts:70-76` defines `preset.status.*` keys that nothing uses; `handlers/commands/preset.ts:367-370` hardcodes "Pending"/"Approved"/"Rejected"/"Flagged" instead.
- Four interaction handlers construct no translator at all: `handlers/buttons/preset-moderation.ts:82`, `handlers/buttons/ban-confirmation.ts:66`, `handlers/modals/ban-reason.ts:45`, `handlers/modals/preset-rejection.ts:49`.
- `scripts/register-commands.ts:41-117` — the `/preset` tree has no `name_localizations` / `description_localizations`.

## Evidence
- **Why P3 and not P1** (the unit reviewer filed these as P1): every one of these surfaces is moderator-facing, inside a channel the worker itself restricts — `channelRestricted: 'This command can only be used in the moderation channel.'` Nothing here reaches a preset author: author notifications are sent by `apps/discord-worker/src/handlers/commands/preset-notifications.ts`, which **is** localized. That puts this in the same class as the `/stats` admin dashboards that earlier audits ruled deliberately operator-English.
- What is genuinely wrong is the mismatch, not the English: the worker pays for a locale ladder, a `Translator`, and a `preset.status.*` key set that cannot change the output, so a future reader (or audit) reasonably assumes localization exists.

## Fix
- Make the decision explicit. If moderation stays English-only: delete the six-entry `locales` map in favour of a plain English table, drop the unused `preset.status.*` keys, and put a one-line note in the worker's `CLAUDE.md` so this is not re-filed.
- If moderators should get their own language: real locale files plus translators in the four handlers above and `name_localizations` in `register-commands.ts` — a real sprint, not a cleanup.
