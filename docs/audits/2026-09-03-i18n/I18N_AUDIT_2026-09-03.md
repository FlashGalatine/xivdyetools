## Positive controls — already right, do not re-file

- **All three locale sets are structurally perfect**: 1872 keys per locale across them, zero duplicate / missing / extra / placeholder defects. Three prior audits plus the 2026-08 remediation have genuinely fixed the data layer.
- **Font coverage is tight**: 0 surplus glyphs in all six CJK subsets and 0 real tofu — the first audit since 2026-04 with no stale subsets. `font-coverage.test.ts` in both workers is a well-built gate (union semantics, a separate "ja glyphs in the JP subset" assertion, surplus as a warning, and a comment explaining why md5 comparison is wrong).
- **web-app's identical-value allow-list** (`scripts/i18n-identical-allowlist.json`) carries a written reason per entry *and* reports entries that stop being identical, so it cannot rot. The strongest guardrail of the three sets — the model the others should copy.
- **web-app eslint i18n rules**: 232 files, 0 active warnings; all 28 `innerHTML` template sites route through `LanguageService.t()`.
- **214 dynamically-built web-app keys and 44 bot-logic dynamic suffixes** resolve in all six locales — verified by enumeration, not assumed.
- **core's generated locales have no drift** — nobody has hand-edited a generated artifact.
- **PR #158 already unified the bot locale layer** (`isValidLocale`, `SUPPORTED_LOCALES`, the Discord-locale map and KV resolution now come from `@xivdyetools/bot-logic/i18n`), fixing the drift that caused BUG-001.
- **api-worker's public API is correctly designed for i18n**: `?locale=` on `/v1/dyes*` and `/v1/match/*`, stable English `name` plus optional `localizedName`, documented in VitePress. The chara ko/zh tables cover >99.9 % of the equippable set with a verified English fallback.
- **oauth renders no user-visible text at all** — every route is JSON or a bodiless 302, so there is nothing to localize.

## Rejected suspicions — checked and dropped

- **"Six gates are failing."** My own `--reporter=basic` flag; vitest 4 has no `basic` reporter, so `loadCustomReporterModule` threw before any test ran. A red gate is a flag error until proven otherwise.
- **CJK punctuation "missing" from the JP/KR subsets** (`，、。「」〜！（）／：；＝？`). Not tofu — every one is carried by the SC face and every stack lists all three CJK subsets. The skill's per-font script is stricter than the runtime; the repo's union-based gate is the correct model.
- **`U+FE0F` in no bundled face.** `discord-worker/src/services/font-coverage.test.ts:152` excludes it deliberately: zero-width variation selector, and `♂ ♀` themselves are covered.
- **Subsets over the 500 KiB "over-inclusion" threshold** (discord SC 814 KiB, JP 547 KiB; og SC 558 KiB). Surplus is **0** glyphs in all six — the size is the honest cost of 1065 / 562 CJK codepoints. The byte threshold is a bad proxy.
- **discord-worker fonts cut ~14 h before the last bot-logic string change.** Coverage is complete, so that change added no glyph. Near-miss, not a defect.
- **The nine emoji in `CATEGORY_DISPLAY`** (`preset-swatch.ts:87-94`) are Discord *message* text, never drawn by resvg — the file says so at `:198`. Only the `★` is drawn.
- **`Δ` is not tofu.** Space Grotesk carries it in both workers. It renders from a different face than the surrounding Fragment Mono — a minor typographic inconsistency, not a missing glyph.
- **CJK literals in `packages/svg`** (`harmony-card.ts`, `swatch-card.ts`, `dye-info-card.ts`) are inside JSDoc comments describing label examples — never drawn.
- **core `visions.*` duplicating `visionTypes.*`** — deliberate short vs long forms.
- **web-app de `swatch.slotTattoo` = "Tattoo"** and the other identical-to-EN values — allow-listed with a reason ("cognate — 'Tattoo' is German").
- **`labels.dark` pairings** (`themes.standardDark`, `swatch.rangeDark`) — same English word, different concepts; core's fr value is lowercase `foncé`, an inline modifier. Not drift.
- **moderation-worker's eight "P1"s.** Every one is moderator-facing inside a restricted channel; author notifications come from discord-worker and are localized. Regraded to a single P3 decision (`I18N-009`).
- **`acquisitions.Crafting` ja.** The dictionary says `制作`, core says `製作`; FFXIV JP uses `製作`, so the **dictionary** is the likely error. Filed inside TERM-002 as a human call, not a code change.

## Recommendations — guardrails

1. **Check the audit base against `origin/main` before running anything.** This audit lost work to a two-day-stale local `main`, and a finding had to be withdrawn.
2. **Derive the font gate's emitted-glyph set from source** instead of the hand-maintained `CODE_GLYPHS = 'Δα·—…→↓–↔≈°÷♂♀#%'`. That literal is why `★` shipped (FONT-002).
3. **Assert `fvar` absence over every bundled face**, not a `/VariableFont/i` filename match, and extend the weight loop past the two Latin families (FONT-001). Prove weight by rendering, never from the SVG string.
4. **Extend `font-contract.test.ts` to scan all of web-app `src/`** for `font-family:` literals naming a bundled family (FONT-003) — it currently guards one already-fixed file.
5. **Give bot-logic an identical-value allow-list with reasons**, matching web-app's; it is the only set of the three without one.
6. **Make `emptyLabel` / `authorLine` required** in `preset-swatch.ts` so a new caller cannot silently bake English onto a card.
7. **Route shared game vocabulary through core's getters** rather than restating it — one rule would close TERM-001, TERM-003 and most of `vocab-split.txt`'s 29 divergent pairs.
