# OPT-002 — A fused image-to-palette route could remove pixel round trips

**Priority P3, conditional follow-on. Potential impact medium. Confidence high in source path. Effort high. Risk high. Primary unit apps/image-worker, consumer apps/discord-worker. Semver additive service route or breaking protocol migration.**

## Location

- `apps/image-worker/src/photon.ts:187` performs existing Rust/WASM resize and pixel extraction.
- `apps/discord-worker/src/handlers/commands/extractor.ts:535` receives pixels, converts to RGB objects and clusters.
- `apps/image-worker/src/admission.ts:18` shares one admission slot across extraction and thumbnail work.

## Evidence

- Default RGBA output is at most 256 KiB, explicit maximum 1 MiB. Returning at most ten clusters could reduce transfer and host allocation. [Review](../evidence/review-image-web.md)
- Photon already contains ownership patches. Fusing work extends admission occupancy and can affect thumbnail rejections.
- Existing source records image-resource activation holds. The audit did not measure provider CPU or aggregate isolate memory.

## Fix

- Compare packed TS in Discord, packed TS in image-worker and a fused Rust kernel using the same decode/sampling. Preserve the existing raw endpoint for staged adoption and rollback.
- Measure mixed-route throughput, memory, abort cleanup and exact retry errors. Close existing image acceptance prerequisites before production adoption, then release the Discord consumer separately.

## Status

OPEN — conditional evaluation, expected latency and resource gain unmeasured.
