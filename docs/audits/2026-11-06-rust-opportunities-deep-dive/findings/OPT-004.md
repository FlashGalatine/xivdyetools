# OPT-004 — Exact distance batches are a conditional secondary kernel

**Priority P3, deferred. Potential impact low at ordinary volumes. Confidence high in source path. Effort medium. Risk high for exact matches. Primary unit packages/core. Semver additive batch minor or conditional major.**

## Location

- `packages/core/src/services/dye/DyeSearch.ts:197` uses exact perceptual scans to preserve correct winners.
- `packages/core/src/services/dye/DyeSearch.ts:218` calculates distances and retains the first strict winner.
- `apps/web-app/src/components/gradient-tool.ts:1492` participates in sequential exclusions across gradient results.

## Evidence

- Synthetic 125-query CIEDE2000 batches measured 31.45 ms upper median. Ten-query batches measured 2.00 ms. [Raw evidence](../evidence/baseline-node.json)
- Normal palette, mixer and gradient callers use small batches. Public match endpoints receive one target. A production 125-query workload was not established. [Review](../evidence/review-core.md)
- RGB already has a k-d tree and coordinate conversions already have caches. Prior approximate perceptual filtering missed correct dyes.

## Fix

- Require a real repeated-query profile, then compare prepared TS coordinates with batched f64 WASM. Map returned indexes to host Dye records and preserve custom datasets, exclusions, ordering and failures.
- Test all metric oracles and near ties. Do not turn dependent gradient queries into independent parallel queries.
