# OPT-003 — Browser palette readback and clustering occupy the UI thread

**Priority P3. Potential impact medium. Confidence high in source path. Effort medium for worker baseline. Risk medium. Primary unit apps/web-app. Semver app-internal if behavior is preserved.**

## Location

- `apps/web-app/src/components/extractor-tool.ts:2165` yields a frame before synchronous full-canvas readback and core clustering.
- `apps/web-app/src/components/extractor-tool.ts:2223` samples a grid before core's 10,000-sample default.
- `apps/web-app/public/_headers:31` specifies a script CSP requiring review for WASM loading.

## Evidence

- A 3840×2160 RGBA readback represents about 31.6 MiB before object samples. Moving only clustering leaves that readback on the main thread. [Review](../evidence/review-image-web.md)
- Existing character-inspection module workers supply cancellation and buffer-transfer patterns. Browser long tasks and mobile performance were not measured in this audit.

## Fix

- Compare a lazy TS worker with transferred packed buffers and a readback variant before adding the Rust kernel. Preserve image privacy, visible canvas/loupe and stale-result rejection.
- Measure full interaction and long tasks on desktop/mobile. Test served CSP, fallback and explicit WASM bundle budgets if that variant proceeds.

## Status

OPEN — responsiveness evaluation proposed, Rust gain unknown.
