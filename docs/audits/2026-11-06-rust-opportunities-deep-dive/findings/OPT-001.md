# OPT-001 — PaletteService clustering merits a packed-kernel comparison

**Priority P3, first Rust experiment. Potential impact medium. Confidence high in source path. Effort medium. Risk high for numerical parity. Primary unit packages/core. Semver compatible internal patch or additive minor, conditional major.**

## Location

- `packages/core/src/services/PaletteService.ts:217` allocates assignments and cluster arrays per pass.
- `packages/core/src/services/PaletteService.ts:302` repeats assignment/update and performs a final assignment.
- `packages/core/src/services/PaletteService.ts:416` exposes synchronous extraction with input normalization and logging.

## Evidence

- Default synthetic 10,000-pixel clustering measured 4.75 ms upper median, ten-color clustering 23.60 ms. [Raw evidence](../evidence/baseline-node.json)
- Arrays, repeated scans and distance work provide a plausible kernel boundary. Initialization already caches nearest distances. [Review](../evidence/review-core.md)
- 2026-11-07 addendum: built core, packed TS and a Rust/WASM port matched exactly under injected draws. Rust measured 1.2–1.4× over packed TS. Packed TS with squared-distance assignment alone measured 1.35–1.6× over current. [Comparison](../evidence/review-rust-comparison.md)
- Public RGB[] input retains fractional channels, sampled order, stable rounded ties, warnings and empty-cluster behavior.

## Fix

- Land the TS control first: counts/sums over packed input and squared distances in assignment only, keeping k-means++ and movement square roots. Ordering is provably identical for integer channels. Keep square roots or a differential test for fractional RGB[] input.
- Defer Rust. After that fix, representative 10,000-sample inputs saved 0.9–3.9 ms in the kernel alone, under the plan's proposed 5 ms bar. Reopen with real-screenshot, browser or workerd evidence, or a larger workload.

## Status

OPEN — Node comparison recorded 2026-11-07. TS squared-distance patch recommended, Rust adoption deferred.
