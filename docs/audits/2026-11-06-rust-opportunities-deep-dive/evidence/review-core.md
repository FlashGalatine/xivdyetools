# Core and bot-logic Rust opportunities

Reviewed source at ee4dd0b65375ed994d8ab0dafc3a695b614c1a3d on 2026-11-06. Source inspection only. The timing thresholds below describe existing tests, and the candidate ranking describes hypotheses.

## 1. Palette extraction — first candidate for an optional Rust/WASM comparison

- The hot loop in packages/core/src/services/PaletteService.ts:217–241 allocates an N-element assignment array that both callers discard, allocates K arrays, pushes N RGB references, and calls a square root for each point-centroid distance. :248–271 then rescans the clusters for rounded means. :302–339 runs the assignment/update loop until movement is strictly below threshold or the iteration limit, then assigns again for final counts. With 10,000 samples, 10 centroids and 25 iterations plus a final count pass, the assignment-only work can reach 2.6 million distance evaluations, or 10.1 million for the public 100-iteration limit. These are work bounds for that sample size, with early termination common by design and no execution data here. Public maxSamples has a floor of two and a default of 10,000, with no upper cap on a finite override (:358–365, :416–508).
- Preserve the existing useful reductions. K-means++ stores nearest distances and only compares the new centroid (:154–210), avoiding an extra factor of K during initialization. Distinct counting stops as soon as it reaches K (:289–296). Sampling preserves the first and last filtered inputs by rounded evenly spaced indexes (:381–396). The palette returns up to K populated clusters, rounds centroids and dominance percentages, and sorts by descending rounded dominance with source order for ties (:523–535). The final assignment can legitimately omit an empty cluster. A 0%-rounded cluster still has pixels. extractAndMatchPalette is synchronous, respects injected DyeService, keeps palette order, omits unmatched colors, and reports distance on the selected method (:555–594). Alpha filtering is inclusive at 128 by default and accepts Uint8ClampedArray or number[] (:607–622). Public extractPalette accepts RGB[] and the distinct-color code explicitly preserves non-integer channels (:276–296). Options validation and logger warnings stay on the existing facade.
- The web caller yields a frame for the busy state then does a full canvas getImageData readback and synchronous extraction. It samples by a spatial grid targeting roughly 100,000 positions before alpha filtering and the core's 10,000 cap. Because step is floored, this is a target rather than a hard cap. The 20 MiB upload limit is on file bytes. See apps/web-app/src/components/extractor-tool.ts:1317, :2142–2239 and apps/web-app/src/shared/constants.ts:129. The Discord caller defers its reply, gets resized RGBA through image-worker, builds an RGB object for each opaque pixel, and supplies 10,000/25 explicitly, with 3–10 requested colors. Its ordinary binding request omits maxDimension, so the default 256 maximum side yields at most 65,536 RGBA pixels before filtering. The binding allows an explicit 16–512 maximum side. See apps/discord-worker/src/handlers/commands/extractor.ts:72–75, :475–503, :530–558, apps/discord-worker/src/services/image-client.ts:66–78, :110–112, apps/image-worker/src/index.ts:153–172, apps/image-worker/src/photon.ts:55, :103–138, :181–202 and apps/image-worker/src/validators.ts:103–121. Decode and resize already use Photon WASM.
- First comparison is TypeScript that avoids per-pass assignment and member-array allocations with per-cluster counts and component sums in input order, keeping a final count-only pass and a packed RGBA path for callers that already have bytes. A two-pass filter plus index sampler or packed intermediate can remove object creation while retaining the current order of grid sampling, alpha filtering and post-filter index sampling. Use the same random draws to test against existing output. Squared distances are an optimization to verify separately. The existing initializer uses sqrt followed by squaring for probability weights, so algebraic equivalence alone cannot guarantee the same seed for a given draw. Even assignment ties need parity on non-integer or exceptional RGB input. Retain general RGB[] handling, including its numeric precision, in JS unless a separately validated f64 adapter covers it.
- Compare the typed-array TS loop and one batched WASM call over the same bytes and seeded draws. Include image readback, packing and copy costs, output conversion, cold load and instantiation, warmed runs, allocation and peak memory, and browser main-thread blockage. A Web Worker answers browser responsiveness separately from a faster kernel. A possible follow-on experiment batches palette extraction inside image-worker to avoid the RGBA service-binding response. Moving that boundary changes cross-worker API, error attribution and rollout risk, so measure the smaller path first. Useful fixtures include flat logos, low-opacity regions, many similar colors, noisy screenshots, equal distances and a final empty cluster. Palette tests cover empty input, distinct colors, sample size and warning behavior, match metric forwarding, dominance order and alpha handling (packages/core/src/services/__tests__/PaletteService.test.ts:37–187, :217–334, :386–536). The core integration performance suite has no palette timing.

## 2. Exact color-distance batches — second candidate with a real batch caller

- DyeService supports caller-supplied tables (packages/core/src/services/DyeService.ts:72–83). DyeDatabase eagerly indexes a loaded dataset and returns the same dye record objects inside copied arrays (packages/core/src/services/dye/DyeDatabase.ts:327–404, :419–448). Bundled catalog is 125 dyes with facewear separated (packages/core/CLAUDE.md:7, :214–221). Preserve custom datasets, legacy-shaped data and query-time exclusion, plus object identity across results. Closest and range already use the RGB k-d tree only when the method is RGB. For the five other options, search uses the exact scan. Prior RGB-radius heuristics skipped the actual winner in oklab (for #00FF55 in the recorded counterexample) and omitted valid range results. See packages/core/src/services/dye/DyeSearch.ts:167–238 and :256–323. Do not translate a heuristic or silently convert to a different metric. Default is CIEDE2000 and unknown runtime values fall through to it. Distinguish is unrounded percentage on the RGB ranking scale. Scalar functions remain synchronous and preserve malformed query warnings plus null or empty results, individual invalid-entry skips, and the unloaded database error outside the catch. Strict less-than preserves first encountered winner in exact scan; ascending stable sort preserves ties and range threshold is inclusive. RGB tree ties follow tree traversal (packages/core/src/utils/kd-tree.ts:134–170, :187–196). Facewear exclusion is already in closest checks, in tree construction and in exact range.
- The numeric loops offer a TS baseline. ColorConverter already caches RGB/HSV/LAB/OKLAB and defensive copies from object caches (packages/core/src/services/color/ColorConverter.ts:95–119, :219–242, :638–674, :1057–1095). Prepare query and eligible dye color coordinates once per request and share the filter Set where caller semantics permit. If a per-dataset precompute is considered, cover rebuild and the shared live dye records rather than freezing a stale parallel table. Return the already-computed winning distance to internal callers that currently recompute it. A single batched boundary taking packed f64 coordinates and returning winner indexes/distances makes more sense than one WASM call per scalar. Benchmark native Math-heavy CIEDE2000 without assuming the port improves it. Keep stable order and host Dye references by mapping the indexes back in JS. Avoid force-fitting parallel batches across the web Gradient path where each result can change the exclusions of the next step (apps/web-app/src/components/gradient-tool.ts:1492–1622).
- Ordinary workloads are small. Discord Gradient schema is 2–12 steps (default 6) while bot-logic's public stepCount is a number and its generator loops directly without enforcing that adapter cap. Web Gradient clamps 3–12. Discord Mixer uses five fixed ratios, while Web Mixer asks for 3–8 results and searches a small filtered dye table. Palette matches at most 10 extracted clusters. API match routes are single query, with range limit 1–125 and API filters before the final slice. See apps/discord-worker/src/commands/schemas.ts:429–434, packages/bot-logic/src/commands/gradient.ts:46–51, :204–213, :301–347, packages/bot-logic/src/commands/mixer.ts:57, :99–122, apps/web-app/src/components/gradient-tool.ts:109–119, apps/web-app/src/components/mixer-tool.ts:124–137, apps/web-app/src/services/mixer-blending-engine.ts:134–158, and apps/api-worker/src/routes/match.ts:34–60, :77–114. Bot gradient and mixer narrow the candidate pool before the nearest search. Do not batch by picking an unrestricted nearest result and discarding it after.
- packages/core/src/services/__tests__/DyeSearch.parity.test.ts:44–78 checks brute-force winners over the 64-point RGB grid for supported methods. packages/core/src/services/dye/__tests__/DyeSearch.test.ts:309–440, :571–605, :643–653 covers exclusions, invalid and shorthand hex, empty/null, range sorting and default method. Existing core performance test :99–126 uses 100 calls to compare RGB and CIEDE2000, with thresholds below 2 ms and 10 ms per call. :129–148 calls default scalar CIEDE2000 closest 50 times and asserts below 10 ms per match, despite the test's k-d-tree label. :151–171 covers 50 scalar RGB tree range calls, with a ceiling below 5 ms per query. These are regression bounds, not evidence of CPU concentration or a WASM speedup. Before taking on a Rust target, require traces showing repeated exact scanning dominates a real interaction after TS preparation and control overhead.

## 3. Color math and blending — retain scalar TypeScript, profile spectral sweeps separately

- The original duplication decision at DEPRECATIONS.md:318–339 is historical. Current core CHANGELOG.md:708–719 records 5.1.0 unrounded LAB and exact CIE constants, and :778–806 records 5.0 removing Gossett-Chen, redefining the RYB facade coordinates, and routing every ColorService mixer into the same blendColors implementation. Current code packages/core/src/services/ColorService.ts:556–579, :634–687 confirms delegation, uppercase return facade and shared RYB transform rescaled to 0–255. /blending gives lowercase hex and its RYB type uses 0–1. Current packages/core/src/blending/conversions.equivalence.test.ts:149–244, :258–320 pins LAB forward/inverse convergence, RYB scale agreement and genuine remaining precision and unit differences (OKLAB rounded to six decimals in converter, HSL normalized 0–1 in blending versus rounded 0–100 in converter, differing inverse rounding). Keep the standalone blending import graph. Moving its small helpers behind a heavyweight core import changes the consumer entry's footprint.
- packages/core/src/blending/blending.ts:66–112 normalizes finite ratios into [0,1], falls back to 0.5 on nonfinite or nonnumber input, handles six modes and falls back to RGB for an unknown runtime mode. :128–155, :226–237 encode hue-arc and neutral endpoint behavior. Keep JS-compatible rounding and clamping, ratio direction, hex validation/exception behavior, precise constants and interpolation units at the existing subpath. Floating-point changes can move an RGB channel by one byte or flip a dye ID in a near tie. Reuse the current blend algebraic laws (packages/core/src/blending/algebraic-laws.test.ts:54–128, :193–210), facade parity (:55–68, :140–155 in packages/core/src/services/__tests__/ColorService.blending-parity.test.ts), the 34 Sharma pairs (packages/core/src/services/color/__tests__/ciede2000-conformance.test.ts:105–133) and the gamut tests (packages/core/src/services/color/__tests__/gamut-map.test.ts:30–109).
- Spectral is an identifiable repeat-work exception. Each spectral call creates both spectral.Color objects and mixes through spectral.js, whose reconstruction is documented as 38 bands (packages/core/src/blending/blending.ts:241–267). Bot /mix calls blendColors five times with the same endpoints and bot /gradient can do up to 12 steps on the Discord adapter (default 6). Web Mixer delegates its spectral mode to the facade (apps/web-app/src/services/mixer-blending-engine.ts:75–90); the OG mixer blends once or twice (apps/og-worker/src/services/svg/mixer.ts:98–114). First profile reuse of preprocessed endpoints within a same-pair TypeScript sweep or deferred mode loading, subject to the library's state and output tests. A different spectral implementation or wholesale color crate risks changing visible blend output and swatch matching. Fund a Rust sweep only after phase timings justify it and tests reproduce exact rendered outputs.

## 4. Harmony and budget — retain TypeScript

- The modern shared harmony selector ranks the filtered candidate pool (roughly 125 bundled dyes) by hue or the chosen metric per target, sorts the scored array, then uses per-slot exclusion, pin reservation, duplicate fallback and companions in stable sequence. There are at most three offsets for the stock wheel types. Unknown harmony keys return [] and wheels that do not carry base HSV force perceptual matching. See packages/core/src/constants/index.ts:166–177 and packages/core/src/services/dye/HarmonySelector.ts:130–159, :188–215, :234–319. Web, bot and OG use it (apps/web-app/src/components/harmony-tool.ts:1543–1577, packages/bot-logic/src/commands/harmony.ts:197–231, apps/og-worker/src/services/svg/harmony.ts:98–110). Legacy HarmonyGenerator already has hue-bucket lookup (:547–565), and core perf :176–208 tests legacy triadic/all-type paths, not the modern selector. Golden tests in packages/core/src/services/dye/__tests__/HarmonySelector.golden.test.ts:273–334 cover all dyes/types and configuration variants. If profiled, share distance preparation and measure render scheduling before porting ranking. Fixed-lightness ring stop generation performs search/bisection at fixed lightness (packages/core/src/services/dye/wheels/oklch-lightness.ts:15, :59–71 and packages/core/src/services/color/ColorConverter.ts:1302–1400). The implementation already caches the last ring stop count (:63–72). Web requests fixed 72 (apps/web-app/src/components/harmony-tool.ts:1247), while the API accepts 3–360 with a default of 72 (apps/api-worker/src/routes/wheels.ts:42–51). A repeated standard ring therefore already has a cheap warm path. Measure mixed-count misses before proposing additional caching. Preserve the first sRGB gamut exit for blue and the chosen wheel's semantics.
- Budget candidate scan runs before price I/O. Discord deduplicates price IDs, fetches through cache and batched Universalis, and sorts/group-packs a small set of rows (apps/discord-worker/src/services/budget/budget-calculator.ts:151–312). apps/discord-worker/src/services/budget/universalis-client.ts:81–82, :266–284 batches in groups of 100 sequentially. Price-cache already has 300-second fresh and 900-second stale handling (:22–31, :188–239 in apps/discord-worker/src/services/budget/price-cache.ts). Integration tests distinguish one versus multiple batches and merged price results (:110–132 in apps/discord-worker/src/services/budget/budget-pipeline.integration.test.ts). Web Budget scans a similarly small table, already deduplicates into a single service call, generation-fences response writes, and recomputes distance for retained rows after the await (apps/web-app/src/components/budget-tool.ts:640–706, :731–766). Reuse per-run distance values if CPU matters and measure cache/miss/remote time separately. Keep display rounding, match thresholds, tier/consolidation pricing, null/stale row placement and async error policy. The host I/O flow and card assembly are poor Rust targets.

## 5. Character parser, character projection and command shells — retain TypeScript

- Live .chara import already moved to exact-pinned xivcharakit 0.1.0-beta.4 (packages/core/package.json:78). The small /chara facade exports a synchronous inspectCharaForTools(string | Uint8Array) and async resolveCharaWithProvider, with an 8,192-byte limit inside the reader. The main entry wraps that resolve with bundled host palettes and dye lookup. See packages/core/src/chara.ts:4–16, packages/core/src/services/chara/chara-library.ts:139–143, :217–248, and packages/core/src/services/chara/chara-library-resolve.ts:33–49. The web caps File.slice then reads in a dedicated inspection worker with an external palette provider. Discord checks attachment metadata and actual capped streaming length. Bot-logic calls the same core facade (apps/web-app/src/services/chara-file-loader.ts:87–109, apps/web-app/src/workers/chara-inspection.worker.ts:24, :68–85, apps/discord-worker/src/utils/chara-attachment.ts:82–114, packages/bot-logic/src/commands/chara-identity.ts:39–51). Worker input refusals are routed by fixed error code and diagnostic projection sanitizes/truncates paths and issue lists (packages/core/src/services/chara/chara-library.ts:47–50, :148–185).
- The parser is a bounded per-file operation with the web cost already off the UI thread. The public source tests explicitly pin 8,191/8,192/8,193 bytes, multi-byte strings, invalid UTF-8, malformed JSON, duplicate keys and unknown producer, and the declaration/entry tests pin the palette-free import graph (packages/core/src/services/chara/__tests__/chara-library.test.ts:57–104, packages/core/src/__tests__/chara-entry.test.ts:23–29, :46–65, :115–128). Full host/library parity captures intentional divergences; the legacy native JSON.parse method is separately synchronous and its decoded-text entry does not enforce the facade limit (packages/core/src/services/chara/chara-parser.ts:427–475 and packages/core/src/services/chara/chara-limits.ts:8–15). A Rust reader in core would create a second interpretation and error surface, while WASM startup, artifact size and marshalling are paid at very small inputs. The web .chara inspection JS chunk has a specific 35 KB gate (apps/web-app/scripts/check-bundle-size.js:153–160, apps/web-app/src/__tests__/bundle-budget.test.ts:75–81). The million-space GPOSERS performance test targets a historical whitespace formatter regression, not parser file throughput (packages/core/src/services/chara/chara-gposers.ts:120 and packages/core/src/services/chara/__tests__/chara-gposers.performance.test.ts:5–49).
- Bot-logic command shells are localization, filter application, small data transforms, network adapter calls and SVG presentation. The package already shares a DyeService singleton and uses per-locale instances to prevent cross-request races. Preserve public Promise results, discriminant, localized message, logger suppression of raw inputs and neutral embed shape across Discord and Stoat. See packages/bot-logic/CLAUDE.md:166–209. Glamour's resolver I/O and grouping by slot (packages/bot-logic/src/commands/glamour.ts:446–488, :516–539), Swatch's small nearest lists and public back-mapping (packages/bot-logic/src/commands/swatch.ts:377, :395–434, :499–520), compare/contrast pair loops and dye-info sorting have no demonstrated benefit from a Rust shell. Keep character diagnostics and privacy constraints even if a future hot numeric kernel is replaced.

## Semver and proof gates

Core 5.16.0 exports ".", "/blending", "/chara", and "/package.json", ESM and types, and declares Node >=18 while also serving Vite and Workers. Bot-logic 4.12.0 declares Node >=18 and exports "." and "/i18n". See packages/core/package.json:2–24, :90–91 and packages/bot-logic/package.json:2–26, :46–47. Internal parity-preserving TS improvements or a transparently falling-back optional kernel with the same export, initialization, platform, output and error contracts can be a patch. An opt-in additive typed/batched API can be a minor. Making existing sync calls async, requiring caller initialization or replacing supported runtimes, removing exports, changing result units/shape/tie choices as a policy, or choosing a perceptibly different mixing algorithm is breaking. Existing numeric-correction precedent includes a core 5.0 major for the changed RYB model. Treat separately from a behavior-preserving implementation swap.

Core 6.0.0's legacy parser/resolver and legacy-only type removals already have written gates. Retain the shared limit, live types and palette-free entry. Bot-logic 5.0.0's planned SwatchResult.character, SwatchCharacter and back-mapping removal has separate gates for the published minor, prerequisite releases, beta/production acceptance and a check for external consumers. Those are planned in DEPRECATIONS.md:394–444. This audit did not verify registry availability, consumer acceptance, or authorize combining those removals with a kernel change. Downstream package consumers are web, api-worker, discord-worker, og-worker, svg and bot-logic, with Stoat/moderation worker transitive or direct bot-logic dependencies. Check declarations/tarball artifacts and browser/worker loaders as well as runtime parity. Publication currently builds, tests and packs artifacts before an isolated, script-disabled publisher verifies them (CLAUDE.md:174–190, :215–217). Optional WASM needs package and bundler validation for both code and .wasm bytes, cold and warm runtime measurements, and a TS fallback. A new kernel artifact or a major number alone is no performance evidence.
