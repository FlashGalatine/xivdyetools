# Rust opportunities in the image pipeline

Scope is tracked source at `ee4dd0b65375ed994d8ab0dafc3a695b614c1a3d`. This is a static review. Tests, benchmarks, deployment state and provider limits were not independently measured or verified.

## 1. Prototype a fused image-to-palette kernel after the resource gate

- Discord defers `/extractor image`, sends the attachment URL to the image binding, reads RGBA and dimensions, allocates an RGB object for every pixel with alpha ≥128, samples at most 10,000, then clusters, matches and deduplicates dyes before building SVG and rasterizing. The core is RGB k-means++ with random seeds, up to 25 Lloyd iterations on the Discord path, per-iteration cluster/assignment allocations, a final assignment and rounded dominance. References: `apps/discord-worker/src/handlers/commands/extractor.ts:430,497,535,539,553,562,590,603`; `apps/discord-worker/src/services/image-client.ts:85,109`; `packages/core/src/services/PaletteService.ts:154,217,302,381,504,522,554,605`.
- Image Worker validates the URL and redirected URL, bounds encoded bytes during fetch, checks format and allocation-bearing headers, then decodes with Photon, uses Lanczos3 resize as needed, copies RGBA out of WASM and releases owned buffers. Default 256² output is ≤256 KiB; explicit max 512² is ≤1 MiB. Input gates are 5 MiB encoded, 4096/axis and 8,388,608 pixels. References: `apps/image-worker/src/validators.ts:26,39,48,99,300,419,464,498,546`; `apps/image-worker/src/photon.ts:55,84,103,147,187,204,211`; `apps/image-worker/src/index.ts:136,170`.
- Compare the current pipeline, packed/two-pass TypeScript in Discord using the existing response, packed TypeScript in image-worker returning clusters, and a Rust kernel fused into the existing decode/resize WASM so pixels can stay in linear memory. A separate palette WASM fed via JS can introduce another full copy. Moving a palette-only kernel would keep matching, localization, deduplication and cards in Discord and could reduce the response to ≤10 cluster records. The earlier split cut at raw pixels to avoid pulling the dye DB into both Workers. References: `docs/operations/IMAGE_WORKER_SPLIT.md:75,79`; `apps/discord-worker/src/handlers/commands/extractor.ts:553,562,574`.
- Preserve alpha and exact filtered sampling order, endpoint inclusion, bounds/defaults, fewer distinct colors, empty clusters, stable ordering of rounded ties and downstream dye/card/error behavior. Inject the same random draws in differential tests and use a representative unseeded corpus too. Keep all-transparent and malformed inputs in the matrix. Existing controls: `packages/core/src/services/__tests__/PaletteService.test.ts:99,120,177,301,470`; `apps/discord-worker/src/services/image-input-errors-contract.test.ts:83,105`; `apps/image-worker/src/photon-gate.test.ts:47,69,76`; `apps/image-worker/src/dimensions.test.ts:186,216,233`.
- Measure phase CPU/wall time, binding bytes, cold/warm p50/p95, WASM capacity and total isolate memory under mixed extraction and thumbnail traffic. Both routes share a single per-isolate slot with no queue and release on actual completion; a longer extraction can raise thumbnail refusals. Keep request-abort and waitUntil cleanup, exact 503 marker and Discord’s one 500 ms retry inside the shared 10 s deadline. Keep production and development binding-only with persistent logs off. References: `apps/image-worker/src/admission.ts:18,21`; `apps/image-worker/src/worker.ts:4`; `apps/image-worker/src/index.ts:113,194`; `apps/image-worker/wrangler.toml:25,35,38,43,47`; `apps/discord-worker/src/services/image-client.ts:26,35,93`; `apps/discord-worker/src/services/image-client.test.ts:95,116,146`.
- The patched Photon build already reduces decode/resize ownership copies. The prior workerd checkpoint and retained build evidence leave aggregate resource acceptance unresolved. The tracked release plan also requires provider CPU-policy acceptance and deployed corrected Discord manual before activating lower caps. The workflow honors a hold variable; source does not establish its live value. References: `apps/image-worker/vendor/photon/README.md:3,7,15,89`; `apps/image-worker/CHANGELOG.md:18`; `docs/audits/2026-10-26-security/evidence/remediation-image-2026-10-28.md:16,110`; `docs/operations/REMEDIATION_RELEASE_2026_10.md:192`; `.github/workflows/deploy-image-worker.yml:34`.
- An additive palette route can coexist with raw `/extract` and `/thumbnail` for staged rollout/rollback. Replacing the binding wire format in place breaks coordinated deploys. A compatible internal kernel can retain the public synchronous core API and existing app versions’ compatibility; changing public `PaletteService` from sync to async or requiring new runtime capabilities is a core major candidate. References: `apps/image-worker/src/index.ts:136,194`; `packages/core/src/index.ts:34`; `packages/core/src/services/PaletteService.ts:416,554`.

## 2. Offload the browser palette path in TypeScript first

- The browser accepts image files capped at 20 MiB, reads a Data URL, decodes through `Image` and draws the visible canvas at image dimensions. Palette work yields one animation frame then synchronously reads the full canvas, grid-samples with a target of roughly 100,000 candidates with alpha filtering and clusters on the main thread (core samples down to 10,000). A 3840×2160 full RGBA readback is about 31.6 MiB before sample objects. References: `apps/web-app/src/shared/constants.ts:129`; `apps/web-app/src/components/extractor-tool.ts:1273,1316,2142,2163,2223`; `apps/web-app/src/components/image-zoom-controller.ts:114`; `packages/core/src/services/PaletteService.ts:360,504`.
- Benchmark a lazy module worker with transferred packed data and current TS sampling/clustering against the present flow. Compare a separate analysis canvas with worker decode/readback where supported; a worker started after full `getImageData` leaves that stall on the main thread. Preserve the visible canvas and loupe, browser decode/color/alpha behavior, in-memory image handling, fallback, count changes and stale-result rejection on replace, clear and teardown. Existing browser worker pattern transfers buffers and terminates superseded requests. Measure main-thread long tasks, first and repeated palette latency and memory on mobile/desktop. References: `apps/web-app/src/components/extractor-tool.ts:1270,1372,2207`; `apps/web-app/src/components/image-zoom-controller.ts:532,556`; `apps/web-app/src/services/chara-inspection-service.ts:8,291,309`; `apps/web-app/e2e/extractor-tool.spec.ts:76,129,180`; `apps/web-app/src/components/__tests__/extractor-tool.test.ts:996,1591,1617`.
- Compare Rust only if profiling leaves meaningful CPU in clustering. Include initialization, asset bytes, duplicate code/data and browser/CSP compatibility. Checked-in CSP uses `script-src 'self'` with no WASM compilation allowance. The bundle gate has a 100 KiB extractor limit and totals 2250/2800 KiB of JS; add a specific WASM budget if tested. A compatible worker is app-internal. References: `apps/web-app/public/_headers:31`; `apps/web-app/scripts/check-bundle-size.js:139,212,221,295`; `apps/web-app/vite.config.ts:55`.

## Keep the existing renderers and thumbnail path

- Photon already performs decode, resize, crop and WebP encoding in Rust/WASM. Presets supplies bytes to `/thumbnail`; it returns 640×264 WebP for R2, with stable status mapping. Replacing working Rust has little source-backed upside. Preserve ownership/ABI, source and license provenance, shape and format parity. The tracked smoke matrix omits dedicated ICC, EXIF, CMYK and animated-fixture parity. References: `apps/image-worker/src/photon-runtime.ts:1`; `apps/image-worker/src/photon.ts:61,277,288,299,311`; `apps/presets-api/src/services/preview-image-service.ts:153,160,173`; `apps/image-worker/src/photon.test.ts:408,479,533`; `apps/image-worker/vendor/photon/REBUILD.md:108,113`.
- Discord and OG rasterize using Rust resvg WASM already, then free both renderer and image. Discord renders at 2× with locale-aware bundled fonts. OG extractor accepts shared palette colors, generates SVG on a guarded cache miss and renders at 3×, with versioned canonical caching including GET/HEAD parity. A shared TypeScript adapter is a maintenance option if needed; moving to a rendering binding needs measured evidence that compressed bundle relief beats cold start and the additional call. Keep cache keys, privacy, font/locale order, dimensions, errors and PNG parity. Discord’s checked-in gzip limit is 3072 KiB. References: `apps/discord-worker/src/services/svg/renderer.ts:11,99,129,135,148`; `apps/og-worker/src/index.ts:270,421,508,1231,1273`; `apps/og-worker/src/services/renderer.ts:11,21,118,128`; `apps/og-worker/src/og-guards.test.ts:299,318,338`; `apps/discord-worker/src/services/font-load-order.test.ts:128,138,147`; `apps/discord-worker/scripts/check-bundle-size.mjs:20`.
- Keep `@xivdyetools/svg` as synchronous data-to-string templates and reusable glyphs. Existing consumer APIs, XML escaping, text-fit, font selection and render parity would make a blanket rewrite costly. Changing return types, exports or runtime requirements would be a major package contract change. References: `packages/svg/package.json:10,20`; `packages/svg/src/index.ts:122`; `packages/svg/src/base.ts:29,171`; `packages/svg/src/palette-grid.ts:135,164`; `packages/svg/src/svg-pipeline.integration.test.ts:314,343`.
