## WebAssembly compatibility

- Cloudflare Workers imports a statically bundled `.wasm` as a `WebAssembly.Module`. `WebAssembly.instantiate` accepts a precompiled module there. Dynamic compilation from fetched bytes and `instantiateStreaming` are unsuitable for this runtime. `workers-rs` can host an entire Worker, but its async handler and bindings still use the JS host's event loop and APIs. A leaf kernel can use those capabilities without replacing Hono or runtime bindings. [Cloudflare WebAssembly](https://developers.cloudflare.com/workers/runtime-apis/webassembly/) · [Wrangler bundling](https://developers.cloudflare.com/workers/wrangler/bundling/) · [Cloudflare Rust](https://developers.cloudflare.com/workers/languages/rust/)
- Current local precedents differ. `image-worker` imports the retained artifact and initializes exactly pinned Photon `/others` synchronously. The OG and Discord resvg wrappers statically import the binary and coalesce lazy first initialization, reset a failed initialization promise, and release both objects. These are loader and lifetime precedents. The historical Photon split restored headroom under the then-current compressed limit. The checkout still gates Discord at 3,072 KiB gzipped. The live Cloudflare docs inspected on 2026-11-06 list a 64 MiB uncompressed limit and a one-second startup limit, with no compressed cap. Keep the repo gate and capture uncompressed/gzip/startup separately. `apps/image-worker/src/photon-runtime.ts:1–7`; `apps/image-worker/CLAUDE.md:7–14,34–43`; `apps/og-worker/src/services/renderer.ts:11–15,24–62,128–129`; `apps/discord-worker/src/services/svg/renderer.ts:17,23–68,148–149`; `.github/workflows/deploy-discord-worker.yml:72–79`; `.github/workflows/ci.yml:276–282`. [Cloudflare Worker size and startup](https://developers.cloudflare.com/workers/platform/limits/#worker-size)
- Preserve existing ESM, JS functions, public types and subpaths. The exports maps use `types` and `import` without a `require` branch, and core declares Node `>=18.0.0` while root tooling requires `>=22.16.0` and CI builds under Node 22. Node and Stoat should use an explicit ESM loader or a tested ESM shim with sibling bytes. Browser should use a lazy Vite asset-backed loader with a resolved asset URL and a fallback when blocked by browser/CSP/availability. Wrangler should have its own static `CompiledWasm` import adapter. Keep the common entry free of host-specific imports and avoid requiring top-level await in existing synchronous imports. Validate the declared Node floor against the existing package as well as the pilot. Direct CommonJS is no current contract, and `wasm-bindgen --target nodejs` emits CommonJS, so it cannot replace the current ESM entry wholesale. `packages/core/package.json:6–24,90–91`; `packages/bot-logic/package.json:9–21,46–47`; `packages/auth/package.json:7–38`; `apps/web-app/package.json:51`; `apps/stoat-worker/package.json:40–41`; `package.json:35–38`; `.github/workflows/ci.yml:156–161`. [Node conditional exports](https://nodejs.org/api/packages.html#conditional-exports) · [wasm-bindgen targets](https://wasm-bindgen.github.io/wasm-bindgen/reference/deployment.html) · [Vite WebAssembly](https://vite.dev/guide/features.html#webassembly)
- Retain generated JS glue, generated TS declarations and Wasm together as one artifact set. The consumer-facing facade should own stable API types while adapter code binds a pinned ABI. Pin Rust target/toolchain, `Cargo.lock`, matching `wasm-bindgen` library/CLI, optimizer, build flags and provenance. A canonical CI build should reproduce digests and inventory and scan dependencies and licenses. Keep clean/pack/Turbo inputs and `dist/**` output coherent with artifact generation. Verify the exact packed files, including assets and fallback, from outside the workspace. The retained Photon tree is a local example of artifact hash, wrapper pin, ABI and retention-manifest checking. Its Windows-only reconstruction does not establish cross-platform or upstream byte identity. `apps/image-worker/vendor/photon/README.md:3–18,22–40`; `apps/image-worker/vendor/photon/provenance.json:11–55`; `turbo.json:55–58`; `packages/core/package.json:23–29,45`. - The technology change alone does not decide SemVer. An internal equivalent backend or performance fix is PATCH where the existing exports, synchronous behavior, accepted inputs, result ordering and runtimes are preserved. A new opt-in backend, subpath or initialization feature is MINOR. A required init call, sync-to-async change, narrower Node/browser/Workers support, altered wire/data/error contract, incompatible output, removed export or renamed subpath is MAJOR. For illustration only, using core 5.16.0 as a published baseline would give 5.16.1 for a transparent fix and 5.17.0 for an additive opt-in. Reserve its existing 6.0.0 work. An API 0.x service still has clients and compatibility routes. Treat an incompatible response as an explicit API migration with versioned routes, and apply local release policy separately. Compare the manifest against **exact** registry metadata and dist-tags before assigning a bump. If a pending version already reflects the change's highest required increment, update its pending entry instead of double-bumping. Keep code, version tables, package changelogs, and required consumer changelogs in agreement. `docs/developer-guides/release-process.md:164–180,194–208`; `.agents/skills/audit-shared/release-mechanics.md:8–16`; `apps/api-worker/CLAUDE.md:216,238`.
