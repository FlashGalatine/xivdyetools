## Method

1. **Delta.** `git diff --name-only <audit sha> origin/main`:
   - `1e842b20` for dead-code;
   - `80262a2f` for deep-dive and i18n.
   - The outputs are in `reverify-2026-10-05/changed-*.txt`.
   - The commits behind it are the in-PR Sprint 0 fixes, the old-domain route removals, #239 (the sheet-name table) and #240 (core 5.8.1).
2. **Scope.** `reverify-2026-10-05/scope.py` maps every finding to the files it cites (Location first, then the whole body) and intersects that with the delta. The output is `scope.json`.
   - 42 findings cite a changed file in their Location, and 19 more in their body.
   - **Narrowing the locale files.** Each web-app locale changed one line in place: `:1033`, `preset.privacyNote`. No finding cites that line, so the 17 findings that only touch locale files were cleared by a line check.
   - **Narrowing the other files.** The README and `docs/versions.md` hits are version rows. A per-finding check that the cited lines are disjoint from the changed hunks cleared those too.
   - **Reverse scan.** Every changed file was matched to any finding naming its basename, outside fonts, changelogs and version rows. That covers cross-unit citations such as core `ko.json`/`zh.json`, and basenames the forward map dropped as ambiguous. Each cited line was checked against both the hunks and the cumulative line shift. No line cited by the remaining findings was edited or shifted.
3. **Verify.** The 32 findings that remained got one read-only verifier each (`reverify-2026-10-05/workflow.js`). They covered:
   - every Sprint 0 row;
   - the policy documents;
   - the moderation-worker strings file;
   - the discord-worker notification builder;
   - the api-worker and presets-api `wrangler.toml` files;
   - core's `build-locales.ts`;
   - the findings that depend on #239 or #240.
4. **Challenge.** Each FIXED, PARTIALLY_FIXED or INVALID verdict got two skeptics with different lenses: completeness across every variant and claim, and attribution of the fixing commit. All 12 such verdicts survived both, so none is disputed. Raw returns: `reverify-2026-10-05/reverify-result.json`.
5. **Notes.** One agent checked the plan's unnumbered notes. Another checked the seven *Pin first* rows against #239's dictionary table.
6. **Baseline.** The whole-graph gate and the root gates were run on `main` (below).

## Execution notes

**Nothing merges between sprints** (one PR per sprint; the batch is reviewed together). So same-unit sprints would collide on versions, changelogs and, in web-app, the same files.

**Adopted: stack within a unit chain.** Each sprint's branch starts from the previous sprint's branch in that chain, and every PR targets `main`.
- **Cross-chain sprints** (7, 13's font re-cut, 26) touch several chains, so they branch from `main`. They still take their pre-assigned numbers from the table. Expect conflicts in the version rows, `docs/versions.md` and the changelogs when they merge; merge `main` into the PR after the earlier sprints land.
- **Package numbers assume a publish between a chain's two sprints:** core 5.9.0 → 5.10.0, svg 4.3.1 → 4.4.0, bot-logic 4.6.0 → 4.7.0. If the second merges before the first is published, `release-mechanics.md`'s fold rule applies instead: fold the change into the unpublished version, with no extra bump.
