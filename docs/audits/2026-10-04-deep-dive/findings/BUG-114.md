# BUG-114: main.ts:126 non-critical tutorial-spotlight import failure triggers renderFatalError over the already-rendered shell
**Severity:** LOW · **Type:** Error handling · **Deploy unit:** apps/web-app · **Covered by test?** no · **Origin:** MAIN

## Location
- `apps/web-app/src/main.ts:126`

## Evidence
- Reproduction: First page load: v4-layout chunk loads and shell renders, then the separate tutorial-spotlight chunk fetch fails (transient network error or deploy flip mid-load) -> whole app replaced by 'Application Error' though every tool works
- tutorial-spotlight is imported only dynamically by main.ts (own 9 KB chunk per bundle report), inside the same try as critical init; a rejection reaches catch -> renderFatalError -> container.replaceChildren (fatal-error.ts:71) wiping the working v4 shell. The originally suggested 'stale tab' repro is wrong (init runs once per load), but the first-load trigger is real. Not in 2026-09-16 Rejected suspicions.
- Second, independent check (severity LOW): The defect is real but I'd grade it LOW, not MEDIUM. In apps/web-app/src/main.ts:126, `await import('@components/tutorial-spotlight')` sits inside the same try block as critical init. tutorial-spotlight is imported only there, and it ships as its own 8.99 kB chunk (bundle-web-app.txt:37). If that import rejects, the catch at :151 calls renderFatalError, and container.replaceChildren (shared/fatal-error.ts:71) replaces the v4 shell that was already mounted. No test covers this: there is no main.test and no test references the spotlight.

Three things push the severity down:
1. The trigger is a fetch failure inside one request window during boot. It comes after the v4-layout chunk and the initial tool chunk have both loaded; initializeV4Layout awaits loadToolContent at v4-layout.ts:465.
2. It happens milliseconds after mount, before the user can have built any state. So the visible result is "boot failed, Reload" with a working Reload button, which is the same as the by-design fatal path for a v4-layout chunk failure one request earlier.
3. In the deploy-flip case, the page is stale anyway, so a reload is the right fix.

The result is a recoverable startup failure on a very rare transient, which fits "latent" better than "wrong result on an edge path". The fix direction stands: give the spotlight import its own try/catch, as loadToolContent (v4-layout.ts:727-747) and changelog-modal.ts:126-132 (earlier-audit BUG-090) already do for their chunks.
- Origin: git show 8ecb878f:apps/web-app/src/main.ts lines 124-127 and 151-170 identical

## Fix
- Wrap the tutorial-spotlight import/init in its own try/catch that logs and continues; keep the fatal overlay for services, language and layout init only. No published package change.
