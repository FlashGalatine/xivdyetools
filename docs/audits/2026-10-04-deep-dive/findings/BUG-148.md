# BUG-148: test-utils KV/R2 mock list(): cursor resume never ends when the cursor's key was deleted; insertion order instead of lexicographic
**Severity:** LOW · **Type:** Edge case · **Deploy unit:** packages/test-utils · **Covered by test?** no · **Origin:** MAIN · **Other units:** same pattern in packages/test-utils/src/cloudflare/r2.ts:241

## Location
- `packages/test-utils/src/cloudflare/kv.ts:233`

## Evidence
- Reproduction: Put 1500 keys, list page 1 (1000 keys + cursor), delete those 1000, list({cursor}) -> mock returns keys:[] list_complete:true, while real KV returns the remaining 500
- Cited lines are wrong (kv.ts has 291 lines), but the logic is real at kv.ts:219-234 and r2.ts:233-242: resume skips until key === resumeAfter. If that key was deleted (or expired, for KV) between pages, skipping never clears and the call returns empty and complete. Map insertion order is not real KV/R2 lexicographic order. Mock-fidelity only.
  - Checked: packages/test-utils/src/cloudflare/kv.ts:219-234 (resume check runs after the expired-key skip); r2.ts:233-242
- Origin: git show 8ecb878f:packages/test-utils/src/cloudflare/kv.ts:233 and r2.ts:241 both contain 'if (key === resumeAfter) skipping = false;'

## Fix
- Sort the matching keys and resume with key > lastKey, so a deleted or expired cursor key no longer stalls the listing.
test-utils is workspace-private: no publish and no deploy.
