# BUG-151: worker-kit KVRateLimiter.reset/resetAll read a single kv.list page (no cursor loop)
**Severity:** LOW · **Type:** Edge case · **Deploy unit:** packages/worker-kit · **Covered by test?** no · **Origin:** MAIN · **Other units:** api-worker, discord-worker and moderation-worker construct KVRateLimiter but never call reset/resetAll

## Location
- `packages/worker-kit/src/rate-limiter/backends/kv.ts:281`

## Evidence
- Reproduction: More than 1000 live 'api:ip:' keys -> resetAll() resolves and every key past the first page keeps counting
- kv.ts:273 and :281 (not :191) call kv.list once and delete only that page, so real KV's 1000-key page cap leaves the rest. Latent: no app calls reset() or resetAll() (git grep apps/*/src). reset(key) covers one client's window keys, so in practice only resetAll is exposed.
  - Checked: packages/worker-kit/src/rate-limiter/backends/kv.ts:270-283; git grep -nE '\b(resetAll|\.reset)\(' -- 'apps/*/src' finds no non-test caller
- Origin: git show 8ecb878f:packages/worker-kit/src/rate-limiter/backends/kv.ts:273,281 have the identical single kv.list call

## Fix
- Loop on list_complete/cursor in both reset() and resetAll().
Needs a @xivdyetools/worker-kit publish; consumer deploys are optional, since none calls these methods.
