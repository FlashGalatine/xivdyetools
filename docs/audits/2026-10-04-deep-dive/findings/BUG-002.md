# BUG-002: budget.ts/preferences.ts: validateWorld cold-cache service calls are awaited inside the 3 s ack window
**Severity:** MEDIUM · **Type:** Resource · **Deploy unit:** apps/discord-worker · **Covered by test?** no · **Origin:** MAIN · **Other units:** N/A

## Location
- `apps/discord-worker/src/handlers/commands/budget.ts:215`

## Evidence
- Reproduction: Cold discord-worker isolate plus an api-worker cache miss with slow Universalis: /budget find world:<DC name> exceeds 3 s and Discord shows 'The application did not respond'.
- Four handlers await validateWorld before answering Discord: budget.ts:215 (find) and :504 (quick) before deferredResponse, plus budget.ts:450 (set_world) and preferences.ts:342, both fully synchronous with no defer. On a cold isolate validateWorld (universalis-client.ts:356-372) makes up to 2 sequential service-binding fetches with a 10 s timeout each (:79, :115). This is the same defect as earlier-audit BUG-008, which was rated MEDIUM. Exposure is narrowed by api-worker's per-colo Cache API (24 h TTL + 6 h SWR): it takes a full cache miss plus a slow Universalis.
- Second, independent check (severity MEDIUM): I could not refute this, and I agree with MEDIUM. I re-derived it from the code. budget.ts:215 and :504 await resolveWorld before deferredResponse() at :236 and :520. budget.ts:450 and preferences.ts:342 await validateWorld and only then send a synchronous reply. Nothing at dispatch level races the handler or auto-defers it: the only Promise.race in discord-worker src is command-trace's drain deadline. earlier-audit BUG-008 (MEDIUM, fixed in 21ae7d5b) has the same mechanism: the same getCachedWorlds and getCachedDataCenters calls, behind the same api-worker cache. The api-worker 24 h + 6 h SWR cache narrows exposure equally in both cases, so it is no reason to downgrade.
- Origin: git show 8ecb878f:apps/discord-worker/src/handlers/commands/budget.ts has await resolveWorld at :215/:504, before deferredResponse() at :236/:520.

## Fix
- Defer first and run validateWorld inside ctx.waitUntil, for find/quick and also set_world and /preferences set (ephemeral defer). Or race the lookup against a ~2 s budget and degrade. No package publish.
