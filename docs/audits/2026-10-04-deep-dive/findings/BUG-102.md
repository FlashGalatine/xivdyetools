# BUG-102: preset-submission-form.ts: dismissTop() after awaited submit/upload can close the wrong modal; unguarded sessionStorage write inside the submit try
**Severity:** LOW · **Type:** Race · **Deploy unit:** apps/web-app · **Covered by test?** no · **Origin:** MAIN

## Location
- `apps/web-app/src/components/preset-submission-form.ts:758`

## Evidence
- Reproduction: Submit with image -> Esc closes the form during upload -> open another modal -> upload resolves -> dismissTop closes that modal; or storage blocked -> duplicate path shows info toast then submitPresetFailed
- dismissTop() at :725/:758 runs after await submitPreset (and after await uploadPreviewImage), while showPresetSubmissionForm drops the ModalService.show id (:104). If the user closes the closable form and opens another modal during the request, that other modal gets closed. Separately, sessionStorage.setItem (:730) inside the try turns a blocked-storage throw into submitPresetFailed after the duplicate toast. Both need user or browser conditions, hence LOW.
  - Checked: preset-submission-form.ts:104-111,712-779; modal-service.ts:143-144 (closeOnEscape/backdrop default true), :220-224
- Origin: git grep 8ecb878f: preset-submission-form.ts:730 sessionStorage.setItem; file unchanged to HEAD

## Fix
- Capture the id returned by ModalService.show and call dismiss(id), as earlier-audit BUG-088 does in my-submissions-modal; wrap the sessionStorage write in its own try/catch.
