## Evidence
- Reproduction: localStorage v4_mixer_selected_dyes=[a,b,c] from a three-slot build -> open Mixer or a mixer share link -> equal 3-way blend shown, ratio ignored, field hidden.
- loadSelectedDyes restores slot 2 (:222) and blends every non-null slot, so blendColorsInternal takes the equal-weight blendColors path, ignores mixRatio, and the field is suppressed (:1164). loadFromShareUrl (:676-717) overwrites only slots 0 and 1, so a recipient's stale slot 2 turns a shared pair into a 3-way blend that ignores ratio. No storage migration trims the key; only pre-42f0579f (2026-08-08) storage has the slot. It clears on the first selector pick (:1038) or selectDye (:803).
  - Checked: mixer-tool.ts:213-229,250-259,676-717,1164; git grep v4_mixer_selected_dyes finds no migration
- Origin: git show 8ecb878f:mixer-tool.ts:222 `savedDyeIds[2] ? (dyeService.getDyeById(savedDyeIds[2]) ?? null) : null`; slot cut in 42f0579f

## Fix
- Force selectedDyes[2]=null in loadSelectedDyes, and re-save when a stored slot 3 was dropped.
