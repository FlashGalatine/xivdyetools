# BUG-082: chara-sheet.ts saveCharacterColors: ?? lets an empty or whitespace Nickname beat the file-name/default fallback, so the save always fails
**Severity:** LOW · **Type:** Edge case · **Deploy unit:** apps/web-app · **Covered by test?** no · **Origin:** MAIN · **Other units:** packages/core (only if fixed in the parser)

## Location
- `apps/web-app/src/components/chara-sheet.ts:162`

## Evidence
- Reproduction: .chara with "Nickname": "" or "   ", click Save character colors: name trims to empty, createCollection returns null, 'save failed' toast (the file card title at chara-file-card.ts:295 is also blank)
- `resolved.nickname ?? ...` (chara-sheet.ts:163) keeps '' or '   ', because the parser keeps any string (chara-parser.ts:487). The name then trims to empty and createCollection rejects it (collection-service.ts:627-630), so the save always fails. glamour-block.ts:1719 uses ||. No real Ktisis/Anamnesis output in the 1,142-file corpus has an empty Nickname, so it is latent.
  - Checked: chara-sheet.ts:162-165; packages/core/src/services/chara/chara-parser.ts:487; collection-service.ts:626-630
- Origin: git show 8ecb878f:apps/web-app/src/components/chara-sheet.ts:163 already reads `resolved.nickname ??`; parser line unchanged since 8ecb878f

## Fix
- Use `nickname?.trim() || fileName || default` at chara-sheet.ts:163 and chara-file-card.ts:295 (app-only fix). Normalising in the parser instead would need a core publish, then consumer deploys.
