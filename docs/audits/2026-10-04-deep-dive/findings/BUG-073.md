# BUG-073: stoat dye-resolver.ts resolveDyeInputMulti: step 1 resolveColorInput first-match makes multiple/disambiguation unreachable for name queries
**Severity:** LOW · **Type:** Logic · **Deploy unit:** apps/stoat-worker · **Covered by test?** no · **Origin:** MAIN · **Other units:** none (the bot-logic behaviour is the documented contract; the fix lives in stoat)

## Location
- `apps/stoat-worker/src/services/dye-resolver.ts:54`

## Evidence
- Reproduction: !xd info white -> 4 dyes contain 'white' -> bot replies with Snow White only, no list (temp repro run, then deleted)
- resolveColorInput's name step is a substring search (searchByName includes) that returns candidates[0], so dye-resolver.ts:54-56 answers 'single' for every name substring. Repro: 'white' gives single Snow White (4 hits), 'Red' gives Rolanberry Red (11 hits); 'multiple'/'disambiguation' only happen for category-only queries ('neutral').
  - Checked: packages/bot-logic/src/input-resolution.ts:241-257 (searchDyesByName -> candidates[0]); packages/core/src/services/dye/DyeSearch.ts:82-94 (includes); temp __repro__ output: white|single|4, Blue|single|25, Red|single|11, neutral|disambiguation; LOW: stoat is parked with no deploy (docs/versions.md:555); 2026-09-16 graded stoat earlier-audit BUG-031/042 LOW
- Origin: git show 8ecb878f:apps/stoat-worker/src/services/dye-resolver.ts:54-57 identical; git diff --stat 8ecb878f HEAD -- apps/stoat-worker/src touches only response-formatter (#234)

## Fix
- Step 1 resolves exact matches only: bot-logic findDyeByName (covers bare ids) + isValidHex/closest-dye, then the substring step, then CSS-name fallback. App-only, no publish.
This makes 'multiple' live, which brings back the up-to-4-message fan-out (FINDING-035); the throttle bounds it.
