**Severity:** LOW · **Type:** Edge case · **Deploy unit:** root (CI/scripts) · **Covered by test?** no · **Origin:** MAIN · **Other units:** all 8 deploy-*.yml production workflows

## Location
- `.github/workflows/deploy-oauth.yml:6`

## Evidence
- Reproduction: Merge a pnpm-workspace.yaml override bump of a bundled runtime transitive (e.g. hono dep) -> no deploy workflow triggers -> workers keep the old bundle
- grep finds none of the root files in any deploy-*.yml; all 8 production deploys (api, discord, image, moderation, oauth, og, presets-api, web-app Pages; claim said 7) are affected, so an overrides/lockfile-only runtime fix never redeploys. LOW: workflow_dispatch is the manual escape.
  - Checked: grep -n 'pnpm-lock|pnpm-workspace|turbo.json|tsconfig.base' .github/workflows/deploy-*.yml -> no hits; deploy-oauth.yml:6-12; docs/developer-guides/deployment.md 'Path filters are load-bearing'
- Origin: git grep -c pnpm-lock 8ecb878f -- .github/workflows/ -> only ci.yml; deploy filters unchanged in 8ecb878f..HEAD (only 3a158847 touched .github, ci.yml)

## Fix
- Add pnpm-lock.yaml and pnpm-workspace.yaml (optionally turbo.json, tsconfig.base.json) to each production deploy's paths, or add a drift check. No package publish.
