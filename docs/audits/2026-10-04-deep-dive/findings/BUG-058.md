# BUG-058: index.ts ogCacheKey keys algo and mode on every /og route although only 5 routes read algo and 2 read mode, contradicting its own docblock
**Severity:** LOW · **Type:** Edge case · **Deploy unit:** apps/og-worker · **Covered by test?** no · **Origin:** MAIN

## Location
- `apps/og-worker/src/index.ts:347`

## Evidence
- Reproduction: /og/budget/5.png?algo=oklab and ?algo=rgb and ?mode=lab each get a distinct cache key, so each is a full resvg render of a byte-identical card
- Real but bounded: the guard caps it at about 10 algo x mode states per path. Ruling S7-R7 accepted that bound before earlier-audit BUG-018 set the stricter rule now stated in the docblock. Operational waste only.
  - Checked: index.ts:347-358 sets algo/mode unconditionally, while wheel is gated by readsWheel at :375; algo is read only at :810/861/906/953/998 and mode only at :934/982; docblock :203-205 and CLAUDE.md say a key must not multiply a card that ignores it
- Origin: git show 8ecb878f:apps/og-worker/src/index.ts:349/357 has unconditional params.set('algo'/'mode')

## Fix
- Add readsAlgo(path) (harmony param route, gradient, mixer, swatch) and readsMode(path) (/og/mixer/*), and key only there, like readsWheel. Extend og-guards.test.ts to assert a budget path ignores algo and mode.
