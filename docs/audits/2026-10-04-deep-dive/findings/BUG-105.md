# BUG-105: toast-container.ts: full rebuild on each change replays animations and re-announces alerts; Escape closes toast and modal together
**Severity:** LOW · **Type:** Logic · **Deploy unit:** apps/web-app · **Covered by test?** no · **Origin:** MAIN

## Location
- `apps/web-app/src/components/toast-container.ts:168`

## Evidence
- Reproduction: Error toast visible, a second toast arrives -> the first slides in again and the screen reader re-announces it; Esc with a modal open and a toast showing -> both close
- Every ToastService notify calls update(), and renderContent clears and rebuilds every toast (:169,193-203). Survivors get toast-animate-in again (0.3s slide) and fresh role=alert/aria-live nodes, so they re-animate and are re-announced. Escape is handled on document by both the toast (:71-77) and the modal (modal-container.ts:202-208), and neither stops the other.
  - Checked: toast-container.ts:49-54,168-206,71-77; modal-container.ts:202-208; globals.css:243-245
- Origin: file unchanged 8ecb878f..HEAD

## Fix
- Keep a Map<id, HTMLElement> and add or remove only the toasts that changed; let one Escape keypress close only one layer.
