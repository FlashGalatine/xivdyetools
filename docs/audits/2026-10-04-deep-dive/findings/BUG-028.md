# BUG-028: dye-palette-drawer.ts renderSwatch: swatch is a click-only div, so keyboard users cannot pick a dye from the app-wide picker
**Severity:** MEDIUM · **Type:** Logic · **Deploy unit:** apps/web-app · **Covered by test?** no · **Origin:** MAIN · **Other units:** none
**Supersedes:** 2026-09-02-deep-dive/BUG-066 (scheduled in that plan, never fixed)

## Location
- `apps/web-app/src/components/v4/dye-palette-drawer.ts:1194`

## Evidence
- Reproduction: Tab through the open drawer: every swatch is skipped. Only invisible star buttons take focus.
- The .swatch div (1194-1199) has @click only: no role, no tabindex, no keydown. A grep for keydown|tabindex|role= in the file finds none. The star is opacity:0 and visible only under .swatch:hover (492, 505-508), with no focus or hover:none rule. The Custom colour (1125) and Favourites (1238) headers are click-only divs. The custom-hex box picks a colour, not a dye.
  - Checked: dye-palette-drawer.ts:1194-1199, 1125, 1238; CSS 492, 505-508; grep keydown/tabindex/role= -> none
- Second, independent check (severity MEDIUM): I could not refute it. dye-palette-drawer.ts:1194-1199 renders each swatch as a `<div class="swatch" @click=...>` with no role, no tabindex and no keydown handler. The file contains no keydown or tabindex anywhere. Its only keyboard-reachable controls are the search input (`@input` only, so Enter selects nothing), the filter and spectrum chips, the Random, Clear and Close buttons, the custom-hex Apply button, and each swatch's nested star `<button>`. That star is `opacity:0` and becomes visible only under `.swatch:hover` (CSS lines 492 and 505-508). It has no :focus or :focus-within rule, and the exceptions are already-favourited dyes and the Favourites section. The Custom colour header (1125) and the Favourites header (1238) are click-only divs.

I also looked for a keyboard fallback and found none in v4. harmony, comparison, gradient, mixer and accessibility each build a keyboard-capable DyeSelector/DyeGrid (dye-grid.ts:265 has a keydown handler) inside renderLeftPanel(). However, v4-layout.ts:601-602 passes the same mainPanel as both leftPanel and rightPanel, and renderRightPanel() calls clearContainer(right) first (harmony-tool.ts:1050, comparison-tool.ts:844). The in-tool selector is therefore wiped straight away. The drawer is the only picker left, and it feeds tools through v4-layout.ts:197-215.

A keyboard-only user can star a dye or pick a random one, but cannot choose a specific dye. Only the Random button and the custom-hex Apply produce a pick from the keyboard. This is a complete block for one group of users on a core path, so it is more than cosmetic. MEDIUM matches the brief's scale and the earlier grading.

Carried over: this is the same defect as 2026-09-02-deep-dive/BUG-066 (same file:line, same claim). That remediation plan scheduled it (REMEDIATION_PLAN.md:300), but it was never fixed. The last commits to the file do not touch swatch semantics, and nothing in git log references the web-app earlier-audit BUG-066. Origin MAIN is correct.
- Origin: git diff --stat 8ecb878f HEAD -- apps/web-app/src/components/v4/ empty

## Fix
- Render each swatch as a <button> (or role=button, tabindex=0, Enter/Space). Show the star on :focus-within and under @media (hover:none), and make both section headers buttons. Web-app deploy only.
