# BUG-076: No tool test invokes the LanguageService.subscribe callback, so the language-switch rebuild that empties four tools (see the MEDIUM finding) is untested
**Severity:** LOW · **Type:** Untested behavior · **Deploy unit:** apps/web-app · **Covered by test?** no · **Origin:** MAIN · **Other units:** none

## Location
- `apps/web-app/src/components/__tests__/harmony-tool.test.ts:127`
- `apps/web-app/src/components/__tests__/accessibility-tool.test.ts:438` — accessibility-tool.test.ts: typeof/not.toThrow tests leave the language rebuild (update keeps results) and the checkbox lens reconcile unpinned

## Evidence
- Reproduction: Select a dye in Harmony (or mix two in Mixer, or pick 3 in Comparison), then fire the language subscriber. The results grid empties or hides, and no test fails.
- All four tool tests mock LanguageService.subscribe as vi.fn().mockReturnValue(() => {}) (harmony :127, mixer :130, budget :164, comparison :106), and none ever calls the captured callback. Only extractor-tool.test.ts:818 does. So the update() path at harmony-tool.ts:313, mixer-tool.ts:608, budget-tool.ts:267 and comparison-tool.ts:229 never runs in a test, and the BUG-021 blanking bugs go uncaught.
  - Checked: grep 'LanguageService.subscribe).mock' apps/web-app/src -> only extractor-tool.test.ts:818/1609/1920; harmony-tool.ts:313-315 calls this.update() with no onUpdate regenerate
- Second, independent check (severity LOW): The coverage gap is real: none of the four tool tests ever invokes the captured LanguageService.subscribe callback. MEDIUM is too high, though. This is a meta-finding that repeats the "Covered: no" line of the language-switch defect already filed as BUG-021 (which covers all four tools). Each of those already prescribes the fix, and the regression test for it closes this gap, so the risk is defended elsewhere. The budget part is also overreach: budget's update() rebuilds its results from targetDye, so budget has no blanking bug for this test to catch.
- Reproduction: Delete updateResults() after a rebuild, or drop activeVision reconcile in the checkbox handler -> accessibility-tool.test.ts stays green
- accessibility-tool.test.ts:438-445 and :459-478 assert only typeof==='function', and :445-451, :480-496 and :533-548 assert only not.toThrow. The file never calls update(), never changes language and never toggles the in-tool vision checkbox. e2e/accessibility-checker.spec.ts only checks that a switch flips its checked state. Results-survive-update and active-lens reconcile are pinned nowhere.
  - Checked: accessibility-tool.test.ts:438-496, :533-548; grep for .update()/language/checkbox/activeVision in the file finds nothing; e2e spec :87-146, :253-286
- Origin: git diff --stat 8ecb878f HEAD -- apps/web-app/src/components/__tests__ touches only chara-file-card/glamour-tool tests; the subscribe mocks are unchanged since main

## Fix
- For each tool, select dyes, then invoke every vi.mocked(LanguageService.subscribe).mock.calls[i][0] and flush. Assert the result cards/grid are present and visible. Follow the pattern at extractor-tool.test.ts:810-821.
- Add a test where 2 dyes are selected, update() is called and the result sections are asserted visible; and one where the active lens's checkbox is unchecked and activeVision is asserted to move to a visible lens.
