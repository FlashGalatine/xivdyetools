# OPT-006: renderer.ts renderSvgToPng never .free()s Resvg or RenderedImage, leaving each render's wasm allocations to FinalizationRegistry timing
**Impact:** LOW · **Category:** Memory · **Deploy unit:** apps/og-worker · **Expected gain:** Deterministic release of about 6 MB of wasm memory per render (1200x1050 RGBA pixmap plus font copies and tree), instead of release on GC finalisation · **Benchmark:** None measured. Suggest a local loop of N cache-miss renders comparing wasm memory.buffer.byteLength with and without free()

## Location
- `apps/og-worker/src/services/renderer.ts:87`

## Evidence
- Reproduction: A sustained cache-miss burst on one isolate holds about 5 MB of pixmap per render, plus about 1.3 MB of font buffers and the parsed tree, until GC finalises the tiny JS wrappers
- The missing free() is factual and the fix is two lines. The memory-pressure impact is unmeasured: no OOM has been observed and finalisation does eventually run. Hence OPT with LOW impact, not a BUG.
  - Checked: @resvg/resvg-wasm/index.js:214-233 and :279-291 free only through FinalizationRegistry or an explicit free(); image-worker frees every PhotonImage in finally (CHANGELOG 'WASM memory hygiene')
- Origin: git show 8ecb878f:apps/og-worker/src/services/renderer.ts:87-102 has new Resvg / render() / asPng() and no free()

## Fix
- Hold resvg/rendered outside the try and call rendered?.free(); resvg?.free() in a finally after asPng() has copied the bytes out. Add a test asserting free() is called on success and on error.
