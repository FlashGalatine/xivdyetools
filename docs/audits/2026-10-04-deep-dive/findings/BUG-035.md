# BUG-035: blending.ts blendHSL interpolates the hue of an achromatic input, which is meaningless (always 0), so grey/white/black mixes get a hue neither input has
**Severity:** MEDIUM · **Type:** Logic · **Deploy unit:** packages/core · **Covered by test?** no · **Origin:** MAIN · **Other units:** apps/web-app (mixer hsl), packages/bot-logic (mixer/gradient hsl) -> apps/discord-worker, apps/og-worker mixer card

## Location
- `packages/core/src/blending/blending.ts:187`

## Evidence
- Reproduction: blendColors('#FFFFFF','#0000FF','hsl',0.5).hex === '#df9fdf' (also ColorService.mixColorsHsl -> '#DF9FDF')
- rgbToHsl returns h:0 for any grey (conversions.ts:240-242), and blendHSL interpolates it as a real hue. Measured: white+blue at 0.5 in hsl mode gives #DF9FDF (pink), not light blue; black+green gives #606020 (olive, hue 60). Reachable in the web mixer, bot /mixer and /gradient hsl modes.
  - Checked: temp repro (deleted) printed R01 #df9fdf #606020 #DF9FDF; ColorService.test.ts:432 only asserts s===0 for grey; conversions.equivalence.test.ts:276 pins the current #644216+#000000 output and will need updating
- Second, independent check (severity MEDIUM): I could not refute it, and MEDIUM is the right severity. In HSL mode, mixing an exactly grey colour gives a colour with a hue neither input has. rgbToHsl returns h:0 for any grey (packages/core/src/blending/conversions.ts:240-242), and blendHSL at packages/core/src/blending/blending.ts:187 blends that 0 as if it were a real hue. Nothing on the path special-cases grey: the web mixer, ColorService.mixColorsHsl, and bot-logic gradient.ts:210 (hsl calls blendColors) all reach blendHSL unchanged. The 'hsl' choice is offered in apps/discord-worker/src/commands/schemas.ts:415 (/gradient), :465 (/mixer) and :646 (the /mixer default setting). Three real dyes are exactly grey (Slate Grey #656565, Jet Black #1e1e1e, Metallic Silver #a7a7a7), and the bot and web tools also accept raw hex such as #FFFFFF. It is not HIGH because HSL is not the default mode and the input must be exactly grey; that is a wrong result on an edge path, which the brief calls MEDIUM. It is not LOW because nothing else blocks it and the result is visibly wrong.
- Origin: git show 8ecb878f:packages/core/src/blending/blending.ts:187 has the same interpolateHue(hsl1.h, hsl2.h, ...); no core commits in 8ecb878f..HEAD

## Fix
- In blendHSL, if one side has s===0 use the other side's hue (CSS Color 4 powerless hue); both grey keep 0. Update the conversions.equivalence.test.ts:276 golden. Needs a @xivdyetools/core publish, then consumer deploys (web-app, discord-worker via bot-logic, og-worker).
