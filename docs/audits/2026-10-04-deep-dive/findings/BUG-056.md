# BUG-056: POST /auth/callback and /auth/xivauth/callback destructure a null JSON body outside the parse try, giving a 500 instead of a 400
**Severity:** LOW · **Type:** Error handling · **Deploy unit:** apps/oauth · **Covered by test?** no · **Origin:** MAIN · **Other units:** none

## Location
- `apps/oauth/src/handlers/callback.ts:64`
- `apps/oauth/src/handlers/callback.ts:64` — oauth callback/xivauth destructure a JSON null body (500), and the xivauth roster guard dereferences null elements and accepts an empty name

## Evidence
- Reproduction: POST /auth/callback, Content-Type application/json, body `null` -> 500 Internal Server Error (expected 400 Invalid request body); the same on /auth/xivauth/callback
- c.req.json() on body `null` succeeds and returns null, and jsonDepthLimit's validateStructure(null) returns ok. `const { code, ... } = body` (callback.ts:64, xivauth.ts:95) then throws, and app.onError returns 500. Reproduced: both endpoints returned 500 'Cannot destructure property code of body as it is null'. Error shape only, no data impact.
  - Checked: callback.ts:51-64, xivauth.ts:84-95, worker-kit body-guards/structure.ts:40 (null returns ok); temp repro (deleted) showed 500 on both endpoints
- Found independently from another slice: Both halves verified. The body half is a wrong status code, and the roster half needs malformed upstream XIVAuth data, so LOW.
- Origin: git show 8ecb878f: callback.ts:64 and xivauth.ts:95 have the same top-level destructure; no commits since 8ecb878f touch either file

## Fix
- After parsing, return 400 'Invalid request body' when typeof body !== 'object' or body === null (both handlers). Add a test with body 'null'. App-only change.
