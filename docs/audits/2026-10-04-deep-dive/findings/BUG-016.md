# BUG-016: chara-sheet.ts saveCharacterColors: a duplicate record name fails with a generic 'save failed' toast and has no suffix fallback
**Severity:** MEDIUM · **Type:** Edge case · **Deploy unit:** apps/web-app · **Covered by test?** no · **Origin:** MAIN · **Other units:** none

## Location
- `apps/web-app/src/components/chara-sheet.ts:166`

## Evidence
- Reproduction: Glamour Reader 'Save to this device' with an empty name field (record named after the nickname), then Swatch 'Save character colors' on the same file: createCollection returns null and the 'save failed' toast shows
- chara-sheet.ts:162-170 calls createCollection with no unique-name loop. createCollection returns null on a case-insensitive duplicate (collection-service.ts:633-636), so a second save, or a palette already saved under the same nickname/file name, shows errors.saveChangesFailed and saves nothing. glamour-block.ts:1731-1738 has the suffix loop.
  - Checked: chara-sheet.ts:162-170; collection-service.ts:632-642 (duplicate and MAX_COLLECTIONS both return null); glamour-block.ts:1729-1743 suffix loop
- Second, independent check (severity MEDIUM): I could not refute it. saveCharacterColors (chara-sheet.ts:162-170) passes the nickname, else the file name, straight to createCollection. There is no uniqueness loop. createCollection returns null on a case-insensitive name match (collection-service.ts:632-636), so the user sees the generic errors.saveChangesFailed toast and nothing is saved. No guard blocks the second click: the file-card button (chara-file-card.ts:354) never disables, and the open PRs add no guard. The only test saves once into an empty store. A plain second click on "Save character colors", or a second .chara file with the same nickname, is enough to hit it. I keep MEDIUM: on an edge path nothing is saved and the error message is misleading, but no existing data is lost.
- Origin: git show 8ecb878f:apps/web-app/src/components/chara-sheet.ts has the same createCollection(name, ...) at :166; git diff 8ecb878f HEAD does not touch chara-sheet.ts or collection-service.ts

## Fix
- Move the saveLocalPalette suffix loop into a shared uniqueCollectionName helper and call it from both save paths. Use a separate toast for the collection cap.
