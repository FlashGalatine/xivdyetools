# BUG-104: swatch-tool.ts updateHandoffRow: SEND TO does a full reload with window.location.assign, so the in-memory .chara session is dropped
**Severity:** LOW · **Type:** State · **Deploy unit:** apps/web-app · **Covered by test?** no · **Origin:** MAIN · **Other units:** none

## Location
- `apps/web-app/src/components/swatch-tool.ts:2341`

## Evidence
- Reproduction: Load a .chara, pick a slot, click SEND TO > Harmony; the page reloads and returning to Swatch shows no loaded character
- swatch-tool.ts:2341 binds each SEND TO chip to window.location.assign(target.url), which is a full document load. chara-session-service.ts:10-11 says the session is kept in memory only by design, so a reload clears it. The loaded character is lost on every SEND TO click.
  - Checked: swatch-tool.ts:2341 window.location.assign; chara-session-service.ts:10-11 'Memory only ... so a reload clears it'; gradient-tool.ts:2056 and swatch-tool.ts:1552 already use handoffTo / RouterService.navigateTo; no test references swatch.sendTo or the chip click (git grep)
- Origin: git grep at 8ecb878f finds the same line at swatch-tool.ts:2341; git log 8ecb878f..HEAD -- swatch-tool.ts is empty

## Fix
- Navigate with RouterService.navigateTo(tool, params), or with handoffTo for single-dye targets, so the SPA and CharaSessionService survive. Keep the stainID params from handoffTargets.
