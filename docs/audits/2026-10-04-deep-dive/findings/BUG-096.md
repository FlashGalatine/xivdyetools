# BUG-096: image-zoom-controller.ts Ctrl-drag pan ignores the centring margin, so a fitted image jumps on the first pan move
**Severity:** LOW · **Type:** Logic · **Deploy unit:** apps/web-app · **Covered by test?** no · **Origin:** MAIN · **Other units:** none

## Location
- `apps/web-app/src/components/image-zoom-controller.ts:607`

## Evidence
- Reproduction: Load an image whose aspect differs from the card (auto-fit centres one axis), Ctrl+drag 1px -> image snaps toward top/left by the centring offset
- autoFit leads to fitToWidth/fitToScreen, which call resetPan and updateZoom(...,true), so isCentered=true and margin = centring + panOffset (:359-365). The Ctrl-drag mousemove (:600-610) writes margin = panOffset+dx and drops the centring term. On a fitted image with a non-zero centring margin, the first move jumps by that margin; mouseup (:655-664) then sets isCentered=false, so the jump persists.
  - Checked: image-zoom-controller.ts:357-371 vs :600-610 and :655-664; autoFit :868-885; fitToWidth/fitToScreen :827-861
- Origin: git diff 8ecb878f HEAD -- image-zoom-controller.ts empty

## Fix
- On pan start, fold the current centring margin into panOffsetX/Y and clear isCentered, or compute the move margin through the same centring formula.
