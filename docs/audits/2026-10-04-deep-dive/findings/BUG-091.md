# BUG-091: glamour-twin-picker (role=dialog) and item-links-menu never register with ModalService, so global 1-9/Shift+T/L/S shortcuts fire while they hold focus
**Severity:** LOW · **Type:** State · **Deploy unit:** apps/web-app · **Covered by test?** no · **Origin:** MAIN · **Other units:** apps/web-app/src/components/item-links-menu.ts:207 (capture handler stops only arrows/Escape)

## Location
- `apps/web-app/src/components/glamour-twin-picker.ts:234`

## Evidence
- Reproduction: Open the twin picker, focus a radio, press 2 -> tool navigation fires and the block (and picker) is torn down; Shift+T toggles theme under the picker.
- Picker is role=dialog (line 98) appended to body; its document keydown handles only Escape (226-234) and list handler only arrows/Home/End, no ModalService.registerExternal (export sheet does, glamour-sheet.ts:428). keyboard-service.ts:155 only suppresses when hasOpenModals(); a radio is not text entry, so '2' navigates and Shift+T flips theme behind the open dialog. Cosmetic/inconsistent, nothing lost.
  - Checked: glamour-twin-picker.ts:98,223-244; keyboard-service.ts:138-185; glamour-sheet.ts:428
- Origin: git grep 8ecb878f: glamour-twin-picker.ts:98 role dialog, no registerExternal; glamour-sheet.ts:428 registerExternal

## Fix
- Call ModalService.registerExternal() when the picker/menu opens and release it in their cleanup (web-app only, no publish).
