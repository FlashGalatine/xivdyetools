# BUG-121: LanguageService.setLocale has no sequencing; overlapping calls desync core and web locales
**Severity:** LOW · **Type:** Race · **Deploy unit:** apps/web-app · **Covered by test?** no · **Origin:** MAIN · **Other units:** none

## Location
- `apps/web-app/src/services/language-service.ts:83`

## Evidence
- Reproduction: setLocale('ja') on an uncached chunk, then setLocale('de') (cached) before ja's import resolves -> core=de, UI strings/storage=ja
- setLocale (language-service.ts:83-129) sets core LocalizationService synchronously-ish first, then awaits a dynamic import of the locale chunk before committing currentLocale. Two overlapping calls with different targets on a cold chunk leave core on the later call and the web locale on the slower one; getDyeName proxies (:202) read core's current locale.
  - Checked: language-service.ts:91 core set, :94-96/:323 dynamic import await, :105 commit; core LocalizationService.ts:217-231
- Origin: git log 8ecb878f..HEAD -- apps/web-app/src/services/language-service.ts is empty

## Fix
- Monotonic request token: after each await, drop the result if superseded, and re-apply core setLocale at commit time; web-app only.
