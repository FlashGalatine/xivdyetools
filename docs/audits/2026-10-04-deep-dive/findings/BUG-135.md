# BUG-135: ColorConverter.hsvToRgb caches under a key rounded to 2 dp but stores the result computed from the unrounded inputs, so the output depends on call order
**Severity:** LOW · **Type:** State · **Deploy unit:** packages/core · **Covered by test?** no · **Origin:** MAIN · **Other units:** apps/web-app gradient-tool, packages/bot-logic gradient

## Location
- `packages/core/src/services/color/ColorConverter.ts:385`

## Evidence
- Reproduction: ColorConverter.hsvToRgb(0,50.004,100); ColorConverter.hsvToRgb(0,49.996,100) -> {r:255,g:127,b:127} (fresh: {255,128,128})
- Measured: hsvToRgb(0,50.004,100) then hsvToRgb(0,49.996,100) returns {255,127,127} for the second call, while a fresh instance gives {255,128,128}. Live through hsvToHex in the web gradient tool and the bot /gradient. Off by one unit per channel, so cosmetic.
  - Checked: temp repro (deleted): R06 {255,127,127} {255,127,127} {255,128,128}
- Origin: git show 8ecb878f:packages/core/src/services/color/ColorConverter.ts:385 same rounded cacheKey

## Fix
- Compute from the rounded h/s/v that form the key (or key on exact values). Needs a @xivdyetools/core publish, then consumer deploys if wanted (web-app, discord-worker).
