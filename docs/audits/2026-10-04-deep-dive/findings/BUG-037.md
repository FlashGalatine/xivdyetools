# BUG-037: index.ts telemetry limiter registered twice; each beacon is charged 2x against the 240/60s fail-closed bucket
**Severity:** LOW · **Type:** Logic · **Deploy unit:** apps/api-worker · **Covered by test?** no · **Origin:** MAIN · **Other units:** none

## Location
- `apps/api-worker/src/index.ts:128`

## Evidence
- Reproduction: POST /v1/telemetry with TELEMETRY_RATE_LIMITER bound -> 2 limit() calls -> beacons from a NAT IP are dropped (429) after 120/min instead of 240/min
- index.ts:128-129 registers telemetryRateLimitMiddleware on both TELEMETRY_PATH and `${TELEMETRY_PATH}/*`. A temporary repro that drove the real index.ts app (since deleted) recorded 2 limit() calls ['telemetry:ip:203.0.113.9:t240_60' x2] for one POST /v1/telemetry and 1 call for /v1/telemetry/x. The bucket fails closed, so the effective cap is 120 beacons per IP, not 240.
  - Checked: Temporary __repro__ test that imports index.ts app: CALLS [t240_60, t240_60] for one beacon; CALLS2 1 for /v1/telemetry/x.; wrangler.toml binds TELEMETRY_RATE_LIMITER (240/60) in both envs (1004 dev, 1003 prod).; rate-limit.test.ts:70-76 registers only the exact path, so no test exercises the real wiring.
- Second, independent check (severity LOW): The defect is real. In apps/api-worker/src/index.ts, lines 128 and 129 both register the same telemetryRateLimitMiddleware instance, and Hono's `/v1/telemetry/*` pattern also matches the bare `/v1/telemetry`. The worker-kit factory (packages/worker-kit/src/middleware/rate-limit.ts) has no once-per-request guard, so every beacon calls the TELEMETRY_RATE_LIMITER binding twice under the same key. The origin is MAIN: both lines exist at 8ecb878f, added in 0bc669e4.

I grade it LOW, not MEDIUM. The only harm is lost analytics data points. Beacons go through sendBeacon, so the client ignores the response, and the TELEMETRY_LIMIT docblock says a dropped beacon "costs nothing but a data point". It only happens when one IP has more than about 30 opted-in tabs open, instead of the intended 60, and the native binding counts per colo. The error is on the safe side: it admits fewer beacons, not more. It cannot 429 /v1/chara/*, which uses a separate bucket, and no user sees a wrong result.
- Origin: git show 8ecb878f:apps/api-worker/src/index.ts shows both use() lines at 128-129; git log 8ecb878f..HEAD -- src/index.ts is empty

## Fix
- Keep only app.use(`${TELEMETRY_PATH}/*`, ...) (Hono's /* also matches the bare path) and fix the stale comment. Add a test through index.ts's app asserting one limit() call per beacon.
