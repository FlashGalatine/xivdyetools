# BUG-084: collection-manager-modal downloadSingleCollection filename strips all non-ASCII (CJK names become dashes)
**Severity:** LOW · **Type:** Edge case · **Deploy unit:** apps/web-app · **Covered by test?** no · **Origin:** MAIN

## Location
- `apps/web-app/src/components/collection-manager-modal.ts:535`

## Evidence
- Reproduction: Rename a collection to 赤い服 and export it individually -> the file is named xivdyetools----.json
- collection-manager-modal.ts:535 applies /[^a-z0-9]/gi, so a collection named in ja/ko/zh exports as xivdyetools-----.json, a meaningless name (import reads content, so there is no data loss). The Safari half (the input is removed synchronously at :606) is plausible but unverified here; it is not the basis of this verdict.
  - Checked: collection-manager-modal.ts:526-540 (live: called at :166); test file only covers the all-collections export (:242)
- Origin: git show 8ecb878f:apps/web-app/src/components/collection-manager-modal.ts:535 has the same replace(/[^a-z0-9]/gi,'-'); no PR touches the file

## Fix
- Sanitize with /[^\p{L}\p{N}]+/gu (and trim the dashes), falling back to collection.id when the result is empty; optionally keep the import input attached until change fires. Web-app only, no package publish.
