# BUG-081: budget-tool.ts saveSwapRecord breaks 216-gil ties by database order, not by ΔE
**Severity:** LOW · **Type:** Logic · **Deploy unit:** apps/web-app · **Covered by test?** no · **Origin:** MAIN

## Location
- `apps/web-app/src/components/budget-tool.ts:1229`

## Evidence
- Reproduction: Target a Wide or Coffer dye with several Standard dyes within the line, then click Save swap: the record stores the first by database order (possibly near the threshold) rather than the closest 216-gil dye.
- priceOf gives every tier-A row gil = CONSOLIDATED_DYES.A.price (216). The reduce uses strict < over this.rows, which is in getAllDyes order (582-598, unsorted), so the first Standard dye in range is saved, not the closest. Save swap is live (renderTargetOverview:1191). MEDIUM: an edge feature.
  - Checked: budget-tool.ts:478-480 tier A gil=216; :1229-1237 strict-< reduce; rows built unsorted at 582-598
- Second, independent check (severity LOW): The mechanism is real. In apps/web-app/src/components/budget-tool.ts, priceOf (lines 478-480) prices every tier-A dye at CONSOLIDATED_DYES.A.price. The saveSwapRecord reduce (lines 1229-1237) keeps only rows with a strictly lower gil. this.rows is built in getAllDyes order and is never sorted (lines 582-598). So when several tier-A rows tie at 216, the first one in database order is saved, not the closest by ΔE. The ledger's default perPoint sort (lines 670-676) puts the closest 216-gil dye at the top, so the saved dye can differ from the row the user sees first. No test covers saveSwapRecord.

I would grade it LOW, not MEDIUM. The saved dye is still at the minimum price and still inside the match line the user picked, so it is an acceptable substitute by the user's own rule. That matches the method's docstring ("best-priced substitute") literally. The defect is a weak tie-break inside an optional, device-local "Save swap" record: nothing is lost, the main ledger and verdict are correct, and the user can see the closer option in the ledger. That makes it closer to cosmetic or suboptimal than a wrong result.
- Origin: git diff --stat 8ecb878f HEAD -- budget-tool.ts: empty

## Fix
- Tie-break lexicographically on (gil, de), or pick the best perPoint row. Web-app only.
