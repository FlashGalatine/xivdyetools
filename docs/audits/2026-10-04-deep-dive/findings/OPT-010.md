# OPT-010: logger redactSensitiveFields rebuilds the normalized redact Set per node per call
**Impact:** LOW · **Category:** Caching · **Deploy unit:** packages/logger · **Expected gain:** ~48 toLowerCase/replace calls and one Set allocation saved per context node per log line; microseconds · **Benchmark:** Microbench JsonAdapter.info with a 3-level nested context x 10k calls, before and after hoisting the set

## Location
- `packages/logger/src/core/base-logger.ts:274`

## Evidence
- Lines 273-275 sit inside redactSensitiveFields, so every object node on every log call rebuilds normalize plus a Set over redactFields. That is about 48 entries for the worker preset, because the constructor prepends CORE to WORKER_REDACT_FIELDS, which already includes CORE. Real but tiny.
  - Checked: base-logger.ts:267-275; constants.ts WORKER_REDACT_FIELDS spreads CORE; constructor at :95 prepends CORE again
- Origin: git show 8ecb878f:packages/logger/src/core/base-logger.ts:273 has the same const normalize

## Fix
- Compute the normalized Set once in the constructor (or memoize per redactFields array) and dedupe it. Needs a @xivdyetools/logger publish, then consumer deploys.
