# BUG-095: harmony-tool.ts renderRightPanel: each render adds a new matchMedia listener; destroy removes only the last
**Severity:** LOW · **Type:** Resource · **Deploy unit:** apps/web-app · **Covered by test?** no · **Origin:** MAIN · **Other units:** N/A

## Location
- `apps/web-app/src/components/harmony-tool.ts:1067`

## Evidence
- Reproduction: Mount Harmony via /harmony?dye=5 (2 renders) or change language N times -> N-1 orphaned lists keep calling renderTypeRail at every 768px crossing after destroy.
- renderRightPanel runs on every update() (renderContent :265). Each run builds a new MediaQueryList and adds onRailBreakpoint, and destroy (:435) removes it from the latest list only. Language changes (:312) and every deep-link mount with dye (handleDeepLink's update() at :601) leave earlier lists firing renderTypeRail, also after the tool is destroyed. The effect is a latent leak with redundant DOM work.
  - Checked: harmony-tool.ts:265,435,601,1067-1068
- Origin: git show 8ecb878f:harmony-tool.ts:1067 `this.railMql = window.matchMedia(...)`; no PR touches the file

## Fix
- Create railMql once in onMount, or remove the listener from the previous railMql before reassigning it.
