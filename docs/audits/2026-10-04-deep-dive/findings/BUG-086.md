# BUG-086: comparison-tool.ts renders the market price row from its own showMarketPrices flag, while the service's showPrices (default off) blocks fetching
**Severity:** LOW · **Type:** Logic · **Deploy unit:** apps/web-app · **Covered by test?** no · **Origin:** MAIN · **Other units:** none (same pattern in harmony/gradient/mixer/swatch tools, same unit)

## Location
- `apps/web-app/src/components/comparison-tool.ts:1969`

## Evidence
- Reproduction: Fresh profile, Comparison, select 2 dyes -> each card shows 'Market · Crystal —' that never fills (service showPrices=false)
- Defaults: comparison displayOptions.showPrice=true (tool-config-types.ts:356/:459, comparison-tool.ts:115) but market.showPrices=false (:414). fetchPricesForDyes filters on shouldFetchPrice, which returns false when !showPrices (market-board-service.ts:297, :321), so the cards render 'Market · Crystal' with '—' forever (result-card.ts:1046, :1684-1691). Harmony, gradient, mixer and swatch share the ungated pattern; only the extractor ANDs it (extractor-tool.ts:1989).
  - Checked: comparison-tool.ts:1969-1980, :1994, :1472-1490; market-board-service.ts:97, :297, :321; tool-config-types.ts:356, :414
- Origin: git diff 8ecb878f HEAD -- comparison-tool.ts market-board-service.ts tool-config-types.ts empty

## Fix
- Gate card.showPrice and the price lookup on showMarketPrices && MarketBoardService.getShowPrices(), as extractor-tool.ts:1989 does (and apply the same to the duel path at :1472-1490).
