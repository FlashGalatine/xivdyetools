# BUG-055: oauth tests never send a percent-encoded /auth path through the app's limiter or a JSON `null` body to the POST callbacks
**Severity:** LOW · **Type:** Untested behavior · **Deploy unit:** apps/oauth · **Covered by test?** no · **Origin:** MAIN · **Other units:** none

## Location
- `apps/oauth/src/__tests__/rate-limit.test.ts:1`

## Evidence
- Reproduction: Run the suite with BUG-007 and BUG-056 present -> everything passes
- A grep of apps/oauth/src/__tests__ for %XX path escapes or a 'null' body finds only one unrelated redirect_uri assertion (callback.test.ts:960). The rate-limit tests call checkRateLimit with literal paths, and the invalid-body tests send malformed JSON only. That is how BUG-007 and BUG-056 went unnoticed.
  - Checked: Grep %[0-9A-Fa-f]{2}|body: 'null' over apps/oauth/src/__tests__ -> one unrelated hit
- Origin: Neither test exists at 8ecb878f, and no open PR adds one (git log 8ecb878f..HEAD shows no oauth test of this kind)

## Fix
- Add an app.fetch test that posts /auth/%63allback past the 20/min limit and expects a 429, plus a test that posts body 'null' to both callbacks and expects a 400. Ship them with the BUG-007 and BUG-056 fixes.
