# BUG-108: preset-detail.ts checkVoteStatus: a failed hasVoted check overwrites the vote count with 0
**Severity:** LOW · **Type:** Error handling · **Deploy unit:** apps/web-app · **Covered by test?** partly · **Origin:** MAIN

## Location
- `apps/web-app/src/components/v4/preset-detail.ts:699`

## Evidence
- Reproduction: Signed-in user opens a 12-vote preset while /votes/:id/check returns 429/500 or the network fails -> badge hidden (currentVoteCount > 0 gate) and the button reads 'Vote · 0'
- hasVoted returns {has_voted:false, vote_count:0} on a non-OK or network failure (community-preset-service.ts:522-535). checkVoteStatus (preset-detail.ts:697-701) applies any vote_count that is not undefined, so currentVoteCount becomes 0. Graded LOW: display-only and transient, since failures are not cached.
  - Checked: preset-detail.ts:690-701; community-preset-service.ts:522-535; preset-detail.test.ts:284-321 covers only the in-flight race
- Origin: git diff 8ecb878f HEAD over v4/ and community-preset-service.ts is empty

## Fix
- Have hasVoted signal failure (vote_count undefined, or an ok flag) or have checkVoteStatus keep preset.voteCount on failure. web-app only.
