# BUG-141: logger redactSensitiveFields spread-copies toJSON objects (Date/URL), logging them as {}
**Severity:** LOW · **Type:** Edge case · **Deploy unit:** packages/logger · **Covered by test?** no · **Origin:** MAIN · **Other units:** all logger consumers (every worker, web-app)

## Location
- `packages/logger/src/core/base-logger.ts:303`

## Evidence
- Reproduction: JsonAdapter.info('x',{at:new Date(0),u:new URL('https://a.b/c')}) -> context {"at":{},"u":{}} (temp repro, deleted)
- Narrower than the claim. The {...context} spread at base-logger.ts:303 destroys only values that have a toJSON (Date, URL): a repro logged {at:{},u:{}}, where plain JSON.stringify gives the ISO string and href. Error, Map and Uint8Array already serialize the same way without redaction, so that half is not a defect. LOW: no in-repo caller logs a Date or URL in context.
  - Checked: base-logger.ts:296-305 recursion; repro output vs the plain JSON.stringify control line; git grep found no Date/URL log context in apps/*, worker-kit or bot-logic
- Origin: git log 8ecb878f..HEAD -- base-logger.ts is empty; git show 8ecb878f:...base-logger.ts:303 has the same redactSensitiveFields(value as LogContext, g)

## Fix
- If a value has a toJSON function, call it first: scan a string result with looksLikeSecretValue and recurse into an object result. Keep spread-and-recurse for everything else (do NOT skip non-plain objects; that would bypass key redaction). Needs a @xivdyetools/logger publish, then consumer deploys.
