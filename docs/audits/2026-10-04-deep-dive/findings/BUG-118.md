# BUG-118: collection-service importData: earlier-audit BUG-024 guard dereferences a null collections[] element outside the per-record try
**Severity:** LOW · **Type:** Edge case · **Deploy unit:** apps/web-app · **Covered by test?** no · **Origin:** MAIN · **Other units:** none

## Location
- `apps/web-app/src/services/collection-service.ts:938`

## Evidence
- Reproduction: Import {type:'xivdyetools-collection',data:{collections:[{name:'A',dyes:[1]},null,{name:'B',dyes:[2]}]}}. 'A' is saved, 'B' is dropped, collection-manager-modal.ts:594 shows the parseFailed error toast, and the modal does not refresh.
- Only a JSON null element throws: the guard at :938-941 reads collection.name before the per-record try (:950), so a TypeError reaches the outer catch at :1004 and pushes parseFailed with success:false. Earlier favorites and collections are already persisted, and the records after the null are abandoned. A number or string element reads .name as undefined and is skipped cleanly.
  - Checked: collection-service.ts:938-948 (guard outside try), :1004-1006 (outer catch -> parseFailed); collection-manager-modal.ts:581-597
- Origin: git diff --stat 8ecb878f HEAD -- apps/web-app/src/services/ is empty; git show 8ecb878f:…/collection-service.ts:938-941 has the same guard

## Fix
- Put `!collection || typeof collection !== 'object' ||` first in the guard, or move the guard inside the per-record try. Web-app only, no package publish.
