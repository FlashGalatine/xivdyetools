# BUG-051: ban-reason.ts handleBanReasonModal: reason length check is untrimmed, so a whitespace-only reason is stored
**Severity:** LOW · **Type:** Edge case · **Deploy unit:** apps/moderation-worker · **Covered by test?** no · **Origin:** MAIN · **Other units:** none

## Location
- `apps/moderation-worker/src/handlers/modals/ban-reason.ts:103`

## Evidence
- Reproduction: A moderator submits 10 spaces as the ban reason, and the ban is recorded and posted with a blank reason.
- ban-reason.ts:103 checks `reason.length < 10` (cited :267 is isBanReasonModal). Modal min_length 10 (ban-confirmation.ts:104) counts spaces, and extractTextInputValue does not trim. The value reaches banUser (:171), which binds it to banned_users.reason and moderation_log (ban-service.ts:498-507). Rejection/revert use reason.trim().length (preset-rejection.ts:121,240). The actor is a trusted moderator.
  - Checked: ban-reason.ts:101-104,171; ban-service.ts:498-507; git show 8ecb878f:.../ban-reason.ts:96 has the same `reason.length < 10`
- Origin: git show 8ecb878f:apps/moderation-worker/src/handlers/modals/ban-reason.ts line 96: `if (!reason || reason.length < 10)`

## Fix
- Use `reason.trim().length < MIN_REJECTION_REASON_LENGTH` (shared constant) and store the trimmed reason.
