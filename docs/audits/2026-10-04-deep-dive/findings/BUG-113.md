# BUG-113: v4-layout-shell.ts re-emits composed child events without stopPropagation, so v4-layout handlers run twice
**Severity:** LOW · **Type:** Logic · **Deploy unit:** apps/web-app · **Covered by test?** no · **Origin:** MAIN · **Other units:** none

## Location
- `apps/web-app/src/components/v4/v4-layout-shell.ts:863`

## Evidence
- Reproduction: Click What's New: the v4-layout changelog-click listener runs twice. The second showChangelogModal is a guarded no-op.
- emit() is bubbles+composed (base-lit-component.ts:110-117). These shell handlers re-emit without stopping the original: config-change (863), clear-all-dyes (919), theme/changelog/about/language (936-962) and advanced (997). handleDyeSelected (911) does stop it. The v4-layout listeners on the host therefore fire twice. This is latent only: the modal shows are guarded (e.g. advanced-options-panel.ts:376) and tool setConfig is change-gated (budget-tool.ts:324+).
  - Checked: v4-layout-shell.ts:863-865, 919-921, 936-962, 996-998 vs 908-913; base-lit-component.ts:110-117; v4-layout.ts:180-194, 228
- Origin: shell and v4-layout.ts unchanged 8ecb878f..HEAD

## Fix
- Call e.stopPropagation() on the original in each re-emitting handler, as handleDyeSelected does. Web-app deploy only.
