# BUG-018: comparison-tool.ts buildSevenReadouts: the ΔE2000 tier skips tierFor's 0->1 bump, so it contradicts the verdict when matchThreshold < 5
**Severity:** MEDIUM · **Type:** Logic · **Deploy unit:** apps/web-app · **Covered by test?** no · **Origin:** MAIN · **Other units:** none

## Location
- `apps/web-app/src/components/comparison-tool.ts:1914`

## Evidence
- Reproduction: matchThreshold=2, active method ciede2000, pair ΔE2000=3.0 -> verdict and chips say CLOSE (tierFor=1), while the ΔE2000 readout row in the same duel says SAME (tier 0)
- tierFor (1190-1197) returns 0 only below matchThreshold and otherwise bumps a band tier of 0 to 1. The readout loop (1914-1915) takes classifyBandTier and forces 0 below the threshold, but never bumps. The ciede2000 match cuts are [5,10,20] (band-vocabulary.ts:94), and the sidebar slider allows 1-15 (config-sidebar.ts:1257-1260).
  - Checked: comparison-tool.ts:1190-1197 vs 1914-1915; packages/core/src/config/band-vocabulary.ts:94; v4/config-sidebar.ts:1257-1260
- Second, independent check (severity MEDIUM): I could not refute it, and MEDIUM is the right grade. I worked it through by hand. tierFor (comparison-tool.ts:1190-1197) bumps a ciede2000 band tier of 0 up to 1 once the value is at or above matchThreshold. The readout loop (1912-1915) only forces 0 below the threshold and never bumps. With the match cuts at [5,10,20] and the slider allowing 1-15, any threshold below 5 leaves a gap between the threshold and 5 where the two disagree. In the same duel the verdict and chips say CLOSE while the ΔE2000 readout row says SAME, and the slider puts that pair above the SAME line. The default threshold is 5, so the user has to lower the slider first. That makes it a wrong result on an edge path, which is MEDIUM rather than HIGH. It is not just cosmetic, because the row contradicts the verdict next to it. Nothing tests it, and the code already exists on main.
- Origin: git diff --stat 8ecb878f HEAD -- comparison-tool.ts is empty

## Fix
- Parameterise tierFor(value, method) and use it for the readout rows, so one function owns the SAME cut.
