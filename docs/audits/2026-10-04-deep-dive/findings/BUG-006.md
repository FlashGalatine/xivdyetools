# BUG-006: preset-favorites getPresetFavoriteEntries returns [] on read failure and addPresetFavorite overwrites the user's list
**Severity:** MEDIUM · **Type:** Error handling · **Deploy unit:** apps/discord-worker · **Covered by test?** no · **Origin:** MAIN

## Location
- `apps/discord-worker/src/services/preset-favorites.ts:100`

## Evidence
- Reproduction: kv.get throws once during /preset favorite add: the list of up to 50 is replaced by the single new entry, and the user sees success
- Same mechanism as 03, so it gets the same grade. Line corrected: the file is 193 lines, so 620 does not exist. The catch at preset-favorites.ts:95-100 returns [] on a kv.get or parse failure. addPresetFavorite (147-150) pushes onto that [] and savePresetFavoriteEntries writes both the v2 and v1 keys, replacing a list of up to 50 with one entry and reporting success.
  - Checked: preset-favorites.ts:67-101 (catch -> []), 137-151 (push + save), 105-120 (puts the v2 and v1 keys); removePresetFavorite fails safe (notFound) on the same read failure
- Second, independent check (severity MEDIUM): I could not refute it. getPresetFavoriteEntries catches every kv.get or JSON.parse failure and returns [] (preset-favorites.ts:95-101). addPresetFavorite treats that [] as an empty list: the dedupe and limit guards pass, it pushes one entry and savePresetFavoriteEntries overwrites both the v2 and the v1 keys (118-119). It then returns {success:true}, and the handler at preset.ts:1238 shows the success embed. Nothing on the path rethrows. I keep MEDIUM rather than CRITICAL: the data lost is a user's own preference list, and the trigger is rare (a transient KV read error, or a corrupt v2 blob). It is not LOW, because the loss is silent, permanent, reported as success, and no other code defends against it.
- Origin: git log 8ecb878f..HEAD -- apps/discord-worker/src/services/ is empty; the same code is at 8ecb878f

## Fix
- Use a rethrowing read on the add and remove write paths, so the existing catch returns {success:false, reason:'error'}. Keep the lenient read for autocomplete and list.
