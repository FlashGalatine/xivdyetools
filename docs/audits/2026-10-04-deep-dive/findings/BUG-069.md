# BUG-069: validation-service validateExampleLink rejects a leading-space link that normalizeExampleLink would accept
**Severity:** LOW · **Type:** Edge case · **Deploy unit:** apps/presets-api · **Covered by test?** no · **Origin:** MAIN

## Location
- `apps/presets-api/src/services/validation-service.ts:438`

## Evidence
- Reproduction: direct API example_link ' https://x.com/a' -> 400 'Example link is not a valid URL'
- validateExampleLink does not trim (validation-service.ts:438). With a leading space the scheme regex fails and it prefixes 'https://'; node shows new URL('https:// https://x.com/a') throws, giving a 400, although normalizeExampleLink trims. Both first-party clients are defended (the web form trims, the bot has no link option): LOW.
  - Checked: node: new URL('https:// https://x.com/a') and new URL('https:// x.com/a') both throw; web-app preset-submission-form.ts:688 trims
- Origin: git show 8ecb878f:validation-service.ts:390 validateExampleLink / :426 normalizeExampleLink, same asymmetry

## Fix
- link = link.trim() at the top of validateExampleLink, before the scheme test. App-only.
