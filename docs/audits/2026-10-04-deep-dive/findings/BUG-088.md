# BUG-088: dye-selector.ts handleGlobalKeydown: activeElement guard is blind inside the shell's shadow root, so '/' is swallowed in tool inputs
**Severity:** LOW · **Type:** Edge case · **Deploy unit:** apps/web-app · **Covered by test?** no · **Origin:** MAIN · **Other units:** none

## Location
- `apps/web-app/src/components/dye-selector.ts:290`

## Evidence
- Reproduction: Comparison tool, focus the dye search input (shadow root), type '/' -> no character inserted (preventDefault), focus stays put
- Tools mount inside V4LayoutShell's shadow root (v4-layout.ts:473-485 getContentContainer), so document.activeElement is the <v4-layout-shell> host and dye-selector.ts:290 never sees INPUT. A '/' typed into any shadow-side field, including the DyeSelector's own search box, is preventDefaulted. keyboard-service.ts:111-133 already documents and fixes this exact retargeting.
  - Checked: dye-selector.ts:246 (document keydown), :288-295; v4-layout.ts:473-485, :581-719; keyboard-service.ts:111-133 isUserTyping
- Origin: git diff 8ecb878f HEAD -- dye-selector.ts is empty; no 8ecb878f..HEAD commits touch it

## Fix
- Reuse the keyboard-service test: check event.composedPath()[0] for input/textarea/select/contenteditable before preventDefault (web-app only, no package publish).
