# BUG-023: swatch-tool setConfig needsReload branch nulls selectedColor but leaves matchedDyes, result cards, SEND TO ids and an enabled share button
**Severity:** MEDIUM · **Type:** State · **Deploy unit:** apps/web-app · **Covered by test?** no · **Origin:** MAIN

## Location
- `apps/web-app/src/components/swatch-tool.ts:520`

## Evidence
- Reproduction: Click grid cell (cards appear), then click another palette chip or change tribe -> empty-state shown, but the old cards stay in matchResultsContainer, SEND TO carries old stainIDs, share button stays enabled with the old params
- The reload path clears only selectedColor. matchedDyes, the rendered cards, the handoff ids and the share-button state survive the palette change.
  - Checked: swatch-tool.ts:519-529 only nulls selectedColor; the .then runs updateColorGrid (1882-1966), which calls updateHandoffRow (it reads matchedDyes) and updateEmptyState, never updateMatchResults or updateShareButton; clearSelection (2854-2861) is what the in-tool selects use
- Second, independent check (severity MEDIUM): I could not refute it. A temporary test confirmed the defect: picking a grid cell and then changing the palette leaves the old result card and enabled SEND TO chips on screen, while the empty state says no colour is selected. One part is overstated. The share button does stay enabled with its old parameters, but updateEmptyState hides the match header that holds it (display none), so a user cannot see or reach it. The palette rail is the tool's main navigation, so this is a normal path. The user sees stale matches and can send stale dyes to another tool, but nothing is lost and the next cell pick fixes everything. That is a wrong result on an edge path, so MEDIUM, not HIGH.
- Origin: git diff 8ecb878f HEAD -- apps/web-app/src/components/swatch-tool.ts is empty; 8ecb878f:swatch-tool.ts:521 has `this.selectedColor = null;`

## Fix
- In the needsReload branch, synchronously clear the forward state (selectedColor, matchedDyes, results container via updateMatchResults, updateShareButton) and keep a slot selectionContext. Do not call clearSelection() in the .then: that would null the slot context pickCharaSlot sets before setConfig.
