# BUG-030: preset-tool.ts handleCardVote: every failed vote is shown as 'already voted'; a failed removeVote is silent
**Severity:** MEDIUM · **Type:** Error handling · **Deploy unit:** apps/web-app · **Covered by test?** no · **Origin:** MAIN

## Location
- `apps/web-app/src/components/v4/preset-tool.ts:859`

## Evidence
- Reproduction: Signed in, presets API returns 500 or the network drops -> click Vote on a card -> card flips to Voted with an 'already voted' toast, but no vote is recorded
- voteForPreset never throws on failure: it returns success:false with errorCode voteFailed/network/notLoggedIn (community-preset-service.ts:394-441). handleCardVote's else branch (:859-863) marks the card voted and toasts alreadyVoted without checking already_voted. A failed removeVote has no else branch at all. preset-detail.ts:821-826 already branches correctly.
  - Checked: preset-tool.ts:845-871; community-preset-service.ts:409-441 (409 -> already_voted, else voteFailed/network); preset-detail.ts:821-826 does it right
- Second, independent check (severity MEDIUM): The defect is real as described. voteForPreset and removeVote never throw: every failure comes back as success:false, with errorCode voteFailed or network (a non-JSON 500 body makes response.json() throw, which is caught and becomes network). handleCardVote's else branch adds the preset to votedIds and shows the 'already voted' toast without checking already_voted. The voted branch has no else at all, so a failed removeVote does nothing, and the outer catch that would show errors.voteFailed can never fire. The trigger is an API or network failure, which is an edge path, and the wrong state lives only in this component's memory (votedIds is never loaded from the server). A reload clears it and no data is lost, so MEDIUM is right and HIGH does not apply. One correction: the cited line numbers are stale. The handler is at preset-tool.ts:881-916 and the faulty else is at :906-910, not :845-871 / :859, but the content matches.
- Origin: git diff 8ecb878f HEAD over v4/ and community-preset-service.ts is empty

## Fix
- Treat the vote as already cast only when result.already_voted; otherwise toast voteErrorMessage(errorCode) and leave votedIds alone. Add an error toast when removeVote fails. web-app only.
