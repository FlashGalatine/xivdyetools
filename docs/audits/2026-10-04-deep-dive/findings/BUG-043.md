# BUG-043: gradient.ts processGradientCommand: Start/End lines print the English Dye.name while step rows are localized
**Severity:** LOW · **Type:** Logic · **Deploy unit:** apps/discord-worker · **Covered by test?** no · **Origin:** MAIN · **Other units:** none

## Location
- `apps/discord-worker/src/handlers/commands/gradient.ts:185`

## Evidence
- Reproduction: /gradient start_color:Snow White (or the Japanese name) end_color:Soot Black, user locale ja -> '開始: **Snow White**' and '終了: **Soot Black**' above Japanese step rows
- In gradient.ts:185-190 the Start/End text uses startColor.name / endColor.name. Those come from bot-logic resolveColorInput (input-resolution.ts:242-252), which always returns the English dye.name, even when a locale name matched. The step rows use dyeName, which bot-logic gradient.ts:290 localizes with getLocalizedDyeName.
  - Checked: gradient.ts:185-190 uses startColor.name; packages/bot-logic/src/input-resolution.ts:242-252 returns name: dye.name; packages/bot-logic/src/commands/gradient.ts:290 localizes the step names only
- Origin: git show 8ecb878f:apps/discord-worker/src/handlers/commands/gradient.ts has the same lines 185-189; git log 8ecb878f..HEAD shows no change to the file

## Fix
- In gradient.ts, build startText/endText from getLocalizedDyeName(startColor.itemID, startColor.name, locale) (services/i18n.js) when startColor.dye/itemID is set; same for endColor. App-only change, no package publish.
