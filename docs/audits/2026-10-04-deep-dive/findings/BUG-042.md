# BUG-042: extractor.ts renderColorSheet: render/edit failure is never logged and is reported to the user as 'no match found'
**Severity:** LOW · **Type:** Error handling · **Deploy unit:** apps/discord-worker · **Covered by test?** no · **Origin:** MAIN · **Other units:** none

## Location
- `apps/discord-worker/src/handlers/commands/extractor.ts:385`

## Evidence
- Reproduction: /extractor color:#FF0000 while renderSvgToPng (resvg) throws -> user sees 'No match found' and no log line carries the error; the only trace is outcome=render in Analytics Engine
- handleColorSubcommand (extractor.ts:190) passes no logger, and renderColorSheet has no logger parameter. Its catch (extractor.ts:385-389) only calls markCommandOutcome('render'), which records an outcome class and no exception. It then answers errors.noMatchFound, although a match already exists at that point (matches.length > 0 was checked before deferring).
  - Checked: extractor.ts:190 calls handleColorSubcommand with no logger; extractor.ts:306-315 renderColorSheet signature has no logger; extractor.ts:385-389 catch uses errors.noMatchFound; extractor.test.ts has no rejected-render case
- Origin: git show 8ecb878f:apps/discord-worker/src/handlers/commands/extractor.ts:388 already uses errors.noMatchFound in the same catch; the file is unchanged in 8ecb878f..HEAD

## Fix
- Pass logger from handleExtractorCommand into handleColorSubcommand and renderColorSheet. In the catch, call logger?.error('Extractor color render error', err) and answer t.t('errors.generationFailed'), as the gradient and extractor-image paths do. App-only change, no package publish.
