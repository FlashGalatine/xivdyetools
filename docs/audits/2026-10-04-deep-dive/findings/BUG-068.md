# BUG-068: validation-service name/description min-length counts whitespace; whitespace-only values pass
**Severity:** LOW · **Type:** Edge case · **Deploy unit:** apps/presets-api · **Covered by test?** no · **Origin:** MAIN

## Location
- `apps/presets-api/src/services/validation-service.ts:182`

## Evidence
- Reproduction: direct POST /presets name '  ' + 10-space description -> 201, blank preset auto-approved if filter clean
- The length checks at validation-service.ts:182/208 run on the raw string, and presets-api never trims name or description, so '  ' passes and is stored blank. The web form trims (preset-submission-form.ts:679), so only direct API callers hit this: LOW.
  - Checked: git grep trim() in apps/presets-api/src shows no name/description trim; web-app preset-submission-form.ts:679-680 trims client-side
- Origin: git show 8ecb878f:validation-service.ts:155/181 same untrimmed length checks

## Fix
- Trim (or require a non-whitespace code point) before the min-length test and store the trimmed value. App-only.
