# BUG-090: extractor-tool.ts fetchPricesForRoll: the catch, parseMarketError and lastMarketError are unreachable because every layer below swallows fetch failures
**Severity:** LOW · **Type:** Error handling · **Deploy unit:** apps/web-app · **Covered by test?** partly · **Origin:** MAIN · **Other units:** packages/core

## Location
- `apps/web-app/src/components/extractor-tool.ts:2037`

## Evidence
- Reproduction: Universalis proxy returns 5xx with prices on -> extractor cards show the server name with no price and no error code
- MarketBoardService.fetchPricesForDyes catches everything and returns an empty Map (market-board-service.ts:399-410), so the extractor's catch never runs and marketError is never set. Below it, core APIService.fetchBatchPriceData (APIService.ts:654-674) also turns HTTP and network failures into an empty Map, so a proxy outage reports lastFetchOutcome 'ok'. The suggested lastFetchOutcome fix would therefore not fire. Tests pass only because they mock the service to throw, which cannot happen in production.
  - Checked: extractor-tool.ts:2020-2021, 2037-2048; market-board-service.ts:399-410; packages/core/src/services/APIService.ts:654-674
- Origin: git diff --stat 8ecb878f HEAD -- extractor-tool.ts market-board-service.ts packages/core/src/services/APIService.ts is empty

## Fix
- Surface batch failures from core (e.g. an outcome or error on the result) and map them in MarketBoardService, which needs a @xivdyetools/core publish followed by a web-app deploy. Otherwise delete the dead parseMarketError/lastMarketError path.
