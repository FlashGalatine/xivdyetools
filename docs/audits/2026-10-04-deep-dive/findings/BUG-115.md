# BUG-115: auth-service performLogout awaits /auth/revoke with no timeout before clearing local session
**Severity:** LOW · **Type:** Error handling · **Deploy unit:** apps/web-app · **Covered by test?** no · **Origin:** MAIN · **Other units:** none

## Location
- `apps/web-app/src/services/auth-service.ts:756`

## Evidence
- Reproduction: The OAuth worker accepts the connection but never responds. Clicking logout (config-sidebar.ts:1751) hangs, and the user stays signed in with the token in localStorage until the browser gives up.
- The comment at :753 says the revoke is non-blocking, but :756 awaits the fetch with no AbortSignal. clearStorage/clearState/notify only run after it settles, so a stalled revoke leaves the token stored and the UI signed in. The earlier-audit BUG-025 memoised logoutPromise makes every retry share the hang. No test uses a never-resolving fetch.
  - Checked: auth-service.ts:750-774 (await fetch before clearStorage); no AbortController/AbortSignal in the file; auth-service.test.ts has no hanging-fetch case
- Origin: git diff --stat 8ecb878f HEAD -- apps/web-app/src/services/ is empty; git show 8ecb878f:…/auth-service.ts:755-757 has the same await fetch

## Fix
- Clear storage and state and notify first, then send the revoke best-effort (void the promise, or use AbortSignal.timeout(~5s)). Web-app only, no package publish.
