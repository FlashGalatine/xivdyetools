# BUG-124: glamour.ts gposersList writes the 'Model <key>' placeholder as an item name and drops Facewear when glasses are unresolved
**Severity:** LOW · **Type:** Logic · **Deploy unit:** packages/bot-logic · **Covered by test?** no · **Origin:** MAIN · **Other units:** apps/web-app (reference behaviour), apps/discord-worker

## Location
- `packages/bot-logic/src/commands/glamour.ts:251`

## Evidence
- Reproduction: A .chara with an NPC model on Head -> embed list '**Head:** Model e0361…'; glassesId>0 with answer.glasses null -> no Facewear line (web prints 'Facewear:')
- readPiece sets name = t('card.glamourNoItemName') ('Model {key}'), and gposersList (l.324) copies piece.name into GposersInput. l.327/450 add Facewear only when answer.glasses resolves. The web builder glamour-list-actions.ts:65-108 deliberately leaves the slot nameless and writes a bare Facewear line.
  - Checked: glamour.ts:247-252,320-327,450; apps/web-app/src/components/glamour-list-actions.ts:65-108; en.json:639 'Model {key}'
- Origin: git show 8ecb878f:packages/bot-logic/src/commands/glamour.ts lines 251-252, 327, 450 are identical

## Fix
- Keep the placeholder for card rows and notes only. Pass name null into GposersInput when there is no item, and add Facewear {name: resolved ?? null} whenever glassesId>0. Needs a @xivdyetools/bot-logic publish, then a discord-worker deploy.
