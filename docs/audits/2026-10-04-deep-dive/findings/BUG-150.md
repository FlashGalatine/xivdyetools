# BUG-150: worker-kit rateLimitMiddleware deny paths drop Retry-After/X-RateLimit-* when formatError returns a raw Response
**Severity:** LOW · **Type:** Logic · **Deploy unit:** packages/worker-kit · **Covered by test?** no · **Origin:** MAIN · **Other units:** none (no consumer passes formatError)

## Location
- `packages/worker-kit/src/middleware/rate-limit.ts:209`

## Evidence
- Reproduction: rateLimitMiddleware({ ..., formatError: () => new Response('x',{status:429}) }) with a denying backend -> response headers: [content-type] only
- Reproduced in a temporary test, since deleted: formatError returning new Response('x',{status:429}) yields 429 with only content-type, no Retry-After and no X-RateLimit-*. The pre-return c.header() writes land in Hono #preparedHeaders, which a raw Response never merges. Latent: no app passes formatError (git grep apps/*/src).
  - Checked: Temporary __repro__worker-kit-test-utils-03.test.ts printed STATUS 429 HEADERS [["content-type","text/plain;charset=UTF-8"]]; rate-limit.ts:82 types formatError as returning any Response; the comment at :201-202 assumes c.json
- Origin: git show 8ecb878f:packages/worker-kit/src/middleware/rate-limit.ts has 'return formatError(c, retryAfter)' at :167 and :210

## Fix
- Copy the computed headers onto the Response formatError returns (both deny paths, :167 and :210), or type and document that it must build through c.json/c.text.
Needs a @xivdyetools/worker-kit publish; consumers need no redeploy today since none use formatError.
