# OPT-005: preferences legacy-key migration re-reads two dead KV keys on every call for users with no prefs blob
**Impact:** LOW · **Category:** I/O · **Deploy unit:** apps/discord-worker · **Expected gain:** 2-3 fewer KV reads per command (pre-defer path) for users without a prefs blob · **Benchmark:** Count kv.get calls in a unit test of one command for a user with no blob, before and after · **Other units:** packages/bot-logic (resolveUserLocale legacy read)

## Location
- `apps/discord-worker/src/services/preferences.ts:136`

## Evidence
- Reproduction: Any user who never ran /preferences set pays about 3 KV reads in getUserPreferences plus 2 in resolveUserLocale per command
- With no prefs:v1 blob, getUserPreferences calls migrateLegacyPreferences on every call (preferences.ts:136-137), and that does 2 legacy kv.get reads (533-544) that are never negative-cached. resolveUserLocale (bot-logic locale-resolution.ts:147-163) adds an unified read plus a legacy read, so a user without a blob pays about 5 reads where 2 would do. The legacy writers were removed in March 2026 (per the docblock at 520-524). This is not one of the declined caches: those earlier-audit OPT-005/009 are core colour items from 2026-09-02.
  - Checked: preferences.ts:126-143, 533-544; packages/bot-logic/src/i18n/locale-resolution.ts:142-163
- Origin: unchanged since 8ecb878f; bot-logic locale-resolution.ts is also at main

## Fix
- Write a tombstone or empty blob on the first legacy miss, or retire the migration after a one-off sweep. Dropping resolveUserLocale's legacy fallback needs a bot-logic publish, then consumer deploys.
