# BUG-012: budget-tool.ts in-page match-line slider writes only local storage; next full budget-config broadcast resets it to ConfigController maxDeltaE
**Severity:** MEDIUM · **Type:** State · **Deploy unit:** apps/web-app · **Covered by test?** no · **Origin:** MAIN

## Location
- `apps/web-app/src/components/budget-tool.ts:328`

## Evidence
- Reproduction: Drag the in-page slider to 14, then toggle any sidebar display option: the ledger reverts to line 8 while the slider thumb shows 14.
- The live slider (rendered from renderMain:737; handler 991-998) never updates ConfigController. setConfig (config-controller.ts:306-334) notifies the full merged config, so a later displayOptions, matchingMethod or dyeFilters write carries maxDeltaE 8. clampMatchLine(8) differs from 14, so the match line is reset, persisted and refetched, and the slider thumb is left at 14.
  - Checked: budget-tool.ts:991-998 has no ConfigController write; :328-342 applies maxDeltaE; config-controller.ts:311-334 notifies newConfig; tool-config-types budget.maxDeltaE: 8
- Second, independent check (severity MEDIUM): The defect is real, and I could not refute it. I re-traced it in the code without using the finding's description:
- The in-page slider handler (budget-tool.ts:991-998) only sets this.matchLine, writes STORAGE_KEYS.matchLine and calls findAlternatives. It never calls ConfigController, so the stored budget.maxDeltaE stays at its default of 8 (tool-config-types.ts:483).
- A sidebar display-option toggle then runs config-sidebar.ts:838-873, which calls setConfig('budget', { displayOptions }). Dye filters go the same way through :893-907.
- ConfigController.setConfig (config-controller.ts:306-334) merges the change into the stored config. The earlier-audit OPT-008 no-op skip does not fire because displayOptions really changed, so it notifies the full config, including maxDeltaE 8.
- BudgetTool.setConfig (:328-342) then computes clampMatchLine(8) = 8, which differs from 14. It overwrites matchLine, persists 8 and re-runs the search.
- In the display-options and dye-filter cases nothing re-renders the slider, so its thumb stays at 14 while the value label shows 8. In the matching-method case renderMain re-renders it at 8, but the user's 14 is still lost.

No guard prevents this: v4-layout.ts:189-192 forwards only the single changed key, but the subscription path above still delivers the full config. No test catches it. budget-tool.test.ts never fires the slider's input event. The e2e test at budget-tool.spec.ts:120-124 only sets the slider and never checks it after a sidebar change.

MEDIUM is right rather than HIGH, because this is a two-step path that is easy to recover from:
- The user has to use the in-page slider instead of the sidebar one, then change another sidebar setting while still on the Budget tool.
- Re-dragging the slider fixes it.
- No data is lost.

It is not LOW either. The ledger silently changes which dyes count as matches, and the slider then shows a value that no longer matches the results.
- Origin: git diff --stat 8ecb878f HEAD -- budget-tool.ts, config-controller.ts: empty

## Fix
- Have the slider call ConfigController.getInstance().setConfig('budget', { maxDeltaE }) (on change), as mixer-tool.ts:524 does, or apply maxDeltaE only when it differs from the previous config. Web-app only.
