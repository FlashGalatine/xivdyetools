# BUG-131: CharacterColorService.findClosestDyes earlier-audit BUG-056 guard misses NaN/non-number count -> TypeError on best[-1]
**Severity:** LOW · **Type:** Edge case · **Deploy unit:** packages/core · **Covered by test?** no · **Origin:** MAIN · **Other units:** apps/web-app (swatch-tool storage read)

## Location
- `packages/core/src/services/CharacterColorService.ts:335`

## Evidence
- Reproduction: localStorage v3_character_max_results = abc (non-JSON) -> swatch-tool.ts:330 maxResults='abc' -> findClosestDyes count 'abc' -> TypeError reading .distance of undefined
- StorageService.getItem returns the raw string when JSON.parse fails (storage-service.ts:81-83), so a corrupted v3_character_max_results like `abc` becomes count 'abc'. 'abc' <= 0 and best.length < 'abc' are both false, so CharacterColorService.ts:351 reads best[-1].distance and throws a TypeError. This is the exact corruption route earlier-audit BUG-056's comment names.
  - Checked: CharacterColorService.ts:335,349-351; apps/web-app/src/services/storage-service.ts:79-83; apps/web-app/src/components/swatch-tool.ts:330-331,2811
- Origin: git grep at 8ecb878f: CharacterColorService.ts:335 `if (count <= 0) return [];` identical; no diff 8ecb878f..HEAD

## Fix
- `if (!(typeof count === 'number' && count >= 1)) return []; const k = Math.floor(count);` (optionally also validate maxResults on read in swatch-tool). Needs a @xivdyetools/core publish, then consumer deploys.
