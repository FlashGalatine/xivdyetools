# BUG-149: worker-kit jsonDepthLimit: case-sensitive Content-Type check lets oauth JSON bodies skip the depth/__proto__ guard
**Severity:** LOW · **Type:** Edge case · **Deploy unit:** packages/worker-kit · **Covered by test?** no · **Origin:** MAIN · **Other units:** apps/oauth (no Content-Type gate); presets-api already covered by its own hasBody gate at apps/presets-api/src/index.ts:184-219

## Location
- `packages/worker-kit/src/body-guards/body-guards.ts:106`

## Evidence
- Reproduction: POST /auth/callback, Content-Type: text/plain, body {"__proto__":{},"code":"x","code_verifier":"y"} -> guard calls next(), handler parses and proceeds instead of a 400
- body-guards.ts:105-108 skips unless content-type includes lowercase 'application/json'; oauth mounts it on /auth/* (index.ts:237) with no Content-Type gate, and callback.ts:53 / xivauth.ts:84 call c.req.json() regardless, so text/plain or Application/JSON bodies bypass SEC-003. Handlers read named fields only and bodySizeLimit still applies, so no downstream harm: a defense-in-depth gap, LOW.
  - Checked: packages/worker-kit/src/body-guards/body-guards.ts:105-108; apps/oauth/src/index.ts:237; apps/oauth/src/handlers/callback.ts:53; README.md:153 documents the skip, but oauth relies on the guard without a 415 gate (presets-api fixed the same class as earlier-audit BUG-054)
- Origin: git show 8ecb878f:packages/worker-kit/src/body-guards/body-guards.ts:106 has the same includes('application/json'); git log 8ecb878f..HEAD touches no worker-kit/test-utils file

## Fix
- Match the media type case-insensitively, accept +json, or gate on body presence the way presets-api does. Needs a @xivdyetools/worker-kit publish, then oauth/presets-api deploys.
Alternatively, add a 415 Content-Type gate in oauth only (an oauth deploy, no publish).
