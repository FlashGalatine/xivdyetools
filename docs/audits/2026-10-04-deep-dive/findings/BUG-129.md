# BUG-129: blendColors lets a NaN ratio through Math.max/Math.min and returns the invalid hex '#NaNNaNNaN'
**Severity:** LOW · **Type:** Edge case · **Deploy unit:** packages/core · **Covered by test?** no · **Origin:** MAIN

## Location
- `packages/core/src/blending/blending.ts:64`

## Evidence
- Reproduction: blendColors('#FF0000','#0000FF','rgb',NaN).hex === '#NaNNaNNaN' (ColorService.mixColorsRgb instead throws INVALID_RGB_VALUE)
- Real only on the direct blendColors path (/blending export): measured '#NaNNaNNaN' for both rgb and lab. The stated ColorService.mixColorsRgb repro is wrong: fromBlend -> ColorConverter.rgbToHex throws a typed AppError. Every in-repo direct caller passes a finite ratio, so the bug is latent.
  - Checked: temp repro (deleted): R05 #NaNNaNNaN #NaNNaNNaN; ColorService.mixColorsRgb threw AppError INVALID_RGB_VALUE
- Origin: git show 8ecb878f:packages/core/src/blending/blending.ts:64 `const t = Math.max(0, Math.min(1, ratio));`

## Fix
- Guard with Number.isFinite(ratio): either default to 0.5 or throw a typed error, matching the ColorService path. Needs a @xivdyetools/core publish; no consumer deploy required.
