# BUG-008: services/svg/gradient.ts interpolate(): the card ramps in a space derived from algo (Lab for the default ciede2000) and ignores the shared interpolation (page default hsv), so its middle dyes differ from the page
**Severity:** MEDIUM · **Type:** Logic · **Deploy unit:** apps/og-worker · **Covered by test?** no · **Origin:** MAIN · **Other units:** apps/web-app (gradient-tool interpolation)

## Location
- `apps/og-worker/src/services/svg/gradient.ts:38`

## Evidence
- Reproduction: Share /gradient/?start=<Ink Blue>&end=<Snow White>&steps=5&interpolation=hsv&algo=ciede2000 -> the page shows green middle dyes while the unfurl card shows greys
- Repro confirmed with a temporary test, now deleted. Ink Blue->Snow White, steps 5: the page's HSV ramp gives Morbol Green / Adamantoise Green / Pastel Green, but the card gives Ash/Goobbue/Charcoal Grey. Jet Black->Canary Yellow: browns on the page, greens on the card. interpolation is never parsed (og-data-generator.ts:825-829) and is not in OG_ALLOWED_QUERY_KEYS (index.ts:216). Distinct from BUG-009, which covers ranking by ciede2000.
  - Checked: gradient.ts:38-44 (mixColorsLab fallback); gradient-tool.ts:96 (default colorSpace 'hsv'), :1718-1766, :1834; temporary __repro__gap5-02.test.ts output (deleted, git status clean)
- Second, independent check (severity MEDIUM): I could not refute it. apps/og-worker/src/services/svg/gradient.ts:38-44 picks the ramp's colour space from `algo`: Oklab for oklab, RGB for rgb/distinguish/redmean, and Lab (mixColorsLab, :43) for everything else, including the default ciede2000. The page ramps in `this.colorSpace` instead (apps/web-app/src/components/gradient-tool.ts:1718-1771 and :1834). That defaults to 'hsv' (:96) and is sent in the share link as `interpolation` (:1691). The worker never reads that parameter: og-data-generator.ts:825-829 parses only start, end, steps and algo, the image URL (:315) does not carry it, and `interpolation` is not in OG_ALLOWED_QUERY_KEYS (index.ts:216). gradient.test.ts does not check which space the middle dyes are ramped in. The defect is already on main.

One point argues against raising the severity, and it also limits the proposed fix. The page's default stepCount is 8 (gradient-tool.ts:95), but the card is capped at BAND_CAP = 5 (band.ts:54, applied at gradient.ts:66). So in the default case the card samples different points along the ramp than the page does, and its middle dyes could never match the page one for one. A fix to the interpolation space alone gives exact parity only for shares with steps ≤ 5.

Against lowering it: on the default path (hsv, ciede2000, 8 steps) the mismatch still changes which dyes the card shows. For Jet Black→Canary Yellow the card shows greens (Mud, Moss, Lime), the page's 8-step HSV ramp shows mostly browns, and a card ramped in HSV would also show browns. The repo has treated this kind of card-vs-page drift as a bug before: mixer `mode` was added 2026-09-03, and commit 35914823 made the harmony card draw the harmony the page draws. The page itself is correct, so this is wrong output on a secondary surface (the link preview), not data loss. MEDIUM stands.
- Origin: git show 8ecb878f:apps/og-worker/src/services/svg/gradient.ts: interpolate() at :38 with mixColorsLab at :43; 8ecb878f gradient-tool.ts:1691 already shares interpolation: this.colorSpace

## Fix
- og-worker only. Default the card's ramp to HSV (the page default), with the same hue-wrap math as gradient-tool.ts interpolateInSpace. Optionally add an allowlisted 5-value interp enum, carried on the image URL and folded into the cache key. Otherwise state in the docblock and CLAUDE.md that the card is an approximation.
