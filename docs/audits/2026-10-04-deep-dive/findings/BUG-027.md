# BUG-027: config-sidebar.ts connectedCallback: local copies of 9 config keys never refresh after an external ConfigController write
**Severity:** MEDIUM · **Type:** State · **Deploy unit:** apps/web-app · **Covered by test?** no · **Origin:** MAIN · **Other units:** none

## Location
- `apps/web-app/src/components/v4/config-sidebar.ts:676`

## Evidence
- Reproduction: Prices off, open Budget: prices show but the sidebar 'Enable market board' toggle stays off. Reset settings, then flip one display option: the old display options are written back.
- connectedCallback (669-701) subscribes only to swatch and harmony. The shell is created once (v4-layout.ts:169) and only gets active-tool updates (:319). budget-tool.ts:292 setShowPrices(true) writes market.showPrices (market-board-service.ts:251-256). mixer-tool.ts:692 writes mixer.mixingMode. resetAllConfigs notifies every key (config-controller.ts:369-385), but 'settings-reset' has no listener. Worse: after a reset, toggling any display option sends the stale pre-reset allOptions back to global (config-sidebar.ts:857, display-options-v4.ts:333).
  - Checked: config-sidebar.ts:669-701 (only 'swatch'/'harmony' subscribe), :751-769 (load once); git grep settings-reset -> only the dispatch at advanced-options-panel.ts:240 plus its test; budget-tool.ts:292; mixer-tool.ts:692; config-controller.ts:369-385 notifyListeners per key
- Second, independent check (severity MEDIUM): I could not refute this finding, and MEDIUM is the right severity. In config-sidebar.ts:669-701, connectedCallback subscribes only to 'swatch' and 'harmony'. Every other config value is copied once in loadConfigsFromController (:751-769). The sidebar stays mounted across tool switches: v4-layout-shell.ts:1019 removes it only for 'glamour', and the shell updates only the .activeTool property. So writes from outside the sidebar never reach its local copies:
- budget-tool.ts:292 calls setShowPrices(true), which writes market.showPrices at market-board-service.ts:251-256. The sidebar toggle at :2006 is bound to the stale this.marketConfig.showPrices.
- Settings reset (advanced-options-panel.ts:239-240) runs resetAllConfigs, which notifies each key (config-controller.ts:369-385). The 'settings-reset' event it dispatches has no listener anywhere.
- After a reset, flipping one display option re-sends the stale full set, which reverts the reset for every display option. display-options-v4.ts:325-334 emits getCurrentOptions(), built from its stale props. config-sidebar.ts:853-873 then writes that whole object to 'global' and to all 8 tools. setConfig merges it in (config-controller.ts:306-315).
No test covers this. config-sidebar.test.ts mocks subscribe, and the mixing-mode and wheel tests only check labels and the wheel. The cause is on main: git diff 8ecb878f..HEAD is empty for config-sidebar.ts, display-options-v4.ts, budget-tool.ts, config-controller.ts and advanced-options-panel.ts.
Why not higher or lower: the Budget case happens on a common path, but the effect is cosmetic. Prices do turn on, the toggle just shows off, and one click brings it back in line. The reset case is a real wrong result, because it silently undoes a destructive reset, but it is an edge path. That fits MEDIUM, not HIGH and not LOW.
- Origin: git diff --stat 8ecb878f HEAD -- apps/web-app/src/components/v4/ budget-tool.ts mixer-tool.ts advanced-options-panel.ts v4-layout.ts is empty

## Fix
- Subscribe to every ConfigKey (global included) in connectedCallback and refresh the local copy, tearing all of them down from one unsubscribe list. Writes are key-level, so nothing else is clobbered. Web-app deploy only.
