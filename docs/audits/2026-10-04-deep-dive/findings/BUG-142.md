# BUG-142: contrast-card.ts tone/tier judged on the raw ratio while 13C·1 prints it rounded to 1 dp (2.96 shows '3.0' in failing red)
**Severity:** LOW · **Type:** Edge case · **Deploy unit:** packages/svg · **Covered by test?** no · **Origin:** MAIN · **Other units:** apps/discord-worker (consumer)

## Location
- `packages/svg/src/contrast-card.ts:106`

## Evidence
- Reproduction: /contrast with 4 dyes where one pair's ratio is 2.95-2.999 -> row reads '3.0' in the failing tone
- ratioTier (:106-111) uses raw >=7/4.5/3. render13C1 prints num(p.ratio, lang, 1) (:427) in ratioTone(p.ratio) (:414), so 2.96 prints '3.0' in the tier-0 tone and 6.96 prints '7.0' in the tier-2 tone. The tier is WCAG-correct (no rounding), but the printed figure contradicts it. 13A/13B have the same edge at 2 dp (2.996 prints '3.00').
  - Checked: packages/svg/src/contrast-card.ts:106-115,414,427; packages/bot-logic/src/commands/contrast.ts:87 (raw ratio passed)
- Origin: git diff --stat 8ecb878f HEAD -- packages/svg is empty; ratioTier and num(p.ratio, o.lang, 1) are present at 8ecb878f

## Fix
- Keep the raw-ratio tier, because WCAG does not round thresholds. Floor the printed value to its dp instead (2.96 -> '2.9', 2.996 -> '2.99') so the print never rounds up across a cut. Do not round before ratioTier, since that would turn a fail into a false pass.
Needs an svg publish, then consumer deploys.
