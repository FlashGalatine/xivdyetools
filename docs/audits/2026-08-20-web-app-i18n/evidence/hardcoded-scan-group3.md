Verification notes that apply to several rows:
- **Virtual "Custom" dyes** (gradient / comparison / harmony `selectCustomColor` + gradient `createCustomDye`): `name: "Custom (#RRGGBB)"`, `category: 'Custom'`, `acquisition: 'Custom'`. `LanguageService.getDyeName(negativeItemID)` returns null, so every `getDyeName(...) || dye.name` site prints the English `Custom (#…)`; core's `TranslationProvider.getCategory/getAcquisition` fall back to the raw key, so `Custom` also leaks through `LanguageService.getAcquisition()` (comparison "SOURCE" row, result-card acquisition line) in all six locales. Custom endpoints also become step 0 / step N result cards in the gradient.
- **`harmony-result-panel.ts` and `color-wheel-display.ts` are unreachable.** `harmony-tool.ts` imports both and declares `resultPanels: HarmonyResultPanel[]` / `colorWheel: ColorWheelDisplay | null`, but never constructs either (results render as `<v4-result-card>`, the wheel as `<v4-color-wheel>`). No other importer exists. Their findings are listed at **Low** — fixing them is dead-code cleanup, not i18n; the cleaner fix is deleting the two files (and the two fields) rather than localising them.
- `export-sheet.ts` `meta` lines are pushed into `headerLines()` of `@shared/palette-export`, which is rendered into the visible `<pre>` preview and the downloaded file — so gradient's export meta string is user-visible.

## Summary

Across the seven files I found **31 rows**: **14 High**, **1 Medium**, **16 Low**. Per file: gradient-tool.ts 9 (4 High / 5 Low), comparison-tool.ts 6 (5 High / 1 Low), harmony-tool.ts 4 (3 High / 1 Low), v4-color-wheel.ts 4 (1 Medium / 3 Low), harmony-result-panel.ts 3 (all Low, unreachable), color-wheel-display.ts 5 (all Low, unreachable), harmony-generator.ts 0. The Highs collapse into three real defects: (1) the **virtual "Custom" dye** built identically in gradient, comparison and harmony — English `Custom (#hex)` name plus raw `'Custom'` category/acquisition that core's localisation falls back to verbatim in every locale (9 rows, one shared fix: a `common.customColorName` / `common.custom` key applied at render time or in one shared factory); (2) comparison's hardcoded **`gil` unit** inside the verdict cost line and the hardcoded **`RATIO`** row tag in the seven-readouts list; (3) gradient's **export header line** `Interpolation: … steps`, which lands in the visible export preview. The single Medium is `v4-color-wheel.ts` using `dye.name` directly in node tooltips. The Lows are label+number concatenations (`STEP n`, `Harmony n`, `avg ΔE v`, `Pinned steps · n`) that should become interpolated keys for CJK word order, plus the two dead components whose strings only matter if the files are revived — deleting `harmony-result-panel.ts` and `color-wheel-display.ts` (and the two unused fields in `harmony-tool.ts`) removes 8 rows outright. Adjacent out-of-scope observation: `src/shared/palette-export.ts:120` has English pluralisation (`'entry' : 'entries'`) and a hardcoded `Generated … ·` header that every export (gradient included) renders.

**Completely clean:** `src/services/harmony-generator.ts` (all harmony names/descriptions go through `LanguageService.getHarmonyType()` / `t('harmony.types.*Desc')`).
