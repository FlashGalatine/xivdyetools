**Project:** `xivdyetools/apps/web-app` (Web-App 5.0, pre-launch)
**Branch:** `monorepo-2.0-prep` @ `1cbb303e`
**Languages:** `en` (source) · `de` · `fr` · `ja` · `ko` · `zh`
**Previous audit:** [2026-08-09](../2026-08-09-prerelease-monorepo-upgrade/i18n/I18N_AUDIT_2026-08-09.md) (web-app tree was 1,509 keys then; the 2026-08-16 dead-code purge removed 472 dead keys)
**Method:** i18n-manager skill — locale parity / duplicates / interpolation / untranslated scan (`evidence/locale-parity.txt`), terminology cross-check against `docs/reference/ffxiv-terminology.md` **and** the runtime core locale JSON (`evidence/terminology-vs-dictionary.txt`), translation-quality heuristics (`evidence/translation-quality-heuristics.txt`), font-stack review, and a **full-read** hardcoded-string sweep of all 117 non-test source files by seven parallel reviewers (`evidence/hardcoded-scan-group1..7.md`).

## Executive Summary

**The locale files are in excellent shape; the code that consumes them is not finished.**

- **Locale files — clean.** 1,075 keys × 6 files, all 1,273 lines; **0** duplicate keys, **0** missing, **0** extra, **0** interpolation-variable mismatches, **0** HTML-tag mismatches; both existing gates (`validate:i18n`, `i18n:unused`) pass. The 87 "identical to English" values are all brand names, units (ΔE2000, GIL / ΔE), cognates or pure-variable templates. Three French values have a stray **leading space**; three CJK values drop a clause; one Korean string spells Hrothgar wrong. That is the whole list of content defects.
- **Source code — ≈270 hardcoded-string rows, ≈100 of them High.** The 2026-08-09 audit found 4 (all since fixed). This pass read every file instead of grepping `v4/` and found the gap is real: one entire form (`preset-edit-form.ts`) still ships 4.x English; the preset submission/vote/collection services toast English validation and transport messages verbatim; seven tools build an English `Custom (#HEX)` dye; six sites hardcode "gil"; route titles and `document.title` are English-only; and one genuine **bug** makes every category heading in the palette drawer English in all six languages (`CATEGORY_TRANSLATION_KEYS` never matches the runtime category names).
- **Vocabulary split.** The config sidebar labels harmony types, vision types and (via the broken map) categories from web-app keys while the result surfaces label the same things from core's getters — 58 cells disagree (ja トライアド vs 三色配色 on the same screen). Core should be the single owner, as it already is for the Discord bot and OG cards.
- **Fonts — nothing to subset** (web-app uses local CJK families only); one Low: `--font-cjk` orders Noto Sans **JP** first for zh/ko users too (Han-unification glyph forms) — a 6-line `:lang()` fix.

**Identical-to-EN values (87 total)** — reviewed one by one; classes: brand/proper nouns (`VERSION`, `BUILD`, `ATTRIBUTION`, Flash Galatine), units & method tags fixed verbatim ×6 by the design record (`ΔE2000`, `ΔEOK · OKLab`, `ΔE76 · CIE 1976`, `GIL / ΔE`, `LAB`, `IDEAL`, `PALETTE`), true cognates (de/fr `Original`, `Pigment`, `Navigation`, `Tags`, `Bracelets`, fr `via {provider}`, `Options`, `Acquisition`, `Description`), pure-variable templates (`{undyed} · {empty}.`), and the ja/ko legal line `FINAL FANTASY XIV © … All Rights Reserved.` (zh/de/fr translated it — ja/ko could too, but Square Enix's own ja Lodestone keeps the English notice; defensible).

**Key order:** every target file diverges from `en.json` order (zh from position 92, the others from 252 — `harmony.*` block). Harmless at runtime (nested lookup), but it defeats a side-by-side diff and is the reason the 2026-08-09 audit's "line counts match" heuristic can be true while the files are not structurally aligned. A one-off `jq -S`-style reorder-to-source script would fix it; consider making `validate:i18n` assert order.

## Recommendations (in order)

1. **Fix the palette-drawer category bug** (HC-SYS-001) — one file, visible to every non-English user on every tool that opens the drawer. Use `getCategory()`, delete the map and the 11 dead `colorPalette.*` colour keys.
2. **Localize `preset-edit-form.ts` and route the preset/vote/collection service messages through keys** (HC-PRE-001/002, HC-SYS-011) — ≈65 rows, most with keys that already exist or an obvious sibling in the submission form. This is the 5.0 "community presets" surface; it is the most English-heavy thing a ja/de/fr user will meet.
3. **Three shared helpers kill four systemic shapes:** `shared/custom-dye.ts` (HC-SYS-002), `formatGil()`/`formatNumber()`/`formatDate()` in `shared/format.ts` (HC-SYS-003, -008), and `localizedDyeName()` used in search/sort/aria (HC-SYS-004/-005).
4. **Make core the owner of harmony/vision/category vocabulary** (TERM-002/003/004): sidebar calls `getHarmonyType()/getVisionType()/getCategory()`; delete the duplicate `config.*` / `colorPalette.*` keys. Removes 58 on-screen contradictions and 20 keys ×6.
5. **Route titles via `tools.<id>.title` + refresh on locale change** (HC-SYS-006); **subscribe the five stale components** (HC-SYS-007).
6. **Locale-file fixes L-1…L-7** — seven one-line edits.
7. **Delete the four dead components + announcer helpers** (HC-SYS-012) instead of localizing them; note the knip type-import blind spot in `knip.jsonc` is exactly what hid three of them — consider a `knip --production` run in CI as a warning-only step.
8. **Guardrails so this does not regrow:**
   - an ESLint rule (the repo already has `eslint-rules/`) flagging string literals with ≥2 Latin words inside `html\`` templates, `textContent =`, `placeholder=`, `aria-label`, `title=`, and `ToastService.*(` calls outside `t()`;
   - extend `validate:i18n` to assert key **order** matches `en.json` and to fail on **leading/trailing whitespace** differences vs source;
   - a vitest that instantiates each Lit component, flips the locale, and asserts at least one rendered string changed (catches HC-SYS-007 for good);
   - keep `evidence/locale-parity.txt`'s script as `scripts/i18n-parity.mjs` (duplicates, interpolation, identical-to-EN with an allow-list) — the 2026-08-09 report asked for this too.

## What is *not* a finding (recorded so the next audit does not re-file it)

- `preset.*.tags[N]` per-locale tag lists of different lengths — authored per language (2026-08-09 I18N-001). The 2026-08-16 purge removed the preset tag arrays from the web-app tree entirely, so this no longer appears at all.
- Native language names in the language modal (日本語, Deutsch…) — correct by design; the **English exonyms** under them (HC-V4-011) are the Low finding.
- World / data-centre names — proper nouns. The `region` strings in `public/json/data-centers.json` (`Europe`/`North-America`/`中国`/`한국`) are the Low finding (HC-V4-009).
- `share-service.ts` share titles/descriptions — traced into a CustomEvent detail only, never rendered; listed Low for completeness.
- The `changelog-modal` content — English-only by source (`CHANGELOG-laymans.md`); structural, not a string to extract.
