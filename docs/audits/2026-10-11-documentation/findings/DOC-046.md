# DOC-046: og-worker overview misdescribes its analytics datapoints and omits /health, / and the crawler 404
**Severity:** LOW · **Deploy unit:** og-worker · **Baseline:** production `16a6123f` = HEAD `42c35e87` for code (checked 2026-10-11)

## Location
- `docs/projects/og-worker/overview.md:302-303` — "One datapoint per **crawler** hit — human page views produce nothing here"
- `docs/projects/og-worker/overview.md:307` — blobs `[event, tool, crawler]` with "the detected crawler type"
- `docs/projects/og-worker/overview.md:106-148` — the Routes tables (tool intercepts and /og/* images) have no `/health` or `/` row and no crawler-404 fallthrough row

## Evidence
- `apps/og-worker/src/index.ts:681-688` — `og_request` written per crawler page hit; :933-937 (and 9 more image routes through :1338) — `og_image_request` with `crawler: 'none'`; the `/og/:tool/default.png` (:888) and `/og/default.png` (:1348) routes write nothing
- `apps/og-worker/src/index.ts:508-518` — the /og/* cache middleware returns `hit` before the route handler runs, so cache hits write no datapoint
- `apps/og-worker/src/index.ts:566-572` `GET /health`; :1364-1376 `GET /` (crawler embed, else 302 to APP_BASE_URL); :1384-1393 catch-all → crawlers get the fallback embed as a `404` with `no-store`

## Fix
- Describe both datapoint kinds: og_request per crawler page hit, and og_image_request with crawler 'none' per uncached parameterized image render (cache hits and default cards write nothing). Add an "Other routes" table for GET /health, GET / and the crawler 404 no-store fallthrough.
