# DOC-006: the Glamour Reader guide says Facewear always starts blank, uses a retired item as its twins example, and omits the retired-family note
**Severity:** MEDIUM · **Deploy unit:** web-app · **Baseline:** production `16a6123f` = HEAD `42c35e87` for code (checked 2026-10-11)

## Location
- `docs/user-guides/web-app/glamour-reader.md:212` — "Facewear always starts blank."
- `docs/user-guides/web-app/glamour-reader.md:73` — "*Dated Hempen Coif* and *Hempen Coif*" as a twins example
- `docs/user-guides/web-app/glamour-reader.md:103` — "| **DATED** | A retired version the game still draws |" (chip table at 95-104 with no retired-family note)

## Evidence
- `apps/web-app/src/components/glamour-list-actions.ts:150-154` — Facewear `generated = glasses?.acquisition`, served by api-worker resolver.ts:148-156 via facewearAcquisitionFor (acquisition.ts:42-45). Counting the table, facewear-unlocks.json maps to 61 distinct unlock items and 54 of them have a line in acquisition.en.json (web-app 5.15.0 CHANGELOG.md:14,18)
- `apps/api-worker/src/chara/resolver.ts:86-101` — selectableItem drops Aetherial/Deepmist rows and Dated rows with levelEquip <= 50 whenever an eligible row exists. XIVAPI Item/372 returns {LevelEquip:1, Name:"Dated Hempen Coif"}, so it is never offered beside Hempen Coif (resolver.test.ts:99-121)
- resolver.ts:96-101 — a family with only retired rows is named with `retired: true`; glamour-block.ts:1324-1326 appends en.json:1342 glamour.row.retired "A retired item, no longer obtainable"

## Fix
- Say Facewear is filled when the table knows the style's unlock source, else blank. Replace the Hempen Coif example with a pair that is actually served, and say Aetherial, Deepmist and level-50-or-lower Dated gear is never offered as a twin. Add the 'A retired item, no longer obtainable' row note. Keep the DATED chip row: Dated items above level 50 still appear.
