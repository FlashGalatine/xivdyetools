# DOC-023: the moderation runbook misstates what a ban shows and keeps
**Severity:** MEDIUM · **Deploy unit:** moderation-worker · **Baseline:** production `16a6123f` = HEAD `42c35e87` for code (checked 2026-10-11)

## Location
- `docs/operations/MODERATION.md:86` — "User ID: 123456789" (ban success embed)
- `docs/operations/MODERATION.md:184` — "Ban history is preserved (unbanning doesn't delete the record)"
- `docs/operations/MODERATION.md:230` — "Logged with target user, moderator, reason, and preset count"

Also: docs/operations/MODERATION.md:106 and :158 — "Restores all hidden presets" / "All 'hidden' presets → 'approved'" (collisions skipped); :135 — "Shows username and ban date"; :150 — "You have been banned from submitting presets"; :193 — "This command must be used in the moderation channel."; :231 — unban log also has no reason. The unban embed's 'User ID' at :118 IS correct (preset.ts:664).

## Evidence
- `apps/moderation-worker/src/handlers/modals/ban-reason.ts:194-201` — the channel embed deliberately has no `User ID` field (FINDING-008, privacy policies), only Presets Hidden / Banned By / Reason. Lines 228-233: the log line carries targetUserId, moderatorId, presetsHidden and reasonLength only (FINDING-011).
- `apps/moderation-worker/src/services/ban-service.ts:604-606` — the unban UPDATE sets `username = '', reason = ''`. apps/presets-api/src/services/moderation-retention-service.ts:22,79 deletes lifted bans after 90 days (LIFTED_BAN_RETENTION_DAYS), run daily (wrangler.toml:126 cron) and after moderation writes. ban-service.ts:413-428 restoreGuard skips hidden presets whose dye_signature collides, leaving them hidden.
- `apps/moderation-worker/src/index.ts:509` — unban choices are `${username} (${idKind}:${id})`, with no ban date. apps/presets-api/src/middleware/ban-check.ts:71 — 'You have been banned from using Preset Palettes.' src/services/bot-i18n.ts:84 (used at preset.ts:481,591) — 'This command can only be used in the moderation channel.'

## Fix
- Drop the ban embed's User ID line. Say unban blanks username and reason and presets-api deletes the row 90 days later. Logs carry ids, counts and reason length; the reason itself lives in D1 moderation_log. Quote the real strings, and note that collisions stay hidden ('Presets Still Hidden').
