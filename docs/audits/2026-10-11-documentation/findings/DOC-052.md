# DOC-052: env-var docs miss ENVIRONMENT's second gate and the 32-character webhook secret; SECRET_ROTATION calls it an HMAC key
**Severity:** LOW · **Deploy unit:** repo-wide · **Baseline:** production `16a6123f` = HEAD `42c35e87` for code (checked 2026-10-11)

## Location
- `docs/developer-guides/environment-variables.md:65` — "`ENVIRONMENT` gates exactly one behaviour: `validateEnv` ..."
- `docs/developer-guides/environment-variables.md:75` — "| `INTERNAL_WEBHOOK_SECRET` | No | Webhook authentication |" (no length rule; same gap at :196 for presets-api)
- `docs/operations/SECRET_ROTATION.md:45` — "| `INTERNAL_WEBHOOK_SECRET` | presets-api → discord-worker ... | shared HMAC key |"

Also: docs/developer-guides/environment-variables.md:196, docs/developer-guides/environment-variables.md:397

## Evidence
- `apps/discord-worker/src/index.ts:315-322` — if ENVIRONMENT === 'production' and the secret is shorter than MIN_WEBHOOK_SECRET_LENGTH, the webhook answers 503 'Webhook misconfigured'. This is a second ENVIRONMENT gate outside validateEnv (env-validation.ts:136-148 records it as a deliberately non-fatal error)
- `apps/presets-api/src/utils/env-validation.ts:148-156` — a missing secret is a production error, but a short one only triggers warnings.push (never makes valid false)
- `apps/discord-worker/src/index.ts:298,325` — expectedAuth = `Bearer ${env.INTERNAL_WEBHOOK_SECRET}`, compared with timingSafeEqual (a bearer secret, not an HMAC key); presets-api sends it as an Authorization Bearer header at notification-service.ts:279

## Fix
- In environment-variables.md:65, name both ENVIRONMENT gates (validateEnv plus the webhook length check). On :75 and :196 add 'min. 32 chars in production (discord-worker answers 503 on the webhook, presets-api only warns)'. In SECRET_ROTATION.md:45, change 'shared HMAC key' to 'shared bearer secret (≥ 32 chars in prod)'.
