# DOC-016: eight code examples import type-only names with a plain `import`, a compile error under verbatimModuleSyntax
**Severity:** MEDIUM · **Deploy unit:** repo-wide (types, core docs) · **Baseline:** production `16a6123f` = HEAD `42c35e87` for code (checked 2026-10-11)

## Location
- `docs/CLAUDE.md:155` — "import { Dye, RGB, HexColor } from '@xivdyetools/types';"
- `docs/projects/core/overview.md:93` — "import { Dye, RGB, HexColor, DyeId, PresetCategory }"; :324 — "import { createHexColor, createDyeId, HexColor, DyeId }"
- `docs/projects/types/overview.md:34,` :55, :91, :131, :163-170 — plain `import { RGB, HSV, ... }`, `{ Dye, DyeId, ... }`, `{ PresetPalette, ... }`, `{ JWTPayload, AuthProvider }`, and the multi-line `{ HexColor, DyeId, Hue, Saturation, createHexColor, createDyeId }`

Also: packages/types/README.md:47, :50, :64, :81, :88, :103, :165, :288, :298, :308 (the published npm README makes the same plain imports of type-only names; :288/:298 mix in the runtime AppError/ErrorCode and need splitting). docs/developer-guides/contributing.md:77 and monorepo-setup.md:145 are deliberate counter-examples, not defects.

## Evidence
- `packages/types/src/index.ts:26-27` — `export type { RGB, HSV, LAB, ..., HSL, ... }` and `export type { HexColor, DyeId, Hue, Saturation }`; :36-42 Dye/DyeWithDistance/FacewearColor, :62-79 PresetCategory/PresetStatus/PresetPalette/CommunityPreset, :112+ AuthProvider/JWTPayload are all in `export type` blocks
- tsconfig.base.json:14 — "verbatimModuleSyntax": true (a plain import of a type-only export is TS1484)
- `docs/projects/core/types.md:37-38` — already shows the correct split: value import of create* plus `import type { HexColor, DyeId, Hue, Saturation }`

*Narrowed at verification:* Title count "seven code examples": the listed locations contain eight plain type-only imports (docs/CLAUDE.md 1, core/overview.md 2, types/overview.md 5).

## Fix
- Use `import type { ... }` for the all-type lines. Split the mixed lines into `import { createHexColor, createDyeId, type HexColor, type DyeId } from '@xivdyetools/types'`.
