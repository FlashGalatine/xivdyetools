# DOC-002: deployment.md says `db:migrate` applies D1 migrations; it only re-runs schema.sql, so numbered migrations never get applied
**Severity:** MEDIUM · **Deploy unit:** repo-wide (presets-api, oauth) · **Baseline:** production `16a6123f` = HEAD `42c35e87` for code (checked 2026-10-11)

## Location
- `docs/developer-guides/deployment.md:132-136` — "Migrations are applied explicitly:" ... `run db:migrate:local` / `run db:migrate   # remote`
- `docs/developer-guides/release-process.md:175` — "6. Apply D1 migrations if the schema changed."
- `docs/developer-guides/contributing.md:151` — "D1 schema changes ship a migration, applied before the dependent code"

## Evidence
- `apps/presets-api/package.json:12-13` — db:migrate / db:migrate:local = `wrangler d1 execute xivdyetools-presets --remote|--local --file=./schema.sql`; schema.sql:8,32,81 are all `CREATE TABLE/INDEX IF NOT EXISTS`
- `git ls-files apps/presets-api/migrations apps/oauth/migrations` lists 0002-0015 plus oauth 0001, and no package.json script references any of them (the only per-file script, db:migrate:indexes at line 14, targets the older 002_add_composite_indexes.sql)
- `docs/operations/index.md:18` and apps/presets-api/README.md:97 already state the real rule: hand-run `wrangler d1 execute … --file=`, never `d1 migrations apply`, because db:migrate cannot alter a live schema

*Severity:* the first verifier graded HIGH, the skeptic MEDIUM; MEDIUM kept — running db:migrate is harmless, the harm is the omitted procedure, which docs/operations/index.md and apps/presets-api/CLAUDE.md already state (see the report).

## Fix
- State that db:migrate only re-applies schema.sql (CREATE IF NOT EXISTS, for a fresh DB). Give the per-file command, e.g. `pnpm --filter xivdyetools-presets-api exec wrangler d1 execute xivdyetools-presets --remote --file=./migrations/<NNNN>.sql`, plus the oauth equivalent against xivdyetools-users. Repeat the never-`migrations apply` rule, and link release-process step 6 and the contributing checklist to that section.
