# BUG-014: the 1–9 tool shortcuts have no production listener — the shortcuts panel advertises keys that do nothing
**Severity:** HIGH · **Type:** Untested behaviour / dead wiring · **Deploy unit:** `web-app` · **Covered by test?** no — the test registers the missing listener itself

## Location
- `apps/web-app/src/services/keyboard-service.ts:228-234` — `handleToolNavigation` dispatches `CustomEvent('keyboard-navigate-tool')` on `window`, under the comment "main.ts listens for 'keyboard-navigate-tool' events".
- Nothing listens. `grep -rn "keyboard-navigate-tool" apps/web-app/src` returns the dispatch site and **only the test file** (`services/__tests__/keyboard-service.test.ts:97,113,129,145`).

## Evidence
- `main.ts` does not register the handler the comment names, and no other module does either, so pressing 1–9 dispatches an event into the void: no navigation, no error, no feedback.
- The shortcuts panel presents these keys to the user as working features, which makes the failure a visible broken promise rather than a hidden dead path.
- The suite passes because each of the four tests calls `window.addEventListener('keyboard-navigate-tool', listener)` itself before dispatching. It verifies the service emits correctly and asserts nothing about the application consuming it — a test that cannot fail on the actual defect.

## Fix
- Register the listener where the comment says it lives, routing `detail.toolId` through `RouterService.navigateTo`, and remove it on teardown.
- Change the test to assert navigation happened rather than that the event fired: drive the keypress and assert the router's current tool, so a missing listener turns it red.
- While there, reconcile the modifier handling flagged alongside this — `keyboard-service.ts:143,150,157` let `Ctrl+Shift+T` reach the theme toggle because the Shift branches omit the ctrl/alt/meta exclusion the 1–9 branch has.
