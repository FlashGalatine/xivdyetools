# BUG-005: `sanitizeErrorMessage`'s unquoted-value pattern stops at the first space, leaving Basic credentials and spaced secrets in the log
**Severity:** MEDIUM · **Type:** Logic / redaction bypass · **Deploy unit:** `@xivdyetools/logger` (published npm API) · **Covered by test?** no

## Location
- `packages/logger/src/core/base-logger.ts:195` — `const V = \`(?:["']([^"']*?)["']|[^\\s,;]+)\`;`
- `packages/logger/src/core/base-logger.ts:192` — the comment two lines above documents a *different*, correct pattern: `[^\s,;'"]+(?:\s+[^\s,;'"=]+)*` "matches unquoted values (including spaces before delimiter)". The implementation is the narrower alternative; the code contradicts its own specification.
- `packages/logger/src/core/base-logger.ts:251-254` — the `authorization` rule that inherits `V`.

## Evidence
- Runnable repro: `evidence/scripts/repro-logger-sanitize.mjs`, output in `evidence/repro-logger-sanitize.txt`:
  ```
  in : Authorization: Basic dXNlcjpwYXNzd29yZA==
  out: authorization=[REDACTED] dXNlcjpwYXNzd29yZA==

  in : token = my secret value
  out: token=[REDACTED] secret value
  ```
- The failure is worse than a plain miss: the emitted line carries a `[REDACTED]` marker directly beside the surviving credential, so a reader — or a log scanner keying on the marker — concludes the value was handled.
- Quoted values (`token="quoted secret value"`) and `Authorization: Bearer …` are redacted correctly, which is why the suite passes: every existing case uses one of those two shapes.

## Fix
- Replace `V`'s unquoted arm with the pattern the comment already specifies, so a value runs to the next delimiter rather than the next space, and add cases for `Basic` credentials and spaced values to `base-logger.test.ts`.
- Ships with [[BUG-004]] in one `@xivdyetools/logger` publish, then consumer deploys — two sprints.
