# BUG-003: web-app's real `CHANGELOG-laymans.md` is never parsed by a test, so a malformed heading silently drops a release
**Severity:** LOW · **Type:** Untested behaviour · **Deploy unit:** `web-app` · **Covered by test?** no — the existing test parses a fixture

## Location
- `apps/web-app/vite-plugin-changelog-parser.ts:89` — the version heading grammar: `/^##\s+[^\n]*?Version\s+(\d+\.\d+\.\d+)\s*(?:[—–-]\s*(.+?))?\s*$/gm`. A heading that omits the word "Version", uses a two-component version, or a dash outside `— – -` produces no entry and no error.
- `apps/web-app/src/__tests__/changelog-parser.test.ts:15` — asserts against "a representative sample mirroring the real CHANGELOG-laymans.md structure", never the shipped file.
- `apps/web-app/CHANGELOG-laymans.md:5` — the real file, currently `## Web-App Version 5.0.1 — September 2, 2026`.

## Evidence
- The bot side gates exactly this and the web side does not: `apps/discord-worker/src/services/changelog-parser.test.ts:8` imports the real bundled `../../CHANGELOG-laymans.md`, and its `describe('root CHANGELOG-laymans.md')` block at line 57 `readFileSync`s the root file. Both shipped files are asserted against the real parser; the web-app's is not.
- The two parsers accept **mutually exclusive** grammars — the bot's is `/^## \[([^\]]+)\]\s*-\s*(.+)$/` (`## [5.1.0] - 2026-08-31`), the web's requires the literal word "Version" and an unbracketed version. Copying a heading style between the three files breaks the destination silently in either direction.
- Downstream effect: `changelog-modal.ts:170` looks the running version up with `findIndex((e) => e.version === APP_VERSION)`; a dropped entry sends it into the BUG-043 fallback rather than showing the release the user just received.

## Fix
- Add a vitest case that runs the real plugin over `apps/web-app/CHANGELOG-laymans.md` and asserts that the newest entry's version equals `package.json`'s — the same shape the bot's test already uses. Four lines, no production change.
