# BUG-006: RYB blending loses green entirely — every green and teal comes back blue on the bot's default mix mode
**Severity:** HIGH · **Type:** Logic / colour math · **Deploy unit:** `@xivdyetools/core` (fix), `@xivdyetools/bot-logic` + `discord-worker` (consumers) · **Covered by test?** no — the suite explicitly exempts RYB from the check that would catch it

## Location
- `packages/core/src/blending/conversions.ts:130-153` — `rgbToRyb`. Leftover green (`g_ - y`) is credited **only** to blue (`b__ = (b_ + (g_ - y)) / 2`); nothing adds it back to `y`. Pure green therefore maps to the same RYB triple as pure blue.
- `packages/core/src/blending/blending.test.ts:101` — `bijectiveModes` is `['rgb','lab','oklab','hsl','spectral']`; `'ryb'` is deliberately excluded from "blending a color with itself returns the same color".
- `packages/core/src/blending/blending.test.ts:116-121` — the RYB substitute asserts only `r > 50 && b > 100` on `#8B5CF6`, a purple, which is the one hue family this defect does not touch.

## Evidence
- Runnable repro against the built package: `evidence/scripts/repro-ryb-green.mjs` / `repro-ryb-two-impls.mjs`, output in `evidence/repro-ryb-green.txt`.
  ```
  pure green #00FF00 -> RYB(r=0.000 y=0.000 b=1.000) -> RGB(0, 0, 255)
  pure blue  #0000FF -> RYB(r=0.000 y=0.000 b=1.000) -> RGB(0, 0, 255)   <- identical triple
  ```
  Green and blue are not distinguishable in this RYB space, so the round trip cannot recover green.
- Self-blends, which must be identity-like, invert the hue:

  | input | `core/blending` (bot path) | `RybColorMixer` (web path) |
  |---|---|---|
  | `#00FF00` | **`#0000ff`** | `#22B42C` |
  | `#40A040` | **`#4040a0`** | `#41A040` |
  | `#008080` | **`#000080`** | `#197C71` |

  Core's *other* RYB implementation is correct, which bounds the blast radius and shows the expected behaviour.
- Reachable surfaces: `packages/bot-logic/src/commands/mixer.ts:114` (`/mix`) and `packages/bot-logic/src/commands/gradient.ts:212` (`/gradient`), both via `blendColors(..., 'ryb')`. RYB is the **default** blending preference — `apps/discord-worker/src/types/preferences.ts:123` is `blending: 'ryb'` — and it is offered on three registered commands (`commands/schemas.ts:376,426,612`).
- The web mixer is **not** affected: `apps/web-app/src/services/mixer-blending-engine.ts:76` routes to `ColorService.mixColorsRyb` (the correct implementation), and `mixer-tool.ts` imports `blendColors` from `@services/index`, which re-exports the web-app's own engine.

## Fix
- Redistribute the leftover green into yellow as well as blue in `rgbToRyb`, so the function inverts `rybToRgb` (which builds green from the yellow∩blue overlap). Validate against the round trip, not against a hand-picked colour.
- Delete the `'ryb'` exemption at `blending.test.ts:101` and let RYB take the same self-blend identity assertion as the other five modes, with a tolerance that admits the conversion's genuine lossiness but not a hue flip. Add green and teal cases.
- Consider whether the two RYB implementations should converge; `DEPRECATIONS.md` records that blending-conversion unification was declined with measured deltas, so treat that as a separate decision rather than folding it into this fix.
- Needs a `@xivdyetools/core` publish, then `bot-logic`, then the `discord-worker` deploy — sequence as two sprints.
