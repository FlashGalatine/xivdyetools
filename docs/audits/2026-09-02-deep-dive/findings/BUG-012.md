# BUG-012: "Inspect Dye in → Harmony" is broken for all 125 dyes — it sends the one id grammar the receiver rejects
**Severity:** HIGH · **Type:** Logic / contract drift · **Deploy unit:** `web-app` · **Covered by test?** no

## Location
- `apps/web-app/src/components/v4/result-card.ts:1188-1189` — `navigateToHarmony` sends `{ dyeId: String(dye.itemID) }`, under the comment "Use itemID for localization-safe deep linking" (a pre-5.0 assumption).
- `apps/web-app/src/components/harmony-tool.ts:524` — the receiver resolves that param with `ShareService.resolveSharedDye`.
- `apps/web-app/src/services/share-service.ts:325-331` — that resolver rejects **any** id `>= 5729` with a visible `share.legacyLink` error toast and returns `null`, by design ("loud-failure contract").

## Evidence
- The two ranges do not overlap at all. Counting the shipped data:

  | dyes | with `legacyItemID` | min | max | below 5729 |
  |---|---|---|---|---|
  | 125 | 125 | 5729 | 48227 | **0** |

  Schema v2 derives `Dye.itemID` from `legacyItemID` (`DyeDatabase.ts:202-207`), so `dye.itemID >= 5729` for every dye without exception. Every click on this menu item therefore hits the legacy-id branch: an error toast, a warning in the console, and no navigation state.
- The stainID grammar the receiver wants is available on the same object — `result-card.ts:1501` already uses `dye.stainID` elsewhere in the file, so this is a single call site left behind by the 5.0 id rewrite rather than a missing capability.
- Not caught because `result-card.test.ts` has no coverage of the hand-off paths at all (5 of its 8 tests are `toBeDefined()` / class-name assertions), and no test drives a navigation from card to tool.

## Fix
- Send `String(dye.stainID)` and update the stale comment. One-line change.
- Add a test that drives `navigateToHarmony` and asserts the emitted param resolves through `ShareService.resolveSharedDye` to the same dye — the round trip, not just the call.
- While in the file, confirm the other hand-offs: `budget`, `swatch` and `mixer` navigate without a dye param (they pass state by other means), so this is the only site with the defect.
